# Agent Note: 原厂屏幕旋转事件与显示恢复

Status: implemented

## 问题

FnKey 的 124 事件调用 Rotation180：主显示器方向 0 切到 2，方向 2 切到 0；方向 1 或 3 交换宽高后切到 2。原程序直接写入显示设置，自研程序必须保留可见预览、确认与恢复，且不能把已有只允许刷新率变化的恢复监护当作已支持旋转。

## 决定

- 显示域提供主显示器标识和唯一的原厂方向目标计算，精确限制设备、色深、位置、频率及旗标不变；旋转和刷新率共用显示控制锁、驱动预检、15 秒独立监护、首次基线与恢复。独立试用可取消到本次前态，保留和取消均绑定试用序号；档案依旧只允许修改刷新率。
- 124 使用独立热键范围，绑定主显示器身份；触发后显示控制台并定位显示卡，由用户查看当前和目标方向并确认试用。这样保留用户要求的执行前确认，试用后仍需在期限内保留；主显示器变化或前态变化时拒绝旧预览。
- 键盘与显示导航共用应用级请求状态、序号和确认，较新的请求不能被旧确认清除。旋转请求不直接写显示器，停止监听、窗口切换、档案试用和外部更改不得绕过显示域的检查。
- 只对已知原厂四个方向计算目标，不推测其他旋转或显示设备；不运行真实 GDI、事件日志、原生窗口、安装包或硬件，使用内存提供者、临时进程出口和模拟页面验证。

## 风险

竖屏交换宽高后的驱动支持与恢复仍需未来独立真机验收；独立进程无法证明显示驱动一定响应。原厂将模式写入注册表，自研试用维持既有仅当前会话的恢复语义，不擅自更改持久系统配置。

## 影响与验证

37项显示与档案内存测试、119项热键测试、16项核心事件和2项独立隔离进程测试通过；后者模拟父进程终止后由子进程恢复竖屏，不调用GDI。30项显示、键盘导航和档案模拟交互通过，新增模块边框检查失败后已调整并单独重跑4项旋转页面通过。360/1440浅深截图已检查；前端构建、主/模拟宿主编译、26项控件及源代码限制通过。未创建原生窗口、读取真实显示设备或运行原厂程序；此前安装包不含此功能。

## 备选方案

- 将旋转当成普通刷新率直接传给旧监护：旧监护只允许同几何频率变化，无法验证或恢复原厂方向规则，拒绝。
- 按键后直接修改并持久化系统显示设置：不满足用户要求的预览、确认和恢复，拒绝。
