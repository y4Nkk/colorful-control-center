# 原厂电池与充电保护契约

## 来源与所有权

Pi保留的原厂CC40 `PageFlexiCharger.Load_Preference/SetFlexiCharger`及本机DSDT的PK04 Case0x1E/0x1F确认充电保护包协议。PageFlexiCharger的sub30读取和sub31四字节设置已直接静态核对；研究目录的实验性cc3不作为原厂源码证据。`battery.rs`拥有预览和事务，`battery/protocol.rs`拥有编解码，`battery/native.rs`拥有Windows及DCHU调用；`api/battery.ts`是前端类型所有者。

## 充电保护

- cmd4双向包sub30读取：byte0为0/1开关，byte1开始阈值，byte2停止阈值，16..31和32..47各自非零项为固件允许的开始/停止候选。候选不是连续范围，不硬编码推荐值。
- sub31写入：byte1开关、byte2开始、byte3停止，其余为零。沿用已确认的固件包通道；CC40另有UI选择记忆，本实现不额外写入page1 offset46或原厂注册表。
- 请求携带expectedRevision和enabled/start/stop，拒绝未知字段、旧修订、候选变化或无效阈值。候选与当前策略共同生成修订，不绑定持续变化的电量。
- 开启时必须从候选选择且开始小于停止。原始关闭状态可含零阈值，关闭时不强造默认值。
- 写前确认电池存在；全局控制锁串行化，写后回读完整策略和候选。失败补偿到本次修改前状态，补偿失败保留诊断，可重新选择并提交所需值。卡片不提供初始恢复入口，也不保存首次修改前的基线。
- 回读证明固件策略，不证明实际充电电流、停止阈值或电池物理状态。

## 读数

`BatteryOverview` 将系统电量、供电和充电状态放在电池图旁。有系统估时时显示预计剩余时间。`BatteryArtwork` 的填充宽度取系统报告的 0–100% 电量，0% 显示空填充与数值，未知显示空填充与文字状态。充电徽记取明确的充电标志。卡片不展示 OEM 诊断与任务采样电量：2026-11-24 起「电池读数与诊断」和校准详情随信息图标入口移除，`diagnostics` 与任务 `facts` 仍由读取命令返回。

电池模块复用 `useDeviceSettings` 的 5 秒只读轮询。读取失败撤销可执行快照，恢复读取后独立保留最近的提交错误。开关和合法的充电范围直接提交。初始值为空或范围无效时，选择有效起止值后才自动写入。节能计划开关只提交保存计划，编辑中的时段与阈值在其编辑器内单独保存。

系统电量、AC、充电标志及预计剩余使用只读[GetSystemPowerStatus](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getsystempowerstatus)。255、-1与无电池按[结构定义](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-system_power_status)保留未知；未知标志不显示为0%或未在充电。

确认由电池供电时，显示「电池供电」及系统提供的预计剩余时间。确认外接电源时，按 Windows 充电标志区分「正在充电」「充电状态未知」和未在充电。明确未在充电时，100% 显示「已充满」。充电保护开启且电量高于开始阈值时显示「充电保护生效，暂不充电」。其余情况显示「未在充电」。供电来源未知时，按系统读数显示「供电未知」和充电状态。

读取失败在卡内直接说明原因，技术细节只留在错误链。充电保护读取失败分为三类：原厂组件缺失、缺少导出或没有双向包传输；通道调用失败或回包不完整；固件数据无法识别。领域把面向用户的原因写进 `chargeUnavailableReason`。固件返回空包表示未提供该功能，写「本机未提供充电保护功能」，不算读取失败。Windows 电源状态读取失败的原因写进 `powerUnavailableReason`。

扩展能力页版本1.0的13..14为原厂WMI16位图，bit9声明BatteryUtility才读取cmd7诊断。旧版能力不从有回声问题的整型导出推断支持；充电保护由自身sub30候选确定。原厂BatteryPackUtility提供cmd7布局：版本0、生产日期2、循环4、满充6、设计8、状态10（均u16），PF12与Operation16为u32，停止阈值20为byte。保留两个状态的完整32位，不复制原厂反编译中的ushort截断。

生产日期按原厂 SBS 压缩值解码并校验日历。两个容量均非零时给出满充与设计容量的比例，保留超过 100% 的读数。容量单位待确认，原始值随诊断一并返回，页面当前不展示。OEM 失败时仍独立保留 Windows 读数，并按上面的分类说明原因。

## 节能计划

`battery/energy/`拥有节能计划、记录和事务，`api/battery.ts`拥有前端契约。事实源为安装载荷EnergySave.MainWindow与FnKey.Features的GetAllCommandForWMI_118及本机静态DSDT的DCHU.SCMD 0x76。能力页仅在版本1.0的WMI16 bit8开放；未支持返回null，未知版本保留错误，不能从整数回声猜能力。

- cmd118的高字节为子命令：1同步本地星期/时分秒；2设置星期掩码和放电下限；3/4设置两个时段；5启停；6设置放电下限/充电上限。所有命令为4字节LE。时间为秒bit0、分钟bit6、小时bit12、星期bit17；时段起点小时bit6、终点小时bit17。原厂INI终点先加1，当前契约直接使用0..24点的右开区间，不保存旧终点别名。
- 每天编码255，指定星期编码bit0日到bit6六。时段可分别关闭，禁止越界、跨午夜和重叠。手动放电档位40..90、充电60..100，步长10；自动采用cmd17 bytes209/208，任一为0时原厂定义95/100，明确标记为原厂默认。
- 首次只读原厂`C:\ComboKey\EnergySave.ini`的当前选择和启停；读写使用当前严格Policy/Record契约，后续`energy-policy.json`是唯一保存所有者，不修改原厂文件。文件不存在或Count为0记录为null，界面显示未保存计划；不能把缺少配置推断成已读到的固件空时段。此初态的恢复语义明确为清除本应用时段并恢复捕获的充电策略，不宣称精确还原未公开的固件计划。
- 每次写前核对计划、能力、充电状态和恢复记录的修订；准备记录先原子落盘，再按禁用→时间/星期/时段/阈值→启用发送，首错停止并独立补偿计划与充电。保存提交失败也补偿；失败记录与初始快照保留，未完成恢复时拒绝继续应用。普通打开不重发计划，计划发送成功与物理时段效果分开。
- 节能和充电保护共用BAEE、BSCP/BTCP；运行本应用节能计划或存在未恢复操作时，充电入口禁止覆盖。停止先禁用并清空两个时段，再恢复最近一次启用前的充电策略；初始恢复保留首次接管快照。充电策略回读覆盖开关、阈值和候选，不能据此声称读到了时段执行状态。
- 页面分别展示保存计划、待发送草稿、关联充电回读、停止和初始恢复目标。草稿编辑不写硬件；确认绑定整份请求，停止只发送已保存计划且保留未提交时段草稿。未知/无电池禁止发送，不支持的机型不提供入口。

验证使用内存传输、私有临时目录内的UTF-16 INI和严格模拟IPC；未读取真实电池或执行实际节能命令。充电/节能的档案集成见下节；供电与唤醒的后台应用已由统一档案策略接入，实际星期/时段、充放电和后台共存留待独立真机验收。

## 充电与节能档案

- batteryCharge保存values及startValues/stopValues，绑定当前固件候选。启用目标遵守候选和开始小于停止；关闭目标保留完整原始快照，包括0/0，不补默认阈值。档案重放精确写入已校验的目标快照，单项草稿仍使用候选约束。
- batteryEnergy保存capability与完整policy。捕获启用计划时不生成独立充电目标；已保存但关闭的计划可与充电目标同时捕获，无原始计划仍为null，不虚构时段。未确认电池、待恢复节能或校准记录不能生成可执行电池档案。
- 电池Scope在HAL前取得原控制器的写互斥锁，单项读/写及节能入口同序。原厂INI报告计划启用但尚无本应用记录时，也禁止单独覆盖阈值。档案启用节能与独立阈值互斥；停止计划先恢复stopCharge，再按该预期状态应用独立目标。预检、执行均核对状态，局部恢复成功不重复外层补偿。
- 节能Store更新要求完整期望Record匹配；每次固件输出和充电恢复也核对拥有的记录、能力和候选，外部变化时停止旧输出及旧补偿，不覆盖现有文件。写入大小上限与读取一致。后续域失败恢复本次充电/计划及先前记录，首次接管仍保留原始持久基线。
- UI用左右模块、真实阈值环、明确关闭状态、星期与24小时时段预览。控制台编辑与档案共用时间条；读取与预览不启动校准。三个电池读取effect取消后释放当前请求引用，StrictMode和快速切页不被过期请求锁住，旧结果不覆盖新状态。

## 电池校准

`battery/calibration/`拥有任务、协议、记录和主进程管理，`api/battery.ts`拥有UI契约。BatteryPackUtility的Discharge1→Charge1→Discharge2→Charge2→AdjustingDischarge顺序已接入；cmd121/sub28、sub29及cmd118/sub7按AC/Refresh/FlexiCharge顺序发送，放电为0/1/0、充电为1/1/0、释放为1/0/1。完整状态bit4/5与独立完全放电事件推进阶段，不以电量100%代替完整充电。每批事件最多推进一个阶段，调整目标绑定预览时的原厂停止阈值。

- 已安装DCHUService.exe（SHA256 A6420A84E15FC77B2948F20B8F630B912632F3922C1DE4BC229A590B7C86DF56）静态源码确认OutLog/PowerBIOSServer_Out的Arg001^85/90/91。只读从订阅时末尾开始，要求服务运行、page1[12]就绪及OutLog/PowerBiosServerLog存在；不重开独占ACPI桥、不写原厂日志或配置。记录缺口、清空、畸形和积压均中止并恢复。
- 主动放电时Windows AC离线是预期事实；真正拔电事件优先暂停并释放强制放电，重新接入后继续原阶段。充电阶段先观察AC恢复，再把后续离线视作拔电。无电池、未知电源/电量、永久故障、停止阈值变化或调度间隔超过5秒均中止。
- `battery-calibration.json`仅保存本应用任务及恢复快照；保存节能计划仍由energy-policy.json唯一拥有。先原子准备记录，独立进程保留控制权并完成READY/ARM后才写入；主进程每500ms发送心跳，不依赖页面。失联或3秒无心跳触发释放和策略恢复，恢复失败重试且保留记录；不在重开页面时自动续跑充放电。
- 主进程发现工作进程提前退出时补偿；重新打开后的未完成记录可明确确认恢复。恢复分别尝试三条释放命令、充电/节能快照及防睡眠释放，首个错误不阻止其余恢复。无保存节能计划时沿用清除本应用时段的语义，不宣称还原未知固件计划。
- 原包batteryUtility.pow及离线生成的15项设置/27个AC/DC索引随程序嵌入，SHA256绑定；不使用SystemRequired代替完整电源策略。预览绑定实际活动GUID，操作标识派生私有GUID；确认目标不存在后先保存planPrepared，再导入、核对全部索引、激活并回读。每次采样检查活动计划及索引，外部变化中止恢复。恢复先激活并核对原计划，再删除本次临时计划；失败保留记录，资源清理只删除与嵌入文件完全相同的应用副本。离线解析工具不加载注册表或调用电源API。
- 模式、性能选项和相关档案在预检、执行和恢复时读取同一校准记录，未完成或损坏记录阻止覆盖计划；页面在校准取得/释放控制时刷新对应状态。工作进程记录目录使用与Tauri一致的RoamingAppData Known Folder及应用标识，不从APPDATA环境变量另建路径。FnKey的低电量事件59/60会另行控制电池。`hal/oem_owner` 按电池范围检测 FnKey.exe 和 BatteryPackUtility.exe，开始时拒绝占用，运行中出现时中止并恢复。卡片可打开共享 FnKey 退出确认，退出后重新预览校准，再确认开始。BatteryPackUtility 由用户手动退出。
- UI分开展示阶段、阶段耗时和总耗时，停止请求已发送不代表恢复已完成；状态以工作进程和记录为准。五阶段不是总体耗时比例，不绘制虚构完成百分比。充电/节能写入口同时检查未完成校准记录，损坏记录保留并拒绝覆盖。

## 原厂低电量阈值事件

FnKey 7.19.5.0 的209/210分别设置和恢复Windows低电量阈值，与充电保护不是同一功能。静态检查Pi会话中的`FnKey/Features.cs`和`powerlife.dll`（SHA256 `cabd0a2c74b3f1d6eb7be4b3e0e601bd855e9b6694009ba980f6244c141405e2`）：209把活动计划低/严重/预留电量的电池值缓存到page1[47..49]，将活动计划及三个标准计划的插电和电池值依次设置为25%、20%、22%；210读取缓存并恢复。应用只针对实际存在的计划，不创建缺失计划；计划目标按[低电量](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/battery-settings-low-battery-threshold)、[严重电量](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/battery-settings-critical-battery-threshold)及[预留电量](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/battery-settings-reserve-battery-level)设置读取与回写。

- 独立范围绑定活动计划、已存在标准计划、逐字段原值和原厂缓存；页面在授权前展示全部插电/电池值与事件目标，初始恢复独立预览确认。读取不修改计划或创建记录。已有非零原厂缓存但没有本应用记录时拒绝推测原值；活动计划或标准计划集合变化停止执行。
- `hotkeys/battery_thresholds/`是事务与`oem-battery-thresholds.json`的唯一所有者；每个尝试字段先原子记录，再写入和回读。记录保留各计划独立的原值、实际接管字段及原缓存，重复209不覆盖首次基线。209失败或许可撤销时尝试逆序恢复；中断或恢复未完成时保留记录供重新预览和重试。210与显式恢复只修改本应用接管字段，外部改写目标字段时拒绝覆盖；活动计划改变后不切回旧计划。
- 原厂只缓存活动计划三个电池值，不能精确还原不同计划和插电原值；本应用按逐字段记录恢复，保留未接管字段。校准任务持有系统计划时禁止写入。已确认方法`SetBatteryLow1Low2ToEC`在当前静态输入中没有调用者，不自动发送EC命令；44/45、47和59/60不是本次阈值事件。
