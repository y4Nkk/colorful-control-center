# Agent Note: 原厂Turbo风扇与DTT独立设置

Status: implemented

## 问题

原厂FnKey.Features.SetPowerMode及CC40.Interface_Fan确认Turbo保存page4 offset8、DTT保存page1 offset32，再发送cmd121/sub25的性能模式2及0x40/0x80位；Turbo操作还重置风扇到自动。最初模式代码只保留字段，缺少编辑入口及完整恢复。研究目录实验性cc3不再作为原厂来源。TurboFan不能标为Intel CPU睿频开关。

## 决定

- powerctl/mode拥有字段和恢复，扩展CoreSnapshot同时捕获两个原始保存值；模式、选项与档案失败恢复共用该快照，不创建另一套恢复基线。
- 能力页v1.0 byte16 bit4提供TurboFan；WMI96的10..11小端u16 bit12提供DTT。2026-11-14核对FnKey.Features确认，旧实现误读WMI122的6..9（其bit12实际为灯条），已同步修正代码和夹具，单独覆盖两位互不替代。DTT启用需要按原厂描述识别Dynamic Tuning驱动，只读枚举失败不冒充已安装。
- 两项草稿分别编辑、统一确认，在性能模式才开放执行；保留另一项。自定义固件曲线和软件曲线时不开放Turbo变更，避免撤销未预览的曲线。Turbo变化预览其自动风扇联动；DTT单独变化不改系统电源计划。
- 保存值回读、命令接受、物理效果分别表达；失败恢复模式、保存选项及风扇，恢复失败保留同一初始快照。旧修订绑定模式、能力、驱动状态、选项和当前风扇。
- UI使用现有原语，设置变化刷新模式联动预览和其他相关域。测试仅注入内存及假驱动状态，不执行实际驱动枚举或OEM命令。

## 影响与验证

- 新增mode/boost、只读驱动识别、2项IPC与控制台性能选项；扩展模式CoreSnapshot的原始保存字段，原厂模式及档案恢复共用，不保留旧的仅命令快照恢复路径。
- 模式域25项聚焦检查通过，包含11项新选项/驱动描述检查；另4项生产工作流内存FFI检查通过，覆盖独立DTT不改Windows/风扇、Turbo风扇写入失败补偿、命令及补偿失败后用户重试、后续模式切换还原首次选项。复用档案夹具，驱动状态显式注入，不调用真实枚举。
- 档案34项回归与4项页面隔离IPC检查通过，覆盖预览确认重置、支持范围、模式/驱动/曲线约束和过期请求。前端构建、workspace及control-sim检查通过；没有执行真实驱动枚举、注册表读取或OEM写入。

## 风险

2026-11-14性能选项已纳入全设备档案，详见implemented/feature/2026-11-14-complete-device-profiles.md。模式Plan直接合入目标位；仅选项Plan保留Windows策略、临时释放/恢复软件会话；单项与档案共用首次基线。161项档案、30项模式、8项假监护进程及19项相关页面检查通过，驱动查询与监护工厂均显式注入。

驱动匹配与保存回读不证明DTT实际调度或风扇效果。普通模式切换沿用当前功能，不将原厂UI耦合开关误称为CPU降压或睿频控制。

## 备选方案

- 独立快照只还原一个保存字节：模式和档案恢复会遗留不匹配，拒绝。
- 把TurboFan命名为CPU Turbo Boost：与原厂控制对象不符，拒绝。
