# Agent Note: 按原厂协议补齐键盘灯效与分区恢复

Status: implemented

## 问题

现有灯光接口只有同色与亮度，首次基线不保留编码类型，恢复时无条件回放三区静态色，会把原厂动态模式改成静态。用户要求继续对照本机反编译和 Pi 会话完成代码，不调试硬件。

## 决定

- 以 kbled RGBKB.SetMode/SetColor/SetLedOnOff 和 CC40 对应实现为事实源，接入 0–8 九种模式、三区独立颜色/开关、普通与 6/22 特殊蓝色编码。
- 单一类型化请求替换旧 family/color/brightness 三参数；读侧同时提供模式、总开关、三区颜色/开关。原始模式与编码进入首次及每次事务快照，失败和用户恢复均回放原灯效。
- 未识别的保存模式或非法亮度在任何写入前拒绝，不能猜静态基线。已识别类型禁止跨家族写入。
- 2026-11-18 灯光页以一整块带数字区的键盘示意取代三区缩略图。三区选择与色环、精确选色、开关和亮度共用草稿。键帽色彩随配置和亮度变化，固件配色只显示键位示意。应用前仍走页面预览和确认，恢复复用原事务。
- 2026-11-19 色环中心通过全局 `ColorPicker` 打开应用内选色面板。色环和色块共用同一颜色草稿。同色时编辑整键盘，分区和呼吸时编辑当前灯区。三区 RGB 亮度提供关闭与 1–4 档按钮，直接选择草稿档位，预览后统一确认。白光键盘沿用其独立亮度控件。

## 风险

即时灯光没有可靠回读；隔离测试证明代码协议和事务，物理灯效留待独立真机验收。逐键键盘使用另一传输协议，不向该家族发送 cmd103。

## 备选方案

- 沿用静态回放：会破坏首次状态，拒绝。
- 等真机验收再接入已明确的原厂模式：不符合用户继续代码工作的要求。
