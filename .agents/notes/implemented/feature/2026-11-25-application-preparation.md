# Agent Note: 主窗口启动准备页

Status: implemented

## 问题

原厂软件检查和硬件装配在主窗口创建前完成，等待期间没有反馈。Agent Switchboard 在同一主窗口中先显示标题栏、居中品牌、当前阶段、循环进度条和用时，准备完成后交给工作区。

## 决定

- `startup/preparation.rs` 拥有初始化状态。创建主窗口后在后台按原顺序检查原厂软件、装配硬件、启动已有服务。控制租约与退出监护在初始化前建立，退出收尾先等待准备线程结束再检查领域状态。准备状态控制主窗 IPC 与托盘硬件控制的准入，登录档案仍由既有授权流程调度。
- `ApplicationPreparation` 复用应用品牌、窗口按钮与视觉令牌。准备期间显示阶段、循环进度条和用时，减少动效时静止。工作区在偏好读取结束后进入指定启动页。连接失败可重新检查，偏好读取失败可重新读取或进入设置，原生准备失败可查看日志、重新启动或退出。

## 影响与验证

- 成功启动继续使用原有窗口显示偏好和唤回路径。运行时准备失败会显示主窗口供诊断。窗口创建前的失败继续交给 Windows 原生提示。
- 前端构建、Rust 检查与两项命令准入测试通过。隔离浏览器覆盖各准备阶段、浅深主题、减少动效、失败恢复、启动页、托盘导航与标题栏。原厂驱动初始化、真实桌面唤回和开机档案待真机验证。

## 备选方案

- 固定延时启动页无法反映硬件初始化。
- 第二个启动窗口会分裂默认启动、托盘唤回和恢复体验。
