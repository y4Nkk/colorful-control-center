# Agent Note: OEM 风扇曲线与独立进程监护

Status: implemented

## 问题

Phase 2 路线要求「任意控制点曲线 + 滞后回差 + 斜坡限制 + 看门狗」。固件两点（cmd14）与十级 RPM 表（cmd4）不等同于软件逐 tick 控制，不能混淆能力或验收证据；软件方式已在本机静态协议核对后另行接入。

## 决定

（2026-11-12，基于 oem-dchu-contract.md 的 OEM 实现审查）

1. 两点固件曲线保留 T1/D1 与末端固定、T2/D2/T3/D3 可调。散热面板默认显示实测温度和转速表盘。设备支持固件曲线时，左侧「编辑曲线」在所有档位开放。档案按已预览的目标应用，软件方式直接输出逐通道 C1。
2. cmd14 斜率为大端，page4 斜率为小端；百分比字节使用与 OEM Math.Round 一致的中点取偶数及运算顺序。
3. 2026-11-19 重新核对本机原厂 ControlCenter30 6.85、FnKey 7.19.5 和 FanSpeedSetting 6.91。预设经 SetPowerMode 和 Load_FanMode_forFn_3 写入固件模式、风扇档和偏移，风扇页面直接写入固件档位及两点/RPM 表。这些入口没有读取实时温度作为写入条件。固件操作交给原厂控制器执行，沿用能力验证、确认、回读和失败恢复。由应用持续发送风扇强度指令的软件曲线独占 READY/ARM/ARMED 监护，断连、心跳超时、传感器失效、已出现 GPU 丢失或达到 95°C 时恢复自动模式。切回固件前先释放软件输出并等监护退出。父进程负责失败补偿与重试。
4. 模式按能力开放；page7[20] bit4 选择十级 RPM 布局时走专用成对表事务，禁止误用两点曲线。十级表接入决策见 `implemented/feature/2026-11-12-rpm-firmware-curves.md`。未知能力页版本不开放自定义曲线。
5. ccc-core 引擎的软件会话经 C1 下发。现行控制权及监护门控见 implemented/feature/2026-11-12-software-fan-acpi-channel.md。

### 2026-11-24 风扇事务审查修正

- 原生 `cmd14` 接受固件 `PK0E` 的整数结果 `0x14`，并单独核对 EC 曲线读回。运行档位来自 `cmd13[14]` 的 D7 位图。保存档位只作为保存字段和模式策略，不能充当运行事实。
- 基准 DSDT 的固定只读窗口提供原始斜率和偏移值。两点曲线从即时整包快照修改指定通道，伴随通道和独立的保存字段分别保留。缺少可信即时前态时，拒绝需要该前态的写入。
- 固件事务捕获首次基线和本次前态。失败按所属字段逐项尝试恢复并报告，软件监护的自动恢复不覆盖固件事务。恢复固件默认时同步清除支持的偏移及所属记忆槽。
- 从面板、预设或档案启用已读 RPM 表时保留原始字节，已确认的原厂停转级也保留。新提交的点位仍按同一手动范围校验。Turbo 与自定义固件及软件曲线在目标预检及写入时复核。

### 2026-11-26 风扇档位写后确认

- 基准机的原厂工具和控制台都经 SCMD 121/1 下发 D7 绝对档位。命令号与即时档位分别确认。`cmd13[14]` 的自动和静音位图分别为 `0x02` 和 `0x08`。本机日志记录自动档下发后 510 ms 内六次回读 `0x08`，回读序列无法确定 EC 未到达目标的固件原因。
- HAL 每次发送后立即回读，再约每 100 ms 回读。普通切档需连续两次读到目标。单轮观察 500 ms，首轮多次回读全部为同一个可识别的非目标档位时，限一次补发相同的目标。首个读数已耗尽观察窗口时仍复核一次，窗口末首次到达目标时同样复核。变化和未知的读数保留在记录中，传输错误立即返回。
- 原厂电源预设命令也可能异步改变风扇档位。发送前标记即时档位待确认，固件管理的预设继续只保存基础档位。其后的显式风扇命令和恢复写入均观察到窗口末，以连续两次目标读数确认。失败补偿使用原始档位，并保留请求与恢复两方的结果。

### 2026-11-25 曲线点拖动磁吸

- 两点风扇强度曲线和十级 RPM 图共用整十值拖动磁吸。温度和目标百分比分别吸入、保持和释放，只吸附各自允许范围内的整十点。沿用全局滑杆的像素距离与相邻刻度约束，输入框和键盘沿用精确步进。

### 曲线草稿与应用

- 两点和十级 RPM 编辑共用一个会话，点位输入、拖动和按键只更新草稿。「应用」校验并原子保存本地自定义配置，随后回到转速表盘。取消丢弃未保存的编辑，失败保留草稿。保存期间当前档位和 EC 保持原状。
- 本地文件保存用户调整过的通道，未配置通道取固件当前曲线。后端持 HAL 写锁核对保存来源。来源修订包括编辑所用的曲线、通道限制及本地配置，与运行档位和偏移无关。
- 用户从散热面板或原厂快捷键明确选择「自定义」时，校验当前硬件并事务化应用已保存的点位和档位。已处于自定义档时，重新点选可应用待写入的配置。固件写入失败时恢复前态，本地配置保留以便重试。预设联动、配置档案和固件恢复沿用各自的目标。

## 影响

- 2026-11-26 的稳定错档补发回归覆盖自动档切换与失败恢复。最初两条新增用例修正后通过。复审的五条用例分别复现了短暂命中被保存、预设跳过恢复、窗口末孤立命中或首次慢读导致的确认错误。修正后 193 项原生隔离检查和 11 项偏移探测测试通过。真机档位写入待验。
- 2026-11-24 的事务修正通过 217 项原生隔离、27 项核心风扇及 RPM、21 项探测及 FFI 检查、68 项相关浏览器回归。基准机只读验证了两点曲线与偏移的固定窗口。真机写入与原厂除尘反馈待验。
- 两点、十级 RPM、软件自由曲线、独立监护和恢复均已接入；隔离测试不能代替物理散热验收。
- 引擎拆到独立 `ccc-core` crate 还解决了 mingw ld 对 cdylib 测试链接的 "export ordinal too large" 限制（纯逻辑测试链接 rlib）。
- 写入路径集中在 fanctl（cmd4/14/121/page4），两点与 RPM 分别复用 ccc-core 校验；用户新目标最低 20%，恢复可信原始表或原厂固定默认表不伪造这个下限。
- 软件闭环已使用本机原厂逐通道协议，不依赖原始寄存器；隔离测试不证明物理散热或驱动阻塞时的效果。

## 备选方案

- **通过裸端口实现 NBFC 式控制**：本机原始 GPU 写寄存器未知，且需要额外传输。已采用经本机 DSDT 确认的 OEM C1 路径。
- **仅做模式切换不做曲线**：不能满足可调曲线需求。原厂已有两点与十级可调实现，本应用按实际协议接入。
