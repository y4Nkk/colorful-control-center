# Agent Note: 原厂 USB 选择性暂停策略

Status: implemented

## 问题

FnKey的USB平台功能不是USB充电开关。固件报告后，原厂powerlife.SetUSB同时修改三个标准Windows计划，需要独立表达固件建议、系统现值及可恢复的字段写集。

## 决策

- 来源为FnKey.Features.Workaround_USBSelectiveSuspendControl、CallingVariations ordinal41，以及powerlife.dll（SHA256 CABD0A2C74B3F1D6EB7BE4B3E0E601BD855E9B6694009BA980F6244C141405E2）RVA4b30。byte23 bit0声明能力，cmd4/sub53值0/1/2表示不干预/建议启用/建议关闭。该getter不拥有Windows现值。
- 静态导出显示SetUSB向平衡/高性能/节能三GUID依次调用PowerWriteACValueIndex及PowerWriteDCValueIndex；USB子组2a737441-1930-4402-8d77-b2bebba308a3，设置48e6b7a6-50f5-4782-a5d4-53bb8f07e226。FnKey随后重载当前活动计划，不改变活动计划身份。
- 复用hal/power_plan唯一原生传输，扩展明确的计划枚举及USB读写方法，同时更新内存提供者；测试未注入通道时继续拒绝原生回退。实际存在的标准计划纳入同次事务，缺失计划明确列出，不创建计划或猜默认值。
- platform/usb拥有能力、固件建议、三个计划AC/DC现值、预览修订和首次恢复基线。目标独立编辑插电/电池启用状态，确认后只写USB字段，全部预检、回读、首错补偿并保留恢复错误；不修改ASPM、CPU、显示超时或当前计划选择。
- 预览绑定计划集合、当前活动计划、能力/固件建议及所有目标值；执行时重新捕获，外部切换撤销确认。仅在每个字段实际写入前登记其最初值；没有修改的AC/DC字段不纳入恢复。补偿仅恢复已尝试字段，外部修改尚未执行的字段保留。其他控制者切换当前计划后不强制切回旧计划。校准期间与系统计划互斥，原厂控制者存在时不接管。
- 控制台按固件声明显示各标准计划的统一设置及原厂建议。固件未声明能力或建议读取失败时，从 Windows 电源 API 读取当前活动计划的 AC/DC 值用于只读显示，活动计划可以是自定义计划。标准计划写入、档案捕获和初始恢复继续使用原有能力、快照和事务检查。

## 影响与验证

11项内存检查通过，覆盖六字段写集、计划缺失、旧预览、每次部分写/激活失败、补偿失败重试、初始恢复、外部切换与校准互斥。7项模拟IPC页面检查通过，覆盖完整预览、两步确认、AC/DC字段保留、未知、能力丢失恢复、读取失败草稿及360/760/1440px布局；已检查卡片截图。共享模式系统计划4项与档案应用25项回归通过，前端构建通过。测试仅使用内存提供者与模拟IPC，没有调用实际电源API或固件。

## 风险

Windows设置回读不表示USB外设确已休眠；缺失或外部删除计划会限制完整恢复。原厂在后台也可能修改这些设置，执行前必须重新核对。此功能不自动跟随AC/DC、唤醒或启动事件。

## 备选方案

- 将sub53猜成固件setter：它是原厂getter，拒绝。
- 只修改当前计划：偏离原厂三个计划写集，拒绝。
- 调用原库并忽略每次写入错误：不能提供原值恢复与诊断，使用现有原生传输。
