# Agent Note: 原厂风扇除尘与定时计划

Status: implemented

## 问题

原厂FanSpeedSetting已有除尘启动、固件状态和星期/整点/唤醒计划，自研应用尚未接入。原厂AntiDust_Done只清缓存，没有停止命令；复制该按钮会伪造停止。定时除尘与软件闭环输出也不能同时占用风扇。

## 决定

- fanctl/dust 拥有领域事实、首次计划基线及事务。HAL 拒绝全零 PSF 能力包。v1.0 使用 bytes10..11 的 WMI96 bit7，v0.0 使用已确认的 WMI96 整数 bit7，整数回声和传输失败均表示未知。桌面与独立偏移探测共用 HAL 状态读取。cmd4 包 `[1,163,0,0,0,0,184]` 由 PK04 转发给 EC。回读 `FCMD=0xB8, FDAT=0` 确认空闲，`FDAT=1` 在 `FCMD=0xB8/0` 时确认运行。PK04 或 ECMD 跳过可返回全零，命令清零并返回 `FDAT=0` 的情况待目标机补证，在此之前锁定操作。page4[80] 仅是原厂缓存。
- 一次性启动为cmd121/sub41值1；执行前重新核对预览、已确认空闲、EC 即时模式非全速、CPU/GPU 风扇强度均不超过 50%、无软件接管及校准互斥。请求即使返回错误也消费原预览，不自动重发；明确区分请求已发送、观察到运行和运行后结束，不臆造停止、时长或完成比例。
- 计划为cmd121/sub40，值days|resume<<7|hour<<8；保存page4[81..85]。启用前按原厂cmd118/sub1同步本地时钟，读取本身不写入或默认开启。首次原厂未保存计划保留未知；撤销本次设置时清除本次触发并恢复原保存字节，明确无法证明未公开的先前EC计划。
- 计划写前重新确认空闲，写后核对所属保存字段。失败后在已确认空闲时补偿命令与原字节并保留重试基线。只恢复81..85，保留曲线、模式及其他域字段。正在除尘或状态未知时阻止普通风扇、模式和除尘计划写入，安全熔断及监护恢复仍可执行。软件曲线仅在已明确关闭除尘触发时开放。启动除尘和启用计划需确认软件调速已解除。
- 控制台卡片按左右布局分开固件状态/一次操作与计划草稿，使用既有Surface/Checkbox/Select/ConfirmButton。当前、草稿、确认、恢复语义分开，轮询保留草稿，读取失败撤销执行快照。
- 隔离页面宿主关闭文件监听和HMR，检查期间只读取当前源文件，避免监听Rust target目录产生EBUSY；不改变实际开发服务器。浏览器测试仅模拟IPC，访问本地1450端口须具备沙箱回环连接权限。

## 影响与验证

新增4项类型化IPC与左右卡片，普通风扇/模式及档案预检、已准备模式的执行和恢复接入同一实际状态互斥；前端直接显示禁止原因并撤销确认。15项领域内存、2项档案/模式互斥及7项除尘页面检查通过；风扇34项、档案36项、模式30项及后补1项预览后互斥检查分批通过。相关性能选项4项、PD8项页面检查通过；截图检查了左右布局与360px回流，修正时间标签折行。npm run build、cargo check --offline --workspace、control-sim编译、25项控件和笔记检查通过。未执行实际OEM、驱动或硬件调用。

生产FFI测试桩明确填充256B加本机DLL额外首字节复制，不通过放宽生产ABI来掩盖空响应。时钟同步失败发生在计划命令前时不触发计划补偿；避免原厂未报告初态被无操作失败意外关闭。

## 风险

计划回读只证明保存意图，运行状态没有公开总时长；原厂后台可能独立修改计划。未保存初态没有可靠EC计划getter，恢复必须明确其边界。实际清灰效果另行验收。

## 备选方案

- 把AntiDust_Done当停止命令或猜sub41值0：没有原厂执行证据，拒绝。
- 启动时照搬原厂每日/唤醒默认计划：普通打开会写硬件，拒绝。
- 用软件定时器模拟除尘或使闭环覆盖固件任务：偏离原厂协议，拒绝。
