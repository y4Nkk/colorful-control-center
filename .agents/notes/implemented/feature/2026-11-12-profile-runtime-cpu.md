# Agent Note: 性能档案的即时 CPU 调校与恢复

Status: implemented

## 问题

当前档案只将 PL/电压写入 page6，无法实现已在控制台提供的即时 MSR 调校。只追加写入而不预检和恢复，会使后续 GPU/风扇失败时留下 CPU 参数。保存值与实际值含义不同，不能改变已有档案字段的解释。

## 决定

- ProfileSettings 新增独立 runtimeCpu 可选字段；原 pl1W/pl2W/coreOffsetMv/gtOffsetMv 继续表示 OEM 保存值。即时配置由 powerctl/runtime.rs 拥有，PL 允许 RAPL 可表示的实际精度，电压保存有符号编码单位，预览换算为 mV，避免捕获当前值时取整丢失。
- HAL 统一创建 MSR 会话；生产打开 PawnIO，测试只能使用显式注入的内存传输，没有真实设备回退。控制台与档案复用即时配置校验与执行，范围保持 PL 35–157 W、核心/GT 使用原应用范围对应的编码边界。
- 档案任何硬件目标写入前完成全部预检，保存请求域原始寄存器/电压编码并保留同一传输会话。OEM 模式、风扇、保存值之后执行即时 CPU，再执行 GPU；首错停止。回滚先 GPU/保存值/OEM 模式，再恢复即时 CPU，最后风扇，避免模式切换覆盖恢复结果。
- 单域即时调节也在写入前记住用户恢复基线。即时步骤失败或回读不一致均恢复、回读原状态，保留恢复失败信息；不尝试安装驱动或绕过锁。
- CPU 目标编码已与现值一致时只确认现值，不重复目标写入；锁定但一致的 PL 不阻止档案其他域。有差异的锁定目标仍拒绝。恢复也允许确认已恢复的原编码；这不构成硬件可写性的证明。
- 所有预检成功后、档案首次目标写入前登记即时 CPU 用户基线，因为更早执行的 OEM 模式本身可能改变 CPU；不能等到即时 CPU 步骤才登记。电源模式同样在命令前登记初始模式，失败补偿也失败时仍可手动重试。
- 控制台同一次 CPU 应用统一提交全部变更字段：即时使用同一运行时计划，保存使用同一 page6 字段事务。移除逐 PL/电压分开的旧 IPC，避免单个确认中前一项成功、后一项失败后留下部分变更；CLI 的原始探测协议不受影响。
- page6 的跨域快照和用户基线同时保留原 IsSaved 字节，恢复时最后写回原触发值，而不是固定写 1；目标字段写入失败也保留可重试的基线。
- 捕获、序列化、预览、导入校验、自启与手动应用复用同一契约；实际机器 PL/降压可行性仍未知，当前仅运行隔离测试。
- 手动应用携带完整的已预览档案，服务端与当前文件比对，发生变化就要求重新预览，不能仅按文件名重读并执行不同目标。显式自启仍应用用户选择的最新档案快照，使用同一硬件事务。
- savedAtMs 限制为 JavaScript Date 可表示的整数毫秒，保证完整预览经 IPC 往返后可精确比对，不接受无法显示或精度丢失的时间戳。
- 浏览器验证发现统一 IPC 错误是普通对象，现有 String(error) 消费者会显示 [object Object]。在 api/shared.ts 让 CommandError 继承 Error 并保留 code/message，文字化只输出原错误正文，使锁位、档案变化和恢复诊断可见。

## 风险

OEM 后台可再次覆盖参数；回读只验证当前时刻，不能证明长期稳定性。Mailbox 查询本身经 MSR 命令，实际机器验收仍须后续明确授权。

## 备选方案

- 将原保存字段直接改为即时写入：改变现有持久数据含义，不采用。
- 只保存 page6 并称为即时应用：不能满足目标，不采用。
- 失败继续执行其他域或舍弃恢复错误：不能提供完整恢复闭环，不采用。
