# Agent Note: 原厂颜色循环与索引恢复

Status: implemented

## 问题

真实FnKey.Form1的57号事件调用KBModule.Change_ToggleRGBColor，RGBKB.Set_ToggleRGBColor推进page2[127]索引、保存All颜色并调用SetAllColor。KBModule仅对6/22/38初始化表；默认1–15，CustomerID为0且SMBIOS系统厂商名包含大小写敏感MONSTER时1–16。SetAllColor只发送F0/F1/F2及已声明Logo/普通灯条的当前颜色，不改保存模式、亮度或开关。

## 决定

- lighting唯一拥有循环颜色、索引及首次恢复；复用当前领域锁、HAL锁和普通灯光基线。索引是热键序列位置，不是档案灯效目标，档案继续捕获原厂保存模式和All色；仅在本应用尝试修改索引时纳入初始恢复，其他灯光操作不覆盖未接管索引。
- 独立keyboardColor授权绑定原始类型、CustomerID、厂商规则和外围能力；设备或规则变化须重新确认。读取不初始化索引，0按原版推进到1；FnKey.exe的Set_ToggleRGBColor在IL_0023/0024及IL_0047/0048使用add、conv.u1，255必须回卷0并发送表0蓝色。只拒绝递增后仍超出当前表范围的值，不用更窄的输入限制替代原版路径。
- 按原版发送顺序执行颜色命令，仅保存All及循环索引，写后回读；部分失败回放本次保存配置并恢复原索引。保存字段与物理灯光分开展示，不以命令返回声称物理颜色回读。
- hal/smbios拥有只读系统厂商，按RSMB及Type1解析，不修改固件。测试必须明确注入厂商或内存IO，不能调用真实系统查询。

现有普通RGB传输的唯一所有者为lighting/protocol.rs，6/22继续使用已选定的本机LedKeyboardSetting 6.26编码，38使用已接入FnKey编码；不因热键切入CC40/FnKey另一版本的半分量编码。事件分支、调色板及索引来自真实FnKey，所有颜色写入继续遵守同一设备编码契约，具体版本差异保留在docs/keyboard-contract.md。

## 影响与验证

9项纯领域、4项跨域及独立授权共14项聚焦原生检查通过，另2项SMBIOS纯字节检查通过。覆盖完整调色板及边界、类型/规则/能力变化、精确选定型号编码、仅颜色与索引保存、发送/保存/无效果写入、部分补偿及恢复失败重试；普通操作不接管索引，颜色热键才记录原始位置。档案捕获及后续GPU失败共用基线，未添加第二份档案颜色结构。

完整档案筛选293项通过（含11项显示领域复用，另2项需明确注入的隔离设备组合保持忽略），灯光94项、热键13项及核心事件5项通过。最终14项相关模拟页面与授权/布局检查及26项控件通过，最终卡片已目检。npm构建、主与模拟宿主离线编译、源码500/80和笔记校验通过；没有新增依赖。静态IL片段保存在target/ui-check/color-cycle-index.il.txt，覆盖两个add/conv.u1分支；新增检查遍历两种调色板的全部256个原始字节，并验证255→0及原始255恢复。

只使用内存、私有测试文件及模拟IPC；系统厂商必须明确注入，原生SMBIOS读取不编入测试路径，没有实际固件查询、OEM访问、热键或灯光操作。

即时灯光没有可靠读取接口；保存模式不因颜色热键自动更改。不同固件中颜色命令对动态效果的可见影响仍需另行物理验收，本轮不运行原厂程序或硬件。

## 备选方案

- 强制切换静态模式：原版没有修改Mode，不能替代成另一行为。
- 只改All字段或漏存索引：不能复刻实际命令或后续循环次序。
- 对所有RGB或固定15色开放：与原版类型和MONSTER分支不符。
- 直接读取本机SMBIOS或触发热键验证：遵守不调试硬件，使用纯数据与显式内存传输。
