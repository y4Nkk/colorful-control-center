# OEM 显示、显卡与平台电源契约

## 来源与执行边界

本机 FnKey 反编译 `Features.SetNVIDIAPower` 委托 `cc30wk.exe 0x0013 0/1`，通过服务执行。现已在本机FnKeyPack 7.19.5.0 x64载荷找到并静态反编译助手7.0.15.0，SHA256为`7C2C1F43479CDE0B77E08432EEEC420D58375ADE4D69293E39DF720B3B847C8B`；此前助手缺失的判断已更正。

助手`NVPCF_DisableEnable`定位SoftwareDevices类GUID `62F9C741-B25A-46CE-B54C-9BCCCE08B6F2`中硬件ID含`ACPI\NVDA0820`的控制节点。应用已使用相同目标和顺序：开启先cmd4/sub34值1，再启用节点；关闭先三次尝试停用节点，再cmd4/sub34值0，间隔100ms。原PCI显示适配器PnPUtil禁用路径已删除。回读证明控制节点和保存策略，不能据此宣称测得物理电源轨断电。

FnKey `FnKey.Device.DisplayManager` 使用 EnumDisplaySettings/ChangeDisplaySettings。应用按已枚举模式只动态修改本会话显示状态，不写系统显示注册表。设备配置的手动切换由用户直接发起，自动刷新率另有独立开关。手动选择刷新率和翻转主屏前检查原厂占用，卡片提供共享退出确认。取消或超时恢复显示试用沿用原有监护。

Windows显示模式接口使用[ChangeDisplaySettingsExW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-changedisplaysettingsexw)；原厂电源控制的CM_Enable_DevNode/CM_Disable_DevNode调用以本机助手为依据，不安装或卸载设备。

## 独显

- 所有者：`gpu_power.rs`事务，`gpu_power/scope.rs`串行预检、执行与本次恢复；`gpu_power/operation.rs`原厂步骤与补偿；`hal/gpu_device.rs`SetupAPI/CM传输，`gpu_power/worker.rs`有界工作入口。LAN与独显的保留授权传输统一由`hal/authorization/`拥有。
- 扩展能力页page7版本1.0 byte19 bit6开放；未知版本拒绝写入。SetupAPI只接受上述原厂控制节点，忽略已经消失的历史节点；存在多个可操作匹配节点时拒绝绑定全局固件开关。问题码22表示停用，0表示正常，其他故障不按普通开关处理。
- 预览携带完整设备事实，执行前重新读取比对。存在任何活动 NVIDIA 显示输出，或无法确认其他 PCI 显示输出时，不允许关断。这样不依赖显示设备字符串总能返回完整实例 ID。
- ShellExecuteEx `runas`只启动同一程序的`--oem-gpu-power`入口；当前唯一参数为严格编码的会话绑定及请求摘要，旧六参数一次性入口删除。请求冻结完整设备前态和两个目标布尔值，16KiB有界读取，临时目录绑定本次随机标识。子进程在Tauri和硬件初始化前保留控制权、检查权限并通知就绪；得到执行许可后才加载DCHU和枚举设备，再核对完整事实和显示输出。
- UAC在后台且不持HAL锁；独显领域互斥覆盖授权、二次预检及收尾。授权后设备、刷新率试用或软件风扇互斥变化会取消，未许可不访问设备。同一进程保留到明确结束，执行、回读、本次补偿、取消和父进程退出恢复使用共享阶段/序号协议，具体原因有界落盘；补偿不重复弹UAC。
- 快照同时保留节点状态与page1 offset5自动关断策略，开启禁止自动关断，关闭允许自动关断。保存策略写后回读，部分失败按本次前态补偿并保留原混合组合；原实例移除时拒绝替换，补偿到关闭状态也遵守活动输出约束。
- 固件补偿失败时保留未确认状态，即使节点/策略读数已回到前态，也须重放原厂恢复命令后才结束本次恢复；原厂供电模式的节点恢复请求同样重放，不将两个标志相等当成固件命令已恢复。普通无变化应用仍零输出且无需授权。
- GPU开关、连接状态同步与显示写入共用HAL控制锁；刷新率试用期间拒绝独显UAC，关闭前要求退出软件风扇曲线。切换前释放NVAPI/NVML并暂停重连，完成后按实际节点状态恢复；回读无法确认则保持暂停。启动先核对原厂状态，再启动GPU采样。暂停保留频率偏移基线，CPU与EC读数继续显示。保留会话的后续补偿只接受本次目标或已回到前态的节点，外部混合策略变化拒绝覆盖；恢复关断仍检查活动输出。
- 不复制原助手隐藏全部NVIDIA设备弹出入口的注册表修改；它不是电源操作所需协议，也不具有原始值恢复语义。MUX/混合模式切换另属独立功能。

## 独显完整档案

`gpuPower`严格保存原厂节点ID、显示名称及`values.enabled/automaticPowerOff`，捕获只读取当前事实，节点关闭时不捕获不可读取的GPU偏移。手动确认绑定完整当前设备及软件风扇事实，旧设备、旧预览或文件变化拒绝执行；关闭目标不能同时包含GPU偏移或软件曲线目标。

显示整组试用须先保留；随后锁外准备独显授权，再全域预检。需要开启时先执行独显前置步骤，再读取档案所需驱动范围和温度；这些复核失败恢复独显，不继续CPU或其他设置。关闭前释放软件曲线，失败恢复节点后再恢复可读取的原始偏移及原曲线。已开启节点的偏移以实际切换前快照为准，授权期间变化不会被旧快照覆盖。单项与档案复用同一授权Scope。

最终节点/策略和显示复核先于映射记录提交及响应会话激活。全部目标已确认但授权收尾失败，保留目标并单独报告；不把收尾问题当作写入失败，只回退部分显示。配置图形只展示开关与数值，不表示物理电源轨已断电。

`gpu_power/mode`拥有原厂模式的节点动作、阶段和快照，供电模块只组装六条件；明确选择的省电和DCMode唤醒具有不同关断资格，均保留自动关断偏好。手动和热键完整入口已接入同一公共Plan，节点与原始频率共享HAL模式初始快照；完整档案共用准备、模式及显式节点最终目标的阶段图，启动和自动规则核对完整授权；软件测试不等于物理验收。

授权Scope已支持1–3个冻结节点阶段，前态必须精确承接上一目标。整个序列使用同一授权工作进程与控制权租约，当前单项和档案单阶段也用Sequence文件；旧的单Request文件不接受。每段开始重新核对同一文件，只在明确许可后创建对应设备任务。取消、进程退出、后续失败或提前提交部分阶段时统一逆序恢复，收集全部错误并保留原会话重试；完整执行后的普通收尾错误仍与目标应用结果分开。两次执行之间强杀和第三阶段写入中强杀已通过私有文件进程测试，未操作真实节点。

## 刷新率与主屏方向

- 所有者：`display.rs` 预览与试用状态，`display/guardian/` 本次试用的独立恢复协议；`hal/display.rs` 唯一调用 Windows GDI 显示模式 API。
- 仅活动非镜像显示设备；候选频率保留当前分辨率、位深、方向和显示标志。目标必须出现在驱动枚举中，先 CDS_TEST，再动态设置，成功后按完整事实回读。
- 应用绑定设备路径、设备身份、当前模式；旧预览拒绝。本次前态在目标写入之前保存，失败尝试恢复本次操作前模式，错误保留供重试。
- 切换前启动同一可执行文件的独立显示监护入口；通过继承管道传递完整恢复目标，READY/ARM 两步确认后才写入。子进程保留控制权租约，恢复失败每300ms重试，恢复完成前不能接管另一控制者。
- 切换后进入15秒试用；父子进程均用单调时钟。保留操作绑定实际试用目标，子进程在期限内回读一致后确认并退出；超时、父进程退出或管道断开均恢复本次前态。主进程每500ms检查子进程状态，子进程提前退出则执行补偿；页面仅接收 `remainingMs`，不依赖系统时间推算期限。
- 全局自动试用提示通过 `read_automatic_display_trial` 读取显示控制器中的试用状态。保留入口依据试用状态分派。屏幕面板读取当前显示与候选刷新率时，仅在取试用快照时持有显示状态锁。自动刷新率面板的只读预览在硬件控制锁之外读取，执行前在锁内重新核对。
- 监护恢复只比较设备身份及技术模式字段，驱动显示名称变化不当作恢复失败；设备替换仍拒绝。独立进程无法保证一个已阻塞的系统显示驱动调用能够返回，隔离验证不代表物理显示效果验收。
- FnKey的124调用Rotation180：当前方向0→2、2→0，方向1/3则交换宽高后→2。自研实现只对唯一活动主屏生成上述目标，频率、色深、位置及标志保持不变；先使用CDS_TEST，再由同一显示控制器和独立监护试用。原厂使用CDS_UPDATEREGISTRY，自研使用现有临时模式，不改持久系统显示设置。
- 124 单独授权并绑定主屏设备身份。事件定位显示模块并选中主屏，翻转目标由开关旁的说明弹窗展示，用户操作「翻转主屏」后开始 15 秒试用。主屏、显示前态或驱动能力变化拒绝旧请求。用户可保留或取消至本次前态。每次试用使用不同序号，旧保留和取消不能影响新试用。旋转不纳入刷新率档案。

### 原厂自动刷新率

`display/automatic/`拥有原厂模式与供电规则、字段事务及通知调度；`read_automatic_refresh / enable_automatic_refresh / restore_automatic_refresh`由`api/devices.ts`封装。唯一主屏的同几何候选按原厂排除低于40Hz及48Hz，设备、候选和原厂能力绑定预览；能力版本未知、供电通知与系统读数不一致或存在其他显示试用时不执行。普通客户与客户5按各自模式表处理，唤醒入口不自动切换。

启用由自动刷新率开关直接提交，按写前记录、回读和补偿维护 page1[27..29]，读取不自动初始化。自动目标共用显示域 15 秒独立监护，主窗口跨页保留或取消。停用时恢复本策略拥有的首次显示模式和原厂字段，外部变更不被旧记录覆盖。开关表示是否仍持有启用记录：已暂停或事务未完成时保持打开，关闭即执行同一恢复命令。原厂保存频率仅一字节，超过 255 Hz 会截断。选择恢复值时仅使用已枚举候选。

原厂部分机型在供电变化时先切电源模式，再使用另一套刷新率分支；模式Controller在同一HAL锁释放前交接实际上一模式、完成模式、供电和触发类型。刷新率Scheduler保留该交接，等待通知与系统读数一致且模式稳定，显示事务接受后才消费；新模式取代旧交接，旧确认不消费新目标。模式尚在排队、授权或执行时不抢先按普通启动/模式规则处理；模式失败不发送成功交接。DCMode供电/启动、DCMode唤醒及客户22按原厂触发分别处理，手动模式事件继续使用普通规则。20720/20724的原厂供电事件入口直接返回，这些其他AMD机型的电源模式控制未开放，软件明确标为未支持。32项领域检查不代表物理显示驱动已验收。

自动调度在没有到期工作时读取供电、电源模式、固件能力和原厂保存字段。真正执行前重新枚举并核对主屏、候选刷新率、供电及恢复记录。试用收尾可能修改原厂保存字段，下一轮重新读取后再处理后续事件。

### 档案显示试用

- `display/profile.rs`拥有严格的多屏目标及当前至目标预览；`profiles/application.rs`拥有一次档案应用的显示确认与继续执行状态。捕获保存身份、几何、位深、方向、位置、标志与频率；应用只改频率，旧身份/几何/候选/预览均拒绝。目标为空、重复、超32台、未知字段或过大输入不进入执行。
- 全域预检与文件/组合模式核对先于任何显示输出。存在变化时，全部屏幕共用一次15秒试用及独立恢复监护，保留前不执行其他档案设置；无变化只确认现状，不创建监护或恢复基线。单屏入口使用同一批次协议。
- 监护只接受`changes[]`与完整整组保留/恢复确认，移除旧单屏报文。输入输出按128KiB有界读取；每屏恢复独立尝试，已恢复或尚未切换的屏幕不重复写入。外部模式变化不覆盖，保留具体错误与恢复资格。
- 用户保留后，显示域保留本次前态，重新预检完整文件与设备；授权仍在HAL外等待，授权后再核对。目标设置失败恢复本次显示前态；根事务确认全部目标时保留显示，监听/授权收尾问题单独报告，不仅回退显示而保留其余已确认目标。确认/恢复期间其他显示、独显和MUX操作不能穿插。
- `Application`明确区分已执行步骤与待显示确认；全局确认只有一处，换页保留。启动档案需要保留时显示主窗口，继续、取消或超时后更新原启动结果；不将待确认或失败报告为全部完成。新读取不能覆盖动作结果，页面以原生剩余时长为准。

## 显卡模式（MUX／混合）

- `graphics_mode.rs`拥有模式选择，`graphics_mode/scope.rs`统一Scope→HAL锁顺序，`transaction.rs`唯一拥有持久选择及本次补偿，`graphics_mode/store.rs`拥有应用数据目录的`graphics-mode.json`唯一记录，版本2严格解码，不读取未知版本或字段。版本1记录只为初始恢复保存`initialMode`，读取时作废为无记录，由下一次写入替换。
- 本机CC3的cmd4/sub21报告当前模式和低四位候选掩码，sub22发送1集显、2独显、3混合或4动态选择；page7版本1.0 byte18 bit0开放。候选只来自本次固件报告。
- 本机DSDT的PK04 Case0x15读取当前启动信息，Case0x16通知SMM；getter不是待重启选择的可靠回读。因此发送成功只表示请求已接受，不要求立即报告目标，也不宣称显示路径已切换。
- 操作记录绑定Windows安装标识哈希及系统BootIdentifier，保留此前选择、目标、能力及prepared/accepted阶段。先原子保存意图再发送，失败尝试发送此前选择并保留恢复记录；应用重开只读记录，不自动重发。记录停在prepared（上次选择未确认）时允许直接重新选择：选择是绝对值，新选择本身即恢复，选中与当前报告相同的模式也会实际发送。
- 预览修订绑定当前模式、能力、记录和启动标识。只有启动标识改变且固件报告匹配目标才标记已确认；不匹配或中断均明确呈现，任何选择都在重启后核对。外部程序未公开的挂起选择无法捕获。
- 启动标识动态查询NtQuerySystemInformation class90并校验32字节结构，接口不可用即报错，不使用时间推算启动。原生查询本轮未执行。
- 选择受支持的模式按钮即发送切换请求；收到待重启结果后提示目标，由用户另行发起 Windows 重启。重启固定调用系统目录 shutdown.exe `/r /t 0`，保留正常关机流程。显示试用或软件风扇控制未结束时拒绝操作。

## PD档位与Deep S5

档案的powerDelivery目标显式区分legacyZeroBased、legacyOneBased和adapterV1，并保存当前适配器报告与候选；绑定失败在任何档案写入前拒绝。与单项PD使用同一Plan和首次基线，后续域失败可恢复本次前态；补偿仍检查当前适配器是否支持原等级。

- 来源为本机FnKey.Features及CC40.InsydeDriver/PageFlexiCharger。page7版本1.0 byte23 bit1声明PD，byte24 bit0声明Deep S5；未知能力版本拒绝执行，不使用整数回声推断能力。
- cmd4/sub54 bytes0/1为当前原始等级/旧最大等级；sub61 bytes0..1为大端版本，byte2为报告功率，bytes16..19为四个候选位图。版本0/max0使用原始0/1，max>0使用1..max；版本1.0按<60、60..89、90..99、>=100W选位图，仅开放其中声明的1..4级。未知版本或空候选报错，未报告功率保留未知。
- cmd4/sub55的byte1发送原始等级，界面显示编号偏移不进入协议。platform域拥有能力快照、修订、事务及首次基线；修订忽略对应版本未定义的保留字段，保留全部已定义事实。执行前重新捕获并拒绝旧预览，写后按完整目标回读。
- 首错补偿本次前态并保留首次基线；恢复时须保持编号语义且原等级仍属当前适配器候选，失败可重试。当前异常等级可展示但不能作为新操作基线，已有有效初态仍可恢复。电池校准记录未解除时，PD应用与恢复在调用传输之前拒绝。
