# Agent Note: 电压探测必须区分负偏移与普通可写性

Status: implemented

## 问题

uv-test 目前默认以当前值加一编码单位验证写入。从 0 写到正偏移不证明固件允许负偏移，不能回答用户重点关心的降压可行性。PL 报告同时打开两套 PawnIO 后端，也会绕过已修复的设备路径。

## 决定

- ccc-core 拥有负向一编码步进、写后回读、无论结果如何精确恢复及恢复回读的探测事务；当前已是最低编码时拒绝，不尝试更大的跨零电压跳变。
- CLI 仅显式 --execute 调用；只有实际负编码写入和恢复均通过才能报告负偏移写入已验证。正偏移降一步仍非负时明确保留未知结论。
- PL 报告复用已打开的桌面 PawnIO 传输，不增加设备打开、安装、服务重启或实际硬件执行。
- 交付复核发现 CLI 的 --execute 帮助仍写 +1，且脚本预期位置缺少 release 可执行文件：统一为负向一编码步进，并实际构建探测 CLI。PL 报告只保留目标所需的 0x610 与 0x606，删除附带 0xCE/0xE2 读取和误导性的 FEATURE_CONFIG 标签。
- 探测批固定使用已构建的 release 工具，不再悄悄改用 debug 文件。PowerShell 5.1 只解析源码校验语法和编码，不运行枚举、服务查询、MSR 或 DCHU 分支；验证 CLI 也只运行帮助入口。

## 风险

Mailbox 读查询本身也写 MSR 命令，当前不执行；负向一步虽小仍有稳定性影响，实际机器结论保持未验证。

## 备选方案

- 从任意正偏移跳到负一：可能造成较大电压变化，不采用。
- 正向步进成功就报告可降压：证据不成立，不采用。
- 只改输出文字：未验证真实负向写入事务，不采用。
