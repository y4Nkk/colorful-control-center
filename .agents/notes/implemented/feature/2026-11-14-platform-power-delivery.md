# Agent Note: 原厂PD档位与平台电源状态

Status: implemented

## 问题

原厂FnKey/CC40已有PD功率等级协议，但自研应用尚未接入。旧版等级0/1、旧版最大值编号和新版按当前适配器功率选择的四张位图不能混用；滑杆显示序号不等于固件编码。Deep S5仅找到读取链路，不能臆造对应写命令。

## 决定

- platform域拥有能力、事实快照、修订、PD事务和首次基线。按本机FnKey.Features与CC40.InsydeDriver/PageFlexiCharger核对的cmd4/sub54、55、61接入；能力仅来自page7 v1.0 byte23 bit1，不读整数回声。
- sub54 bytes0/1为当前原始等级/最大值；sub61 bytes0..1为大端版本、byte2为当前PD功率、16..19为四个功率区间位图。版本0/max0使用0/1，max>0使用1..max；版本1.0按<60、60..89、90..99、>=100W选择位图中已声明的1..4级，不填补位图空洞。未知版本、越界及不能恢复的当前等级拒绝写入。
- 请求绑定完整能力和当前事实；sub55 byte1发送原始等级，写后重新读完整事实。首错补偿本次原始等级；适配器变化时只在新候选仍允许原等级且编号语义不变时恢复，失败保留诊断及首次基线。校准接管时禁止PD改动。
- 修订只使用对应版本已定义的字段：v0忽略sub61未定义数据，v1.0忽略旧最大值及表的保留字节；不让填充噪声成为第二份能力来源。异常当前等级仍可读取，但不能作为新写入的恢复基线；已有有效基线允许在当前候选内恢复。原生读写均放入阻塞工作线程，不占用窗口线程。
- Deep S5能力来自page7 v1.0 byte24 bit0，cmd4/sub57 byte0只读0/1；当前没有可证明的写入口，界面表达状态，不提供虚构开关。继续核对USB/LAN、防尘和其余能力的真实调用链。
- 界面使用现有Surface/Select/ConfirmButton，当前与草稿分开，适配器功率没有报告时保留未知；级别不标成虚构的CPU瓦数。预览确认、错误与恢复独立，后台轮询不丢草稿。

## 影响与验证

新增3项类型化IPC、platform领域及控制台卡片，使用当前事实/目标左右布局，窄屏回流。15项原生内存检查通过，覆盖编号、全部功率分界、稀疏位图、能力/版本、旧预览、部分写入、回读不符、适配器切换、补偿失败与恢复重试。8项平台页面及平台/校准/充电/性能选项23项组合通过，覆盖确认、草稿、变化失效、读取错误、能力及360px布局。npm run build、cargo check --offline --workspace通过；未调用实际OEM或电源接口。

## 风险

回读证明固件等级，不证明适配器协商功率或实际性能；原厂后台可能改变当前选择。物理效果独立验收，不阻塞代码实施。

## 备选方案

- 把所有PD等级直接映射成瓦数或固定0..4滑杆：原厂没有该统一含义，拒绝。
- 将Deep S5的57号读取猜成58号写入：没有调用链证据，继续静态追踪。
