# Agent Note: 原厂键盘锁与交换设置

Status: implemented

## 问题

原厂 Control Center 的 Fn锁、Win锁及 Fn/Win交换尚未接入自研控制台。三个状态与其他键盘功能共用一个命令包，单字段写入不能清空其他字段。

## 决定

- 本机 CC3 Window1.SetKeyboardSetting、FnKey.Features.GetFnLockStatus/SetFnLockStatus/RestoreKeyboardSettings 为事实源；cmd4/sub24读取五个状态，sub25写入五个状态，保存值为page1 offset36..38。Fn锁/交换为1开启、2关闭，Win锁为2开启、1关闭；0表示不支持。
- keyboard 域拥有实时状态、保存快照、预览修订和失败补偿；UI只改草稿，确认才写入。请求只编辑已支持的前三项，保留第4/5项原值。
- 预览绑定实时与保存值；首次基线与本次前态分别保留。写后回读即时状态与保存值，首错停止后补偿；恢复时保留最新的其他键盘状态。未知值、能力变化和旧预览拒绝写入。
- 与既有 HAL 写锁、DCHU 双向包和类型化 IPC 共用入口，不引入键盘钩子或后台热键写入。

## 影响与验证

- 10项内存测试通过，覆盖全部编码、共享字段、旧预览、保存默认值保留、首份基线、保存失败补偿、回读不一致、能力变化与补偿失败重试。
- 2项实际构建页面隔离IPC检查通过，覆盖草稿、确认重置、错误保留与恢复；宽/窄面板截图已检查。开发服务器请求超时后使用构建产物的本地静态预览验证，不启动生产应用或访问硬件。
- npm run build、cargo check --offline --workspace 通过；聚焦测试仅使用内存提供者，不运行完整测试套件。

## 风险

不操作真实键盘或OEM DLL，固件实际效果仍待单独验收。此模块不宣称已实现 Flexikey 宏、OSD 或全部热键。

## 备选方案

- 用应用层拦截模拟Win锁：与原厂固件控制不同，拒绝。
- 拼接仅一项的sub25包：会覆盖共享状态，拒绝。
