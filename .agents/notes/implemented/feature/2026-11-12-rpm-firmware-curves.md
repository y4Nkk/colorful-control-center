# Agent Note: 接入原厂十级 RPM 固件曲线

Status: implemented

## 问题

原版 FnKey 的 Interface_FanTable 已完整实现十级 RPM 表。此前应用只支持 cmd14 两点曲线，遇到 page7 v1 [20] bit4 时主动禁用自定义。这是可通过静态协议实现的功能缺口，无需猜测原始 GPU EC 寄存器。

## 决定

- ccc-core 拥有 112 字节表及成对 256 字节包的编解码、十点校验与回读比较；DCHU HAL 增加唯一 SetDCHU_DataEx 传输，fanctl 按能力选择两点或 RPM 协议。
- 读命令 40/42 的首表从 0 开始，写命令 41/43 的首表从 16 开始，第二表都从 128 开始；RPM 为大端。保存原始完整表，修改仅涉及请求风扇，保留热保护及未修改伴随表。
- 新目标沿用原版温度下行阈值、按每风扇最大转速换算目标 RPM；升降速及其他固件参数从原始表保留，不虚构时间单位。新目标最低 20%，十个温度点均可调且递增，末级须达 100%（温度可低于 100°C）。原厂默认恢复使用其明确的固定默认表并结束于自动模式，普通请求不能绕过 20% 下限。
- 先全量预读与校验，再启动独立监护，写模式及表并回读；失败尝试精确回滚，保留恢复错误。基线与档案快照使用原始字节，避免百分比转换漂移。
- 图形编辑与数值输入共用草稿；RPM 纵轴明确表示最大转速百分比，沿用无网格、按语义展示的当前界面。性能档案捕获、校验、预览、执行及恢复同步接入。
- 档案数据与校验由 profiles/model.rs 拥有。两点与 RPM 字段互斥，新提交的曲线复用运行时校验。面板点选自定义、预设联动及只指定自定义档的档案均启用已读原表，保留原厂停转级。自定义档内的点位更新只写曲线表，失败只恢复触及的表。包含切档的事务也恢复即时档位和保存字段。OEM 模式的风扇恢复在原厂模式恢复之后执行。
- 风扇确认按钮只显示变更项数量，完整差异仍在旁边；草稿变化以 React key 重新建立确认状态，避免长串目标值及确认失效。

## 影响与验证

- ccc-core 的 6 项 RPM 字节测试通过；control-sim 的 10 项风扇域与 3 项档案契约测试通过，覆盖回读失败、第二对部分写入、保存失败、精确恢复及恢复错误可见。模拟调用生产实现，不初始化硬件。
- 两点界面 57 项与 RPM 界面 30 项隔离浏览器检查通过：十点拖动/数字同步、最低目标、确认撤销、草稿保留、专用命令、伴随风扇保留及 360–1440px 布局。结果位于本会话 control-verification 的 app-results.json / rpm-results.json；模拟数据未进入产品代码。
- npm run build、cargo check --workspace 通过；本地 NSIS 构建通过。不执行本机硬件读写、驱动安装、安装包运行或真实用户配置写入。完整桌面窗口与硬件响应仍需后续验收。

## 风险

模拟不能证明真实固件生效与物理散热；十级固件表不等同于原路线的任意点软件 EC 闭环。原厂 FnKey 和本应用并行控制仍可能覆盖彼此的设置，需要后续真机验收。

## 备选方案

- 永久禁用已明确的 RPM 能力：保留已知功能缺口，拒绝。
- 用 cmd14 或推测的 GPU 地址替代十级表：协议不同，拒绝。
- 覆盖原厂 XML 配置：超出授权数据边界，本应用使用自身的性能档案。
