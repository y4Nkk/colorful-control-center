# Agent Note: 活动麦克风静音与原厂热键

Status: implemented

## 问题

Pi实际FnKey.Form1.Arg001_GetEvent的38分支创建DgMic并对全部活动录音端点执行SetMicStateTo；DgMic使用ECapture/DeviceStateActive，AudioEndpointVolume通过Core Audio SetMute/GetMute。Features.SetCallMuteStatusToRegistry仅保存page1[41]，不是寄存器或音量控制命令。CallingVariations中的SetVolume/GetVolume声明没有在这条执行链被消费，不能据此宣称音量热键完成。

## 决定

- hal/audio只拥有Core Audio活动录音端点、名称及静音读写，使用工作区已锁定的windows 0.62.2生成接口，避免手写COM虚表。COM初始化与释放严格配对，身份字符串释放，不枚举播放端点、不录音。测试不创建原生COM对象。
- microphone唯一拥有活动端点集合、OEM保存偏好、当前/目标预览与本会话首次基线。全部静音/全部取消静音需要确认；混合状态明确展示。每个端点写后回读，部分失败仅补偿尝试字段，补偿失败保留可重试记录，恢复保留初始混合状态与原始OEM字节。
- 单项、热键及完整档案使用同一Scope/Plan及HAL控制锁。目标绑定完整端点ID集合，旧预览或设备集合变化零写；不自动接管新接入的设备。原厂控制者存在时拒绝写入，不结束其进程。读取不修改偏好或恢复设置。
- 恢复只核对初始设备仍然存在，额外新设备保持当前状态；初始设备断开或被替换时保留记录并拒绝旧恢复。首次基线未结束且集合变化时不提供新的热键授权；明确恢复成功后释放旧基线，再允许对新集合重新确认。
- 38号热键独立授权，混合状态的下一次操作明确为全部静音；完全静音时取消静音。UI和OSD报告实际端点状态，原厂偏好不能冒充系统回读。初始化不执行原厂RestoreCallMuteStatus的隐式写入。
- 领域IPC、控制台左右模块、完整档案捕获/导入导出/手动/启动及预览恢复已接通；依赖特性、锁文件、边界注册和事实文档同次更新。完整契约见docs/microphone-contract.md。拆分设备执行阶段与除尘预检，保持各函数职责和80行限制。

## 影响与验证

9项领域、10项档案及独立授权检查共20项聚焦原生检查通过；覆盖混合端点、空集合、重复/非法ID、逐端点及保存失败、成功但无效果的回读、补偿重试、未知原始偏好、外部变化、共用首次基线及新增设备恢复。档案过滤277项通过（含11项显示领域复用，2项真实设备忽略）、热键10项及核心事件5项通过。

147项相关模拟页面组合通过，随后14项直接页面检查覆盖最新状态用语、读错撤销、确认/恢复、热键范围、捕获/导出/导入、显示试用、启动选择及深浅窄屏；截图已目检。npm build、workspace cargo check、隔离宿主离线编译、12项隔离软件进程、26项控件及104个Rust/48个前端源文件500/80限制通过。宿主补齐明确的Variant特性及源模块路径，避免依赖Tauri特性合并；没有新增兼容路径。

只使用内存传输、私有文件和模拟IPC，没有调用真实音频设备、DCHU、日志或热键，也没有录音；实际音频驱动、插拔及原厂后台共存仍未验收。初始基线属于本次应用会话，重开不隐式应用原厂偏好。

## 备选方案

- 只修改原厂保存字节：不能证明系统端点已静音，使用实际Core Audio读写及回读。
- 只控制默认麦克风：原厂遍历全部活动录音端点，按完整集合处理。
- 把混合状态压成一个保存开关：丢失可恢复的逐设备事实，档案和基线保留逐端点状态。
- 手写COM虚表或复用音量DLL的未消费声明：使用已锁定windows生成接口，API边界以实际调用链为准。
