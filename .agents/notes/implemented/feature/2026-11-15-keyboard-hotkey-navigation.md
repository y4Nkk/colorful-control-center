# Agent Note: 原厂键盘灯快捷入口

Status: implemented

## 问题

Pi会话FnKey 7.19.5.0的Arg001事件131只在原厂识别的键盘类型1、2、3、6、22、23、38上打开或导航到键盘灯界面；自研应用已实现键盘灯，但尚未处理该入口。原厂的单独键盘窗口与本应用控制台内嵌模块不同，不能据此关闭整个自研主窗口。

## 实现

- 为131增加独立热键授权；预览绑定已识别的原厂键盘类型，不继承唤起控制台、灯光修改或其他热键权限。只请求显示和定位自研键盘模块，不修改灯光、硬件或原厂程序状态。
- 后端登记带递增标识的待处理导航请求并通知主窗口，主窗口显示和聚焦失败保留诊断。应用根负责切换控制台与请求消费，控制台挂载后滚动到设备区域首部；重复请求逐次生效，不强制隐藏主窗口。
- 借用既有热键状态订阅与首次读取，先订阅后读取以避免初始化竞态；请求消费以标识校验，旧确认不能清除新请求。重载或前端暂不可用时后端保留请求，消费失败留有明确错误，不建立第二个导航事实所有者。

## 验证范围

覆盖原厂类型白名单、独立授权及变化、事件131/低字节解码、重复请求及旧消费竞争、启动订阅竞态、从其他页面进入控制台和已有草稿保留。仅使用注入状态与模拟页面，不读取真实键盘、不调用系统窗口或原厂进程。

## 风险

原厂键盘独立窗口有关闭行为；自研控制台采用嵌入模块，快捷键定位不能宣称完全复制该窗口的关闭动画或生命周期。主窗口不可显示时应保留请求和错误。

## 备选方案

- 将131并入已有唤起控制台授权：会扩大已确认的导航行为，拒绝。
- 连按时隐藏整个主窗口：原厂仅关闭键盘界面，没有证据支持隐藏全部控制台，拒绝。

## 决定

事件131独立授权并绑定原厂型号白名单，使用后端唯一待处理状态和递增序号；窗口显示成功后应用根切到控制台，工作区定位设备区域并确认消费。旧确认不得覆盖新请求，失败保留待处理状态和诊断。

## 影响与验证

3项授权与状态、2项灯光判型、15项核心事件和12项模拟页面通过，覆盖首次读取、晚到事件、连续请求、失败重试、切页与草稿保留。前端构建、控件和模拟宿主检查通过；没有读取真实键盘、触发物理热键或打开原生窗口。现有阶段包不包含本功能。

2026-11-15屏幕旋转事件接入后，键盘与显示共用同一导航请求、序号及确认命令；旧键盘专用状态与IPC路径已移除。两类请求竞争仍由较新序号决定，具体约束见原厂屏幕旋转笔记。
