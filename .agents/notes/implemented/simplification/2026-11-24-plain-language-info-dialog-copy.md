# Agent Note: 信息弹窗文案改为用户视角的说明

Status: implemented

## 问题

信息图标及其文字入口打开的说明弹窗多数从实现角度描述功能，用户难以判断一项设置会带来什么效果、代价和限制。2026-11-24 用户先要求把「性能选项说明与诊断」改成用户看得懂的文案，随后要求覆盖所有模块。排查中还发现三处指向已删除入口的过期说明。

## 决定

1. 范围包括 `DetailsDialog` 的信息图标入口，以及概览和性能卡片上的「规格」「详情」「说明与诊断」入口，共 30 类说明弹窗。模式循环里的「风扇与系统设置的变化」按共享入口计一次。弹窗中显示的事实组件沿用同一套术语。
2. 写法约定，供后续弹窗沿用：
   - 先说这项设置做什么，紧跟用户能感知的效果或代价（噪音更大、温度更高、可能中断程序），再写限制。
   - 不用实现层的词：固件→电脑，策略→设置或方案，互斥→不能同时开启，回读→重新读取，缓存→电脑记录的值，候选→可选，节点→独显电源，会话→本次接管。
   - 说明里解释锁频、占空比等术语，沿用界面现有的设置名称。电源模式循环的说明入口改为「电源模式循环会改动什么」，结束屏幕接管的确认文案写明会停止监听。
   - 按界面上的名称指代别处入口（「性能选项」「预设模式」「性能与散热 → GPU 频率」），提到入口前先确认它仍然存在。
   - 说明功能能改变的参数。温度、噪音与性能的实际变化用条件和可能性表述。
3. 页面与弹窗共用的事实取值函数（`energyValue`、`gpuSkipReason`、`GpuModeFacts` 的说明行）一并改写，档案预览和供电模式恢复预览里的同一概念不再出现第二种说法。紧凑取值（`gpuLock`、`gpuTarget`、`ASPM_NAMES`、`PLAN_NAMES`）保持原样。
4. 修正过期指引：「性能选项说明」末行指向的预设模式恢复入口自 v1.0.2（`db8852d`）起不存在，改为经 `fan_target` 核对的行为——开启或关闭 Turbo 风扇后风扇档位切到「自动」，且只在选项立即生效的模式显示；「电源模式循环」预览里的「初始状态可在『性能与散热』恢复」随独显电源迁到设备配置、恢复按钮于 2026-11-24 删除而失效，删除该句；热键「飞行模式按键」规则里指向同一恢复入口的半句删除。
5. UI 检查的断言随文案更新。受影响的热键用例按实际路径操作，从「配置热键」选择范围，从「详情」进入热键诊断。需要检查嵌套说明时，先打开对应弹窗。
6. 飞行模式和软件偏好诊断提示如何重新读取，原始错误仍可用于定位问题。内存说明区分原厂参考频率与内存条的配置速率。

## 影响与验证

- 改动集中在前端文案和关联的 UI 检查。动态错误详情继续使用对应领域返回的诊断。
- `npm run build` 和 `cargo check` 均通过。Playwright 使用前端构建产物和模拟设备数据检查 30 类弹窗，覆盖浅色、深色和 390px 窄窗。共验证 48 项相关 UI 用例，包含两项修正定位后的复跑。

## 备选方案

- 只改「性能选项」一个弹窗：用户明确要求覆盖所有模块。
- 连弹窗标题和按钮名一起改：会改动无障碍名称和十余份检查脚本的定位，收益小于风险，未采用。
- 在 `parameterDescriptions.ts` 之外另建一层「用户文案」映射：同一术语两处定义，违背单一归属，未采用。
