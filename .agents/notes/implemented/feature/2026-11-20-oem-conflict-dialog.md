# Agent Note: 原厂控制进程冲突确认

Status: implemented

## 问题

自动刷新率、输入设备、热键、自动策略与档案可能因原厂进程占用而无法操作。各模块显示原因，预设此前独立提供关闭确认。触摸板和麦克风卡片把具体禁用原因放在详情中。

## 决定

应用根统一托管关闭确认。已有冲突状态在对应模块提供入口，交互写入被互斥拦截时也可直接打开确认。后台检查更新模块状态。

复用 `hal/oem_owner` 对唯一原厂 FnKey 的 Windows 包、程序映像、会话、PID、创建时间和窗口检查。确认后沿用正常退出及有界等待。其他进程或无法核验的身份由用户手动退出。校准继续单独检查电池原厂控制程序。

预设保留绑定进程身份和模式修订的「关闭并切换」。通用确认成功后刷新模块并保留原有执行、预览和恢复入口，避免重放发生部分写入的操作。

补齐读取阶段的原厂占用提示。自动刷新率、供电模式、飞行模式和预设恢复在有可用目标时展示实时阻止原因和「关闭原厂软件」按钮，写入时继续重查。屏幕手动切换、PD 档位和性能选项复用现有原厂互斥检查。显示试用和档案试用中的显式操作收到冲突时也提交同一确认。取消试用和暂停监听仍可在原厂占用期间执行。

## 影响与验证

- 当前系统只读枚举识别了 ELAN I²C 触摸板，HKCU 系统触摸板状态为 `Enabled=1`，同时 FnKey.exe 正在运行。麦克风截图中已有三个活动端点，控制器先检查原厂占用，再检查端点集合是否与首次基线一致。触摸板和麦克风卡片直接呈现各自读到的阻止原因。
- `pnputil` 未发现飞行模式写入所需的原厂设备接口 `6e59105f-34e7-4b3c-b676-c5c8233c008d`。截图所示 `CONFIGRET=0x0, size=1` 是成功返回空设备列表。卡片报告缺少接口，写入仍要求系统提供该接口。
- 工作区与独立源码快照通过前端构建。独立端口的无头模拟 IPC 共覆盖 68 项不同用例，包括 6 项共享冲突确认。Rust 工作区检查、1 项 IPC 窗口边界测试、6 项飞行模式事务测试和控件约束检查通过。真机检查限于只读查询，进程退出、刷新率试用及硬件写入由隔离夹具验证。
- 补齐入口后，工作区和隔离快照通过前端构建。80 项相关无头模拟 IPC 检查通过，覆盖跨卡片刷新、供电占用时暂停、自动刷新率及档案试用的继续与取消。7 项飞行模式事务测试通过，新增检查确认占用时仍提供实际状态且读取阶段没有写入。

## 备选方案

- 各域单独处理进程退出。共用进程核验和确认可统一处理替换、其他进程占用及超时结果。
- 所有域关闭后自动重试。失败结果可能带有部分写入或待恢复状态，重新预览保留用户确认与目标校验。
