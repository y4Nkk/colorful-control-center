# Agent Note: 接管后的控制链路补全与写入恢复

Status: implemented

## 问题

原会话把 Phase 0–4 标记为完成，但 GPU 偏移、软件闭环和看门狗未交付，温度与写入尚未完成真机验收。PawnIO 的 UTF-16 设备路径含内部零字符，设备打不开不能证明驱动僵死；MSR 回读掩码错误，DCHU 读失败被当作零值，缺失风扇仍参与曲线校验，性能档案失败后继续写入。

## 决定

2026-11-12 继续核对 `cc-research/decomp/fanset/FanSpeedSetting/FAN.cs`：`Write_WMI14` 的斜率为大端，`SetFanInfo` 的 page4 斜率为小端，二者不能共用编码；`GetTDP()` 固定返回 `"0"`，本版本 `CalCPUTemp` 返回原始温度，删除误套的 65W 换算。以独立固定字节用例验证，并补齐离线 EC 差异比对工具与指引。探测 CLI 的锁位结论只能描述锁位，不能宣称实际写入可用。

Pi 会话 `9b0d7323-5294-4777-8be6-bbeabdcfb6a8` 的后续反编译目录 `dec/fnkeynet/FnKey.exe_dec/FnKey/Features.cs::SetPowerMode` 已明确电源模式写入路径为 cmd121/sub25，性能模式合并 page1[32] DTT 与 page4[8] Turbo 标志。原“原生命令未知”的结论失效。按 page7 能力开放 0–3 模式，预览确认、字段回读、失败补偿和初始恢复统一接入控制台。代码及模拟验证不等同于机器生效验证。

继续对照 OEM Math.Round：统一风扇强度转换的运算顺序及中点取偶数，修正 30%/50% 等边界；模式按实际能力开放，十级 RPM 固件禁止误用 cmd14。探测批默认只读，删除自动提权、服务重启和驱动安装；真实电压测试必须显式选择，DCHU CLI 读取失败直接报错，不再输出伪造的可写结论。

1. 修复现有硬件读写、协议编码与恢复语义，再补全原计划已有的控制功能；不改动并行的窗口外观工作。
2. GPU 偏移经独立 NVAPI HAL、类型化命令与控制台接入，使用已核对的结构布局和函数 ID。写入前展示当前/目标，后端检查驱动能力与范围，回读失败恢复原偏移；恢复也回读，档案快照保持原始 kHz。
3. MSR 协议由 ccc-core 唯一拥有，桌面与探测 CLI 复用。RAPL 单位从 0x606 读取；OC Mailbox 检查 busy/返回状态，写失败尝试恢复并保留恢复错误。测试使用内存模拟，禁止为验证而操作真机。
4. DCHU 读路径返回错误，禁止用失败读取的零值覆盖设置。只为存在且能力确认的风扇构造写入包，校验数值有限性、温度与风扇强度范围。任一写入阶段失败都尝试恢复自动风扇。
5. 补全独立进程风扇看门狗：启动握手通过后才能进入手动控制；进程死亡、心跳超时、过温和传感器失效恢复自动。软件自由曲线只使用已有可信协议，不猜测寄存器或 OEM 命令；未确认的硬件能力明确报告不可用。
6. 性能档案在所有设置预检通过后顺序应用，失败即停止并恢复；不再把持久化意图描述为已确认的硬件生效。托盘/开机应用复用相同的确认与执行入口。
7. 完成后以实际证据修订 README、契约和验收清单。构建、纯逻辑测试、模拟后端检查与真机验收分别报告，不再用全绿阶段表掩盖未验证项。

## 影响

硬件写入的错误会更早暴露，缺失通道与未知能力不会变成伪造的成功。代码和模拟验证可以自主完成；未经验证的 EC/GPU/键盘能力不能通过猜测命令来宣布完成。此轮不安装驱动、不提权、不重启、不执行硬件写入探测、不提交或推送。

实现包含设置触发字节恢复、看门狗独立心跳与父进程补偿、GPU 全局控制锁和键盘灯静态编码。核心及生产模块模拟测试、前端构建与工作区检查已执行。原生测试此前的 0xc0000139 已由统一 Common Controls v6 清单修复，原生聚焦测试与独立进程验证见 `2026-11-12-windows-native-test-loading.md`。尚未真机确认参数生效或未知 EC 通道。
