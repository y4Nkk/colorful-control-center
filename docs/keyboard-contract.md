# 键盘灯光契约（cmd103 分区 RGB / cmd39 白光）

## 原厂系统事件与面板维护

FnKey `Arg001_GetEvent` 的132只打开系统目录中的 `control.exe /name Microsoft.Recovery`，授权绑定程序摘要；72独立请求关机，192依据当前计划的两种供电合盖设置执行。三个范围互不继承低电量许可，均默认关闭。192绑定活动计划、AC/DC动作和现代待机能力，未知供电拒绝请求。现代待机的睡眠动作发送关闭屏幕，其他平台请求睡眠；休眠与关机沿用计划。系统动作由HAL唯一实现，现有令牌权限在调用后恢复；软件策略恢复不撤销已发送的关机、睡眠或Windows恢复窗口。

240/241仅记录原厂开始／停止充电通知，不改变充电策略，也不推导实际电池充电状态。通知能力标识为 `oem-state-notifications-2`，旧确认不得隐式涵盖新增反馈。

本机 `powerlife.dll` 的ordinal31（RVA0x4690）已静态核对：参数2调用 `ExitWindowsEx(5,0)`，包含强制结束标志。自研入口明确请求Windows正常关机及断电，不带FORCE，保留应用结束协商；不复制原厂跳过未保存程序确认的行为。现有令牌的关机权限在调用后恢复，失败保留Win32错误。标志语义见[Microsoft ExitWindowsEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-exitwindowsex)，原生DLL未被执行。

133飞行模式由 `airplane::Controller` 唯一拥有手动与热键的事务。系统事实来自 `HKLM/SYSTEM/CurrentControlSet/Control/RadioManagement/SystemRadioState` 默认REG_DWORD，仅接受0/1；缺失或读取失败保留未知。原厂DLL的专属接口为 `6e59105f-34e7-4b3c-b676-c5c8233c008d`，IOCTL `0x00322804`输入1字节绝对状态，无输出。Windows成功枚举空列表时报告缺少该设备接口，并保持开关不可用。先发送DCHU121/sub26，再调用设备接口，回读系统报告；不以单独无线网卡开关替代。源设备、预览和许可逐段复核，本次前态在第一笔输出前保存，部分失败补偿固件与系统两条通道。状态回读不持有HAL锁，取消后仍完成本次前态补偿。软件不保存首次基线。

84分为两条独立的一次性请求：OLED签名沿用面板清单所有者，发送DCHU94=1；NVSR采用 `NvsrPanelCheck` 的11个唯一EDID签名，并核对GetWMI84为非负且不等于1。未解析面板不推断可用。原厂 `cc30wk 0x0025 2`对应一次AuxSwitch请求，自研不启动助手或加载其DLL：在专用STA内创建CUI类 `7160a13d-73da-4cea-95b9-37356478588a`、查询接口 `f932c038-6484-45ca-8fa1-7c8c279f7aee`，slot12枚举固定DISPLAY1，slot44发送GUID `bfb9816c-aeb0-434b-99f3-0f94e6bebf0d`的148字节包，前四DWORD为UID/8/132/0x721，后132字节全零。HRESULT按原厂语义判定，未定义输出仅保留日志，不猜测状态码。接管激活后执行适用NVSR启动修复，84事件还独立唤醒OLED；取消与来源变化停止后续请求。恢复只撤销软件接管，不虚构一次性修复的反向命令。

65–71是其他AMD模具的热/功率联动，93为空分支，301–304被唯一调用者的低8位解码排除；这些分支不在本机Intel目标上扩展为硬件操作。协议证据来自本机FnKey 7.19.5.0及其安装包内的原生DLL静态分析，未执行真实系统动作、无线控制、CUI请求或固件写入。

本文拥有灯光协议与事务行为。主要事实源是本机反编译的 LedKeyboardSetting 6.26：
`dec/kbled/CC/RGBKB.cs`、`WhiteKB.cs`、`BaseKB.cs`、`InsydeAcpiProt.cs`。
CC40 7.19 仅作逐项交叉审查，不能视为完全相同版本。实现位于 `src-tauri/src/lighting/`；
传输 ABI 见 [oem-dchu-contract.md](oem-dchu-contract.md)。本轮只读源文件和运行隔离模拟，不执行硬件调试。

## 1. 判型与适用范围

cmd70 触发 Init_WMI 后读 cmd13 包 byte15，活动类型优先；失败可用 OEM page2 offset4 缓存，
再考虑 live 的无背光值。cmd16 与 CPU 频率双占位，不用来判型。未知值不预选家族；
未知类型只提供诊断与重新读取，识别完成后才开放；已判明的家族不得跨写。

| 1 | White | cmd39 亮度 |

| 38 | ZoneRgb | 活跃FnKey.RGBKB：亮度1–4为47/102/155/212，其他值47；颜色使用普通蓝色比例，关闭仍由E0开关控制 |

## 2. cmd103 立即命令

全部为 `SetDCHU_Data(103, word.to_le_bytes(), 4)`。

| 用途 | 编码 |
|---|---|
| 左 / 中 / 右颜色 | zone=F0/F1/F2；word=`zone<<24 | B'<<16 | R<<8 | G`，LE=[G,R,B',zone] |
| 普通蓝色 B' | .NET 默认偶数舍入 `40/51 × B`，纯蓝 255→200 |
| 亮度 | `0xF4000000 | raw`；级别 0..4 对应 0/47/95/143/191 |
| 总开关与区域开关 | `0xE0000000 | base | bit12 | logo<<13 | TP<<15 | left<<16 | mid<<17 | right<<18` |
| 关闭 | 亮度写 0，开关写 `0xE0000007`，不携带分区使能位 |

base 通常为 7；TP 已开且颜色非黑时为 1。Logo/TP 开关从本次保存快照组合；已声明普通LightBar的型号使用page2[104]作为bit15，其他型号保留TP分支。Logo/灯条编辑归§9，不由键盘模式请求覆盖；TP颜色保留原值。

| 保存模式 | 名称 | 模式命令 / 颜色命令 |
|---|---|---|
| 0 | 随机 | 0x70000000 |
| 1 | 分区 | 分别写三个区域颜色 |
| 2 | 呼吸 | 三区颜色，再写 0x1002A000 |
| 3 | 循环 | 0x33010000 |
| 4 | 波浪 | 0xB0000000 |
| 5 | 舞动 | 0x80000000 |
| 6 | 节奏 | 0x90000000 |
| 7 | 闪烁 | 0xA0000000 |
| 8 | 同色 | 三个区域均写 AllColor，保留独立区域开关 |

顺序遵循 RGBKB.Init/SetMode：亮度 → 相应颜色与灯效 → 开关掩码。动态颜色由固件产生，
UI 不提供无效颜色输入。三区颜色和开关草稿始终独立保留，切换模式不丢弃。

## 3. 白光

cmd39，4B LE `[level,0,0,0]`，级别 0..5。恢复总开关为关闭的基线时，立即命令写 0，

## 4. 保存布局与当前 IPC

读取 page2[32..108]，共 76 字节；offset32=模式，35=亮度，80=总开关，81..83=AllColor；
84/88/92 是三区开关，各自随后三个字节是 RGB。96..99=TP，100..103=Logo，104..107=灯条。

TP独立颜色在当前静态IL中的活动范围：RGBKB.set_TP只由FirstRun/ReadAllReg调用，WriteAcpiTPColor仅由属性和WriteAllReg调用并保存page2偏移97起的三字节；能力SupportTpColor没有指令引用。SetColor的活动调用为SetCustomColor/SetBreathMode/SetAllColor，已确认选择器为F0/F1/F2/F3/F6，不据此猜测TP选择器。现有总开关协议保留TP伴随字段，不把共享颜色保存视为独立即时控制；这不是其他组件或硬件能力的全局否定。tools/research/audit-oem-il.py绑定原程序集摘要并检查上述边界。
33/34及其他未涉及字段不由键盘模式请求改写。闲置定时36..39、开机覆盖7与外围100..107归§9，逐键参数归§7；各域独立恢复所属字段。

`apply_keyboard_lighting` 只接受一个 `request`：

- `family=zoneRgb`：brightness、effect（九种字符串枚举）、allColor、固定三个 zones（enabled/color）。
- `family=white`：brightness。

后端拒绝未知字段、旧 color 参数、未知模式和非三个分区。读侧快照提供 rawMode、effect
（未知时 null）、enabled、brightnessLevel、allColor、zones。判型/不可用原因/警告与首次基线继续返回。

## 5. 事务与恢复

首次写入前捕获完整保存块和所用家族/类型；本次写入前另取快照。两者都先验证亮度与模式可恢复，
未知模式拒绝写入，不能静默钳制或猜成静态。家族和颜色编码与首次状态不一致时拒绝。

所有序列在 Hal 写锁下执行：立即命令 → settings::apply 字段事务（预读、写、回读、失败恢复）。
任一步失败，独立尝试本次灯效/亮度/颜色/开关回放与所属保存字段恢复；一条失败不阻止另一条。成功明确报告已恢复，恢复失败进入rollbackError并保留首次基线，档案可继续尝试本次检查点恢复。

用户恢复读取当前共享保存块，只合并首次灯效所属字段再回放，保存恢复独立尝试；三区仅32、35、80..95，白光仅35、80。删除整块page2回写，保留其他控制者的新睡眠、逐键和外围灯值。键盘类型或灯条能力变化拒绝旧恢复；基线保留可重试，关闭但保留亮度的基线不会因恢复而点亮。

## 7. 逐键 RGB

事实源为本机 kbled 6.26的`PerkeyKB/KBModule/InsydeAcpiProt/Page_LED_Device`、解码后的页面BAML，以及已安装FnKeyPack 7.19.5中的`Device_HID/perkey/perkeyhook.exe`、`gamefeet.dll`、`Windowshook.dll`与`HID_Device.dll`静态反编译。原生接口匹配HID usage=0xCC、usagePage=0xFF89、ProductID=0x8910；本应用直接实现16字节Feature Report，不复制或加载原厂DLL，不运行原厂初始化或助手。需要唯一匹配设备，发送失败保留Windows错误。

- 报告：`[0xCC, cmd, data0, data1, data2, data3, 0…]`，共16字节；SetLEDStatus 入口 RVA0x1E40、选择器 RVA0x1AD4，均已静态核对。
- 清空/静态：`[0,12,0,0,0]` 后等待100ms；逐键 `[1,(row<<5)|col,R,G,B]`。每排20位置，共6排120位置；黑色显式输出，不依赖旧灯色。
- 亮度：`[9,levelRaw,speed,0,0]`，级别0..4映射0/2/4/6/10；总开关为0时按原厂发送`[9,0,0,0,0]`，保存亮度和速度仍保留。BAML的KbSpeedSlider Maximum=2，实际速度编码0..2，界面显示1..3档。
- 颜色矩阵384字节，起始绝对地址640；每个颜色索引为 `row*64 + col*3 + col/5`，行内填充保留。HAL 逐页读取 page2[128..256]、page3[0..256]，不跨越单页边界。
- 设置所有权为page2[32..36]模式/静态/速度/亮度、[41..48]渐灭/Fn、[48..80]动态参数、[80]总开关及矩阵。保存逐段回读、首错停止；补偿独立尝试即时回放和全部所属保存区域。闲置关灯[36..40]、相邻未归属字节[40]及区域/TP/Logo/灯条[81..108]不在逐键恢复写集内，保留其他控制者的新值。
- 首次快照保留整个设置块和矩阵；恢复0..13原始模式、方向、颜色、静态矩阵与开关。模式12按静态矩阵回放，13为FnKey新增渐灭。原厂未实际使用的参数仍保留，不虚构灯效相位回读。
- MCU查询发送`[CC,17,selector,0…]`，selector1取得语言/窄边框/三列标志，16取得新灯效位；HID_Device响应有效载荷位于有界16B报告的bytes2..5。不会调用带ClearColor副作用的GetMcuVersion。
- 当前请求只有`{expectedRevision, values:{enabled,brightness,speed,pattern}}`。pattern为严格标签联合：static、wave、breath、blink、random、scan、snake、ripple、fn、fade。静态必须120色；动态仅提供有效参数。旧brightness/colors顶层请求、未知字段、速度/方向越界及旧预览均拒绝。revision绑定HID身份、能力、布局事实及保存块；恢复另外核对原设备和MCU能力。

### 7.1 动态模式与事件

旧MCU的波浪/随机/扫描/蛇形分别用模式0/3/4/6；新MCU对应7/9/8/10，支持颜色与方向。呼吸1、闪烁2、涟漪5、Fn11和渐灭13共用现有命令。波浪方向0..7映射命令21参数113..120或161..168；蛇形0..3映射命令22参数113..116或161..164。扫描双色使用两条23/161、23/162，随机自定义使用24/161。

原厂会把多数动态黑色替换红色；应用新草稿明确拒绝这一隐式变化，提示选择非黑色或关闭。扫描允许单端黑色，双端同时黑色才拒绝。UI方向文字来自BAML箭头样式及GetWaveVector/GetSnakeVector，未按数字猜测顺时针顺序。

原厂事件链路是WH_KEYBOARD_LL，不依赖HKFltr过滤驱动。自研捕获线程只投递扫描码与按下/释放，有界64项队列，不记录按键文本、不阻止输入；独立输出线程持有同一HID身份并经过HAL全局控制锁。模式确认前先准备未激活会话；保存成功后激活，失败和切换停止旧输出，恢复按目标模式准备新会话。线程回收在释放HAL锁之后执行。

涟漪/单键响应分别发送cmd7/8：多彩`[cmd,FF,scan,0,0]`、自定义`[cmd,scan,R,G,B]`。扩展扫描码低字节置bit7，E036归一36；左Win延迟50ms，与左Shift/F23组合编码DD。重复按下过滤，Fn扫描码6F按下时按原厂语言/三列标志点亮对应LED，释放清空。暂停递增事件代次，旧队列不能在切换后补发；队列满或发送失败停止并保留诊断，UI允许同值重新应用启动事件。读取发现设备/保存值变化也暂停会话。普通启动不自动捕获或写入灯效。

### 7.2 键帽布局

`src/lib/perkey-layout-data.json`是原厂BAML键位几何、Content和Tag，以及纯UpdateKBLayout分支离线生成的事实数据；生成过程使用自建C#属性桩，未运行原厂程序集。4种语言×三列标志×紧凑标志共16个分支。物理三列标志取kbled使用的cmd17 byte14，紧凑判型来自cmd4/sub12的EDID毫米尺寸；任一必要事实未知时显示明确的灯位矩阵，不猜成完整键盘。

- 原始1型调用GetWMI(61)，严格接受本次有效整数0–5，随后同步page2[35]亮度及[80]开关；不发送cmd39/103。page7 v1.0的WMI122 bit14仅控制0–2或0–5的屏显样式，普通样式收到3–5仍同步并刷新控件，只是不弹OSD。未知能力版本、回声、未写输出和越界值拒绝同步，不用旧缓存代替报告。
- 白光同步只回读并补偿所属保存字段，不创建或改写硬件首次基线。软件策略恢复还原初始规则，不撤销固件已执行的按键动作。hotkeys的私有Completion分别表达结果与屏显条件，runtime统一更新最后结果、控件刷新和可选提示，无第二发布路径。
- 灯光107项、热键19项及跨域/整数ABI的5项聚焦检查通过，相关模拟页面22项组合和最终4项检查通过，覆盖失败补偿、共享基线、报告上限与屏显样式分离、权限变化及深浅宽窄布局；没有调用真实OEM接口或执行物理按键，保存回读不证明实际灯光效果。

## 18. 摄像头状态反馈与保存镜像

- 来源为同一FnKey的Form1.Arg001_GetEvent与Features.WriteCCDValue。246/247分别报告摄像头关闭/开启并将page1[6]保存为0/1；248报告摄像头和麦克风关闭，不写保存值；249报告组合开启，仅将摄像头保存为1。Features.SetCCD另有SetWMI(34)，这四事件未调用它，也未调用麦克风开关。事件高位不改变这些固定语义。
- 独立cameraReports范围默认关闭。stateNotifications或microphoneMute授权不包含保存副作用，新范围必须预览确认；能力只检查保存字节可读取性，不把旧缓存描述为实际设备状态。所有反馈沿用原厂控制权检查，CC40存在时不接管，与原版246/247的CC40屏显抑制保持一致。
- hotkeys/camera_report唯一拥有此事件镜像，在共享HAL锁内先读原字节、按需写入并回读；失败只补偿该字节，不覆盖其余page1字段。重复报告已一致时不重复写入；未知原值按原始字节补偿，初读失败零写入，补偿失败同时保留原始错误与恢复诊断。
- 此范围不调用设备开关、Core Audio或系统授权，也不建立硬件初始基线。临时停止结束本次监听；软件策略恢复还原初始规则，由原规则决定后续接管，不把固件已报告的缓存改回旧值。runtime统一发布最近结果及可选OSD，取消、策略变化或原厂控制者出现时不显示迟到提示；此类反馈不发布hardware-controls-changed。

## 19. 原厂屏幕亮度策略

78/79与48–56通过独立screenBrightness范围接入原厂目标表，不是背光加减或只读状态通知。面板、计划和完整目标绑定预览确认；实际WMI报告与计划AC/DC保存值分开，事件执行、取消、补偿及逐计划初始恢复见[屏幕亮度契约](screen-brightness-contract.md)。原厂目标报告失败不阻止已知初始计划恢复，停止和软件规则恢复也不替代硬件恢复。

## 20. 原厂215屏幕按键

- FnKey 7.19.5.0在215号事件上先按OLED_Panel分支；OLEDPanelCheck只认可EDID的`4C8329A0`、`4C834341`两个签名。自研检查完整EDID基本块和设备节点，保留未解析节点诊断。存在已确认OLED时优先选择屏保；没有确认OLED且任何节点未解析时，不推断非OLED。
- 原厂OLED分支经鼠标定位和PowerShell启动系统`scrnsave.scr /s`，其效果是空白屏保。自研直接启动系统文件，在私有Windows Job中管理会话，不发送显示电源命令、模拟鼠标或结束其他屏保；准备后复核许可和来源，保留可取消的100ms等待。
- 非OLED时先只读查询`cmd4/sub8`。版本0.0沿用原厂允许输入监听的默认值，版本1.0检查byte15 bit3，未知版本不推断。符合条件时同线程观察键盘和鼠标：首次键盘按下只结束，首次鼠标活动发送`SetWMI(94,1)`后结束，按键释放不结束，也不拦截输入。发送结果只表示请求被接受；不构造反向命令。
- `panelHotkey`默认关闭并单独确认，来源包括已确认面板、相关固件标志及屏保文件身份。会话结束的确认绑定当前会话，确认后冻结后续活动并停止监听；失败保留可重试资源。临时停止、软件策略切换和退出均清理本应用会话，软件策略恢复不重放先前交互。
- 测试只使用明确注入的面板与OEM内存函数、隔离假子进程和模拟IPC；未读取真实面板、执行系统屏保、安装输入钩子、读取原厂事件或发送固件请求。低级钩子超时可能被Windows静默移除，参见[Microsoft钩子说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)；回调只入队类别并立即返回。
