# Agent Note: 原厂显卡模式与重启后验证

Status: implemented

## 问题

独显电源关断不等于MUX/混合显卡模式。原厂CC3 Window1使用cmd4/sub21读取模式及能力位、sub22发送1..4选择后重启。已核对本机DSDT：PK04 Case0x15根据PSF0和ACPI命名空间报告当前模式，Case0x16通过PRM0=0x1B/SSMP=0xC0通知SMM；未提供待重启选择的可靠回读。不能要求写后sub21立即等于目标，或把命令接受当作显示路径已切换。

## 决定

- page7扩展能力版本1.0 byte18 bit0开放；候选只能来自sub21 byte1低四位，1集显、2独显、3混合、4动态。当前报告、应用自身的待重启选择及实际重启验证分别表达。
- 单一version1操作记录持久化在应用数据目录，绑定Windows安装和BootIdentifier，保留初始模式、此前已知选择、目标、能力及命令接受阶段；先原子记录意图，再发送，失败发送此前选择补偿。应用重启不丢恢复入口；启动读取记录不写硬件。
- 预览修订绑定当前报告、能力、操作记录与启动标识。只有系统启动标识已变化且固件报告匹配，才标记重启后确认；同次启动即使报告碰巧匹配，也不冒充已重启。
- Windows启动标识使用动态链接NtQuerySystemInformation的SystemBootEnvironmentInformation，只读系统元数据，校验结果及结构；不以墙上时钟推算重启。ABI参考[System Informer phnt](https://github.com/winsiderss/phnt/blob/master/ntexapi.h)，动态链接约束参考[Microsoft文档](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntquerysysteminformation)。接口不可用时明确报错，不猜启动状态。
- UI以固件支持的模式按钮直接发送选择，卡内显示当前报告与待重启目标。恢复选择在卡内确认，重启单独确认。重启仅使用固定 Windows 系统工具，保留正常关机流程。测试使用假传输、假启动标识和隔离记录。
- 2026-11-23 显卡模式选项在标签上方展示无底色的集显、独显与屏幕通路示意。单显模式突出一条通路，混合模式显示两条，动态切换显示虚线分支。图形只表达选项含义，所选样式取自原有固件报告或待重启目标。
- 2026-11-24 通路示意重绘。四种模式共用画幅、线宽与字形位置，取自 Lucide 的 cpu、gpu、monitor 比例，不新增图标依赖。选中项里位于通路上的 GPU 画成实心挖空字形，未选中项用线框与浅底色，不在通路上的 GPU 淡出，沿用导航图标的线框／实心配对与强调色选中。通路以箭头收尾并指向屏幕。混合模式改为独显经箭头汇入集显、再由集显输出到屏幕，不再把独显画成直连屏幕。动态切换的两条通路改为点线，汇聚到带双向箭头的切换徽标后输出到屏幕。图形最大宽度由 136px 调整为 156px，两列宽卡填充更满，四列窄卡仍受卡片宽度约束。图形仍只表达选项含义，不表示实际显示路径已切换。依据 [Apple 人机界面指南图标页](https://developer.apple.com/design/human-interface-guidelines/icons)：全套界面图标保持一致的线宽、细节层级与尺寸，造型高度简化，选中项使用强调色，采用矢量格式。

## 影响与验证

- 新增graphics_mode领域、4项IPC及控制台卡片；固件报告保持旧值时，已接受的写入仍呈现待重启，恢复请求同样不冒充即时切换。
- 18项原生聚焦检查通过，覆盖新启动匹配/不匹配、准备阶段中断、外部记录变化、失败补偿、恢复重试、重启失败与启动标识ABI。存储只读写临时目录，拒绝旧修订、未知字段/版本和其他Windows安装的记录。
- 3项构建页面隔离IPC检查通过，覆盖草稿与确认重置、独立重启确认、恢复、保存失败和能力候选约束；构建及workspace检查通过。原生系统查询、OEM命令和实际重启均未执行。
- 2026-11-24 重绘后，显卡模式4项、配置密度11项与档案MUX9项隔离用例通过（另一检查服务占用1450端口，本轮改用1451端口的隔离服务）。用例断言四种模式的通路段数为1、1、2、3，动态切换使用点线，实心挖空字形只出现在选中项。`npm run build`、`cargo check --offline` 与 `verify-notes` 通过。已目检浅/深主题、560/1000/1440px、两种与四种候选的截图。未做原生 Tauri 窗口验收，无硬件写入。

## 风险

命令接受不证明SMM已持久化选择。原厂未公开此前其他程序尚未重启的挂起选择，恢复目标只能取固件报告和本应用已知选择。原生重启、系统标识查询和物理显示路径本轮不执行。

## 备选方案

- 用PCI禁用模拟MUX：语义不同，拒绝。
- 用sub21的旧启动报告判写入失败并立即还原：会撤销有效待重启设置，拒绝。
- 只保留内存草稿或用时间戳识别启动：应用重启丢恢复记录，时钟修改会误判，拒绝。
