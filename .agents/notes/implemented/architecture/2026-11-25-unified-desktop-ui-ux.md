# Agent Note: Colorful Control Center 界面与模块原位优化

Status: implemented

## 问题

主按钮原有白字对比度为 3.65∶1。部分控件用阴影表示焦点，选中和获取键盘焦点时难以同时识别。各工作区也有相似的数字、单位、标题和状态反馈对齐问题。

54 张预览进一步显示，浅色工作区与模块共用同一底色，深色则把模块、图表和控件集中在相近的蓝色亮度上。常规面板主要靠细描边分隔。区分窗口框架、工作区、面板、内嵌内容和浮层能增加层次，尤其是设置、档案和设备配置等同时显示多个交互区的页面。

构建产物把侧栏时长从 `320ms` 压缩为 `.32s`。指示条把数字部分当作毫秒，导致切换动画接近瞬时。改用 CSS 和脚本共读的一项毫秒数值，减少动效时将数值置零。

## 决定

共享样式直接采用 `src/styles/tokens.css` 的操作文字、填充、控件边界和焦点令牌。主按钮默认、悬停和按压时的白字对比度均达到 4.5∶1（2026-11-27 起操作蓝改为 `#3A83F7`，对比度为 3.64∶1、下限 3∶1，见 [操作蓝改用浅蓝](2026-11-27-lighter-action-blue.md)）。按钮、输入、开关、页签和选项采用独立的实线焦点轮廓。开关和选项在强制颜色模式下用系统色表示选中和焦点。安装向导由现有构建脚本生成画刷，继续使用 `installer/Theme.xaml` 管理原生按钮及输入框。

界面采用仓库内 Apple `DESIGN.md` 的黑白灰表面及圆角和边框尺度，操作蓝为单一的产品自定色（2026-11-27 起为 `#3A83F7`）。顶栏和侧栏用半透明中性色，减少透明度时使用同色实底。卡片、读数、输入、菜单和弹窗通过色面与细边界建立层次。反馈采用原有文案、状态图标和公开的控件语义。自绘 SVG 保留硬件数据及插画配色，系统强制颜色由 Windows 配色接管。 [Apple 设计参考](../../../../docs/design-references/apple/DESIGN.md)

主操作与次操作使用 Apple 胶囊形，紧凑按钮与下拉用 8px 圆角，内容卡、弹窗和安装向导用 18px 圆角。文本字段、滑块和开关使用共享边界及颜色。键盘背光、色轮与用户选色作为 SVG 显示；方向和亮度继续由实际数据驱动。原生安装向导从全局令牌生成画刷与尺寸。

| 区域 | 优化 |
|---|---|
| 概览 | 对齐 CPU、GPU、内存和存储读数，以及图表单位和峰值。 |
| 性能与散热 | 校正模式名称、参数组标题和确认区行距，统一散热读数及曲线控件焦点。 |
| 键盘与灯光 | 对齐亮度、颜色值和模式控件。由键帽表面呈现背光，以各自的状态标识区分选中与键盘焦点。 |
| 电源设置 | 用实底电池槽承托原有电量填充，对齐百分比、阈值和档案应用规则。 |
| 配置档案 | 统一档案名称层级和差异数值基线，保留现有预览和回读路径。 |
| 设备配置 | 统一参数和 GPU 功耗单位，校准现有更改预览及结果区的排版。 |
| 设置 | 对齐设置项、外观选项和控件，提高既有更新进度及链接的对比度。 |
| 通知、屏显与对话框 | 校正通知数量及长标题的空间分配、屏显档位数字和对话框操作反馈。 |

概览和性能页保留预设 SVG 的路径、画幅、配色、动画和显示规则。导航、模块顺序、分栏及硬件提交和恢复流程沿用原有入口。本次新增界面文案、装饰标签和兼容分支均为零。持续生效的视觉约定由 `DESIGN.md` 维护。

排版及焦点参考苹果指南，读数与控件细节参考 BoardUI 社区组件。 [Apple HIG · Layout](https://developer.apple.com/design/human-interface-guidelines/layout) · [Apple HIG · Focus and selection](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection/) · [BoardUI](https://www.boardui.com/components)

电源设置页的设备卡片固定保留。能读取的状态直接显示，硬件无对应能力、无适用设备或读取失败时在卡内反馈。默认浏览器与展示夹具只使用省电、安静、娱乐和性能四档。声明扩展安静档的机型用其替换普通安静档。

### 2026-11-26 图表卡片

CPU、GPU 保留两行卡头，部件插画和品牌标识在左侧，名称、型号与规格入口在右侧。系统内存和本地存储的卡头使用单排布局，依次显示部件插画、标题和最右侧的共享信息图标按钮。窄窗缩小插画列，硬件型号可折行。CPU、GPU 和内存的当前值集中在卡头与图表之间。趋势以实际采样绘制一个时间坐标，横向参考线、渐淡填充和指针读数均由共享图表维护。风扇实况、编辑曲线、档案曲线、电量和节能时间轴沿用同一系列色与轨道。可编辑曲线继续以当前虚线和目标实线区分数据。导航、模块网格、预设插画、轮询及硬件事务沿用已有入口。

图表使用 BoardUI 的明暗轨道、参考线和分类色阶。高温继续用 95°C 阈值及读数标出。全局控件采用现有主题；图表使用本地 SVG，无新增运行时包。 [BoardUI 图表卡](https://www.boardui.com/components/revenue-chart-card) · [BoardUI 图表色](https://www.boardui.com/components/color#graphs)

散热实时区按通道显示带指针和刻度的环形转速表。各表盘使用同一量程，覆盖 4000 RPM、设备报告上限及五分钟采样峰值，随后按 1000 RPM 换算刻度与读数。读屏按实际 RPM 播报。停转、缺测和上次读数有独立表示。自定义档继续使用风扇实况、曲线和点位编辑。 [BoardUI 环形图表](https://www.boardui.com/components/radial-chart-card)

### 2026-11-26 调校卡片标题区

性能与散热页的预设模式、CPU 调校、GPU 调校、散热控制和风扇除尘各在模块标题栏最右侧提供一个信息图标，读屏名称与悬停提示使用对应弹窗标题。窄窗里的除尘重新读取按钮可以换行，信息图标与模块标题保持同排。CPU 和 GPU 调校共用卡头，硬件型号显示在标题下方，与标题文字左对齐。GPU 型号来自当前可调校设备的配置回读。CPU 型号来自概览所用的设备资料，资料由应用工作区持有。直接进入性能页且尚缺 CPU 型号时读取一次，概览可见时继续按原周期更新设备资料和存储。性能页复用已读型号，内存采样仍按概览可见性启动。

### 2026-11-26 散热控制分栏

散热控制通过两张内嵌面板区分整机策略与风扇实况。整机策略持有风扇模式、加速偏移、预设选项和恢复入口。风扇实况按已确认档位显示环形表盘，进入自定义档后显示实时读数、曲线与点位。宽窗两张内卡共用一行高度，上下边缘对齐。恢复入口贴左卡底部，自动档的表盘区随右卡可用高度展开。窄窗按相同顺序纵排，各卡随内容定高。面板通过共享表面色和留白分组。外层继续持有读取状态、诊断、重试和散热控制模型。

## 影响与验证

- 图表卡片通过 64 项 Chromium 聚焦回归与 21 项布局复测，覆盖深浅主题、宽窄窗、温度和转速缺口、悬停读数、曲线点位编辑及电池和档案读数。图形验证使用隔离 IPC 回放。
- 比较材质更新前后的构建产物。浅深主题、六种窗口尺寸和七个工作区或子区组成 84 组检查，模块顺序、主分栏、预设 SVG 画幅和可见溢出记录一致。
- 在隔离 Chromium 中核对主按钮三种操作状态的文字对比度、独立焦点、强制颜色、较高对比度与减少透明度。保留短窗控件和 GPU 回读失败恢复检查。
- 扁平样式通过 40 项 Chromium 聚焦用例。检查浅深主题工作区的控件色面、悬停和按压状态、键盘背光配色以及强制颜色。安装向导复用隔离安装引擎渲染，核对原生按钮和长路径编辑。
- Apple 参考接入后通过 72 项 Chromium 场景、34 项控件与规则测试、前端构建和 Rust 类型检查。验证浅深主题的共享操作蓝、细边框和键盘焦点、SVG 色谱及键盘背光、曲线吸附和窄窗布局。隔离 WPF 渲染覆盖安装向导。当前图册包含 56 张原图。
- 前端构建、控件边界检查及 Rust 类型检查通过。当前图册共 52 张预览，覆盖浅深主题、各工作区、四档预设、浮层及 Windows 安装向导。安装向导使用 WPF 和隔离事务渲染六种画面。
- 电源模块回归包括 68 项 Rust 聚焦测试和 38 项浏览器场景。沙盒外使用生产 DCHU 读通道取得 BIOS 1.0 能力页。本机未声明 PD、Deep S5、USB 原厂策略、网卡节能、关机唤醒补丁。Windows 当前活动计划的 USB 插电与电池设置均为开启。
- 沙盒内 NSIS 启动及下载失败后，复用已编译的 2.0.0 主程序在沙盒外生成 NSIS 引擎，再运行原有 WPF 封装验证。安装包通过 AMD64、版本、五份资源和摘要校验。真实安装流程待验收。

## 备选方案

- 仅更新共享样式可以统一按钮和焦点，读数、单位和长状态仍需要领域样式处理。
- 逐页定义样式可以更快试验单页效果，共用控件的行为和视觉细节会分散。
