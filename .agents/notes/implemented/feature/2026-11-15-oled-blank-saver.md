# Agent Note: 原厂OLED空白屏保事件与适用条件

Status: implemented

## 问题

本机FnKey.Form1的215号事件存在两个活动分支。OLED_Panel为真调用Features.SetScreenOff；否则在DisableFnF2TouchPadHook为假时仅广播clevofnkey^1ff。当前仍未接入，不能将方法名解释为显示器断电或无条件触摸板切换。

## 决定

- 来源为指定Pi会话的FnKey 7.19.5.0：Form1.cs 2434分支及1059启动检测、Features.cs 908–930/1436–1452、OLEDPanelCheck.cs 229–333。SetScreenOff实际先移动鼠标到绝对坐标0/0并点击，再经PowerShell启动scrnsave.scr /s；它是Windows空白屏保，未发送DPMS/亮度/EC命令。
- OLEDPanelCheck枚举Monitor类节点，核对硬件ID及对应EDID bytes8..11；原厂精确白名单为4C8329A0和4C834341。不能用厂商名称、OLED宣传型号、WMI能力位或任意新面板替代这两个标识。原版读取失败吞掉异常，自研应保留来源诊断并基于当前可确认节点绑定许可。
- 实现使用独立默认关闭范围，预览明确为原厂条件下的空白屏保。复用现有Windows显示/设备身份读取职责，严格来源绑定；屏保启动不创建亮度、显示模式或设备开关恢复基线。正常输入退出和显式恢复均只管理本软件创建的会话，不按进程名结束其他程序。
- 自研直接启动明确的Windows系统空白屏保及固定/s参数，保留原版黑屏保护结果；不加入模拟鼠标点击、PowerShell脚本或未经确认的显示电源命令。启动、重复事件、结束、退出及失败保持可审查的所有权，测试只使用显式假进程和内存设备。
- 非OLED消费者已确认：DCHUService.Service1的341–346行收到clevofnkey^1ff后启动WakePanelUp_Hook.exe。本机49200字节程序集SHA256为5561d41e4ae54460f0045e1678b2bed87fdcbe45e94236867ee8b3255ff2b9c4，静态提取在target/ui-check/wakepanel-source；没有执行程序。Form1在首个键盘按下只退出，首个鼠标活动才调用SetWMI(94, 1)后退出，键盘释放不结束、也不吞输入。自研使用既有键盘事件通道及独立鼠标只读事件通道，只保留本次一次性监听，回调不写硬件，不复用原厂吞错误的辅助进程。
- DisableFnF2TouchPadHook仅在BIOSSpecialFeature_v1_0将page7[15] bit3置真；v0.0不赋值，保留默认false。版本0.0/1.0分别按已确认契约解码，未知版本拒绝非OLED分支。OLED优先判断，不依赖此位；禁止位为真时不设置任何输入监听。两种行为共用独立215范围，预览展示当前实际分支、来源和撤销语义，不扩展已有触摸板或屏幕亮度授权。
- 空白屏保进程创建时关联私有Windows Job，采用KILL_ON_JOB_CLOSE，显式结束仅针对所持句柄；不采用创建后再关联的窗口，不按PID重开或进程名终止。鼠标唤醒的撤销只解除等待，不猜测反向休眠命令。新进程验证只启动隔离假子进程，原厂屏保、原厂Hook及真实输入钩子均不运行。
- 非OLED能力直接只读查询cmd4/sub8，避免将未初始化page7的零值当成已确认v0。已知OLED优先；没有已知OLED且任何节点读取失败时拒绝判断为非OLED。面板读取返回已知节点和逐节点诊断，不让无关节点错误遮蔽已确认OLED。
- 本机原生SetDCHU_Data的返回约定及既有DSDT的SCMD 0x5E分支已静态核对：参数1发送C2、返回0x5E；复用set_u32(94,1)，只报告唤醒请求被接受，不推断物理唤醒，也不构造94,0恢复。
- hotkeys/panel_hotkey唯一持有交互会话，准备和等待在HAL锁外；准备后再次检查软件许可和来源，才启动屏保或激活一次性输入监听。回调只传递键盘按下/鼠标活动类别。临时停止、策略更换和退出先取消事件执行，再结束所持资源；资源清理失败保留可重试会话。软件策略补偿不重新启动已结束的交互会话。
- 键盘和鼠标钩子在同一专用线程安装，按观察到的首个活动结束等待；解绑错误写入日志，线程退出后Windows释放线程所有的钩子。低级钩子超时可能被系统静默移除，回调只传递活动类别，不等待其他工作，不能把监听启动冒充唤醒已发生。
- 显式结束时在会话串行锁内核对预览版本并冻结后续启动及活动处理，再停止监听并清理该会话；解冻发生在停止完成或失败之后。因事件并发造成的版本变化会拒绝旧确认，失败仍保留可重新读取和重试的资源状态。

## 风险

原版方法名不代表物理显示器状态，屏保过程不能宣称面板已断电。机器当前是否匹配白名单未查询；适用条件由运行时只读提供者判断，不因缺真机验收停止代码实现。

## 影响与验证

热键领域70项、键盘事件4项、核心规则3项、受管假进程5项及模拟页面6项通过；覆盖来源变化、许可隔离、准备中并发确认、首个输入、错误与清理诊断、父进程终止、子进程树和无关进程保留。页面目检深浅宽窄布局，前端构建、源码长度和26项控件校验通过。只对系统屏保文件做文件存在核对，没有执行它，也没有读取真实EDID、安装实际输入钩子或发送唤醒请求。

## 备选方案

- 根据SetScreenOff命名发送显示器电源命令：不符合已确认执行链，拒绝。
- 复刻原版坐标点击和PowerShell包装：不是完成空白屏保行为所需，拒绝。
- 按scrnsave进程名统一结束程序：可能影响非本软件会话，拒绝。
