# Agent Note: 风扇控制采用 OEM 曲线模式优先（软件闭环延后）

Status: implemented

## 问题

Phase 2 路线要求「任意控制点曲线 + 滞后回差 + 斜坡限制 + 看门狗」。任意自由曲线的执行有两种架构：软件逐 tick 闭环直写 EC（0xE7，需内核通道 + 看门狗），或使用固件自带的自定义曲线（cmd14 三可调点 + 斜率）。两者自由度、安全性与依赖差异巨大，需要先定架构再动工。

## 决定

（2026-11-12，基于 oem-dchu-contract.md 的 OEM 实现审查）

1. **Phase 2 交付 OEM 曲线模式**：用户曲线经 `compress_to_oem_points` 压缩为固件三点（T2/D2、T3/D3；T1/D1 与 100%/100°C 固定），cmd14 写入 + 模式置 Custom(6) + page4 持久化。**曲线由固件执行——软件崩溃/退出不影响风扇，天然免除看门狗需求**。
2. 曲线引擎（插值/滞后/斜坡/熔断）作为纯逻辑落在 `crates/ccc-core`（11 个单元测试），当前服务两件事：任意曲线 → OEM 三点的压缩采样；为软件闭环模式预置完整逻辑。
3. **软件闭环自由曲线延后**（Phase 2.5，需用户启用）：FanMode=Custom + 引擎逐 tick 直写 EC 0xE7（PawnIO 端口模块）+ 双进程看门狗 + 95°C 熔断。引擎与安全语义已就绪，仅缺内核通道与看门狗进程。

## 影响

- Phase 2 验收标准中「看门狗」项由 OEM 曲线模式的固件执行语义满足（软件强杀后风扇仍按曲线运行）；「任意控制点」在 OEM 模式下为 3 可调点表达（压缩采样），完全自由度待闭环模式。
- 引擎拆到独立 `ccc-core` crate 还解决了 mingw ld 对 cdylib 测试链接的 "export ordinal too large" 限制（纯逻辑测试链接 rlib）。
- 写入路径集中在 fanctl（cmd14/121/page4），全部经 validate_oem_curve 几何校验（温度/占空比严格递增、D3<100）与 ≥20% 钳位。
- 软件闭环到来时必须补：PawnIO 端口 IO 模块集成、看门狗双进程、dt 时钟来源。

## 备选方案

- **直接上软件闭环（NBFC 式）**：自由度最高；但必须先引入内核通道（PawnIO 端口模块或 WinRing0），Defender 拦截风险回归，且看门狗/时钟/恢复链路一次到位复杂度高——与"避免调试机器"的节奏冲突。保留为 Phase 2.5 增量。
- **仅做模式切换不做曲线**：安全但没解决用户核心痛点（原版 CC 曲线死板）。OEM 曲线模式已经比原版 CC 的固定档位强得多（原版只有自动/全速/固定档），放弃。
