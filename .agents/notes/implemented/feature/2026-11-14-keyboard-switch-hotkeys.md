# Agent Note: 原厂键盘灯总开关热键

Status: implemented

## 问题

本机Pi的FnKey.Form1.Arg001_GetEvent中63调用KBModule.Status反转及SetStatus，158/159只对type2/3/6/22/23/38执行同样操作；白光type1不进入158/159分支。现有热键授权仅含亮度，不应隐式扩大为开关。KBModule按家族委托普通、逐键、白光和多区设备，不能统一发送cmd103。

## 决定

- 新增严格keyboardSwitch授权范围，事件63及158/159保留白光适用差异；原有六类授权不隐式包含该动作。
- 各领域添加总开关动作，复用本域Scope/Plan/首次基线及失败补偿。关闭保留非零亮度、颜色、模式、其他灯区；逐键按键会话继续经过候选准备、提交和锁外退出，不新增写入通道。
- 补齐真实FnKey.RGBKB的type38：键盘判型归普通RGB，亮度档位精确为47/102/155/212（原厂未匹配档位值47），关闭仍以E0总开关表达；颜色继续普通蓝色比例编码。独立顶盖仍用自己的标准亮度表，不因键盘38改变。该型号此前未开放，不能直接套用2/6/22的亮度表。
- 执行前核对现有设备身份和家族，未知状态不猜测。每次事件串行读取当时已保存状态，不使用页面草稿。UI单独展示接管范围、确认和恢复软件策略，硬件初始恢复仍在灯光模块。

## 影响与验证

新增6项跨域内存检查覆盖普通/白光/逐键/多区的开关、保留亮度和颜色、部分失败、设备变化、逐键响应会话及档案共用首次恢复；type38新增3项精确亮度/颜色/开关编码、逐阶段失败及恢复检查。档案过滤267项通过（含11项显示领域复用，2项真实设备忽略），灯光85项、热键9项、核心事件5项通过。

新增2项页面检查覆盖亮度/开关分别授权和设备变化撤销确认；与独立顶盖、多区及档案组合30项页面通过。npm build、workspace cargo check、12项隔离软件进程及26项控件检查通过；92个Rust和40个前端/检查源文件500行、函数80行检查通过。所有检查只用内存传输、私有文件和模拟IPC，没有读取真实事件、调用原厂程序或访问物理设备，真实灯效及桌面屏显未验收。

## 备选方案

- 让现有亮度授权自动包括开关：改变已有授权含义，新增独立范围并明确确认。
- 所有家族统一写cmd103：逐键和多区有独立协议及会话，复用各领域事务。
- type38复用标准亮度表或让其改变独立顶盖亮度：与活跃FnKey代码不符，按原始型号选择键盘表，顶盖保留独立固定含义。
