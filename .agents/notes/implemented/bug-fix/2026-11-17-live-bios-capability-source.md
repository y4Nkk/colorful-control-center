# Agent Note: BIOS能力使用原厂实时查询来源

Status: implemented

## 问题

安装版展示全部模式不支持、自动刷新率无模式及多个设备未知。原厂Features.BIOSSpecialFeature使用cmd4/sub8查询，然后WriteAppSettings(1792,256,packet)建立page7缓存。自研多个模块直接读取此缓存，没有执行原厂查询；缓存为零不能证明固件不支持。

## 决定

Dchu唯一拥有read_bios_capabilities，按原厂SetWMIPackageEx(4,首字节8)取得能力包，校验传输、完整包、范围和已实现版本。所有直接能力消费者使用该入口；SettingsAccess适配器的逻辑page7读取映射同一能力来源，供现有纯事务与策略复用原厂布局，不能读取缓存回退。read_settings拒绝page7，避免后续误用，能力读取不回写原厂缓存。保存字段仍走原AppSettings通道。

按原厂版本规则补齐无显式模式掩码时的WMI16基础候选和WMI96 DTT分支；1.0内嵌字段有效时不调用整数分支，原厂整数分支不可读明确报错，不伪装未支持。17处直接消费者及原有实时查询接入同一来源，探测CLI同步。档案共享夹具由bios唯一拥有固件包，pages[7]保持空缓存；原先分离的能力/节能测试事实合并，其他测试消费者同步，不用复制缓存掩盖来源错误。

## 影响与验证

全速监护组合复查补齐剩余测试消费者：workflow/energy_tests七处多行get_mut(8)及GPU手动联动一处均改用同一bios字段。原夹具已不再建立selector8的第二事实来源；不恢复旧表来掩盖失效测试。

涉及HAL及模式、风扇、独显、显示、电池、灯光、映射和平台能力消费者。同步模拟固件查询响应、契约与相关检查。保留预览修订、确认、补偿及恢复，不运行真实查询或写入。HAL传输9项、模式14项、Turbo/DTT20项、档案GPU18项、后台权限9项、故障曲线锁3项及自动刷新率32项聚焦检查通过；除尘和平台/键盘/顶盖/逐键档案消费者检查通过，日志归target/ui-check/live-source-*.log。明确验证原厂缓存为空时，真实模式读取仍从模拟固件查询获得四模式，且不写共享缓存。软件曲线与真实隔离监护组合17项通过，Windows GUI监护管道10项通过；这些进程只使用假传输和私有目录。

## 风险

仅隔离验证，不证明驱动或物理控制效果；原厂0.0与1.0的整数能力分支必须分别核对。

## 备选方案

写入或复制page7默认能力会改变原厂共享缓存且伪造事实；按机型硬编码开放按钮也不能替代真实能力来源，均拒绝。
