# Agent Note: 风扇加速偏移的档位与机型门控

Status: implemented

## 问题

寂静档调偏移曾有「未见转速变化」的口头反馈，没有同负载对照。把现象直接推断为
「寂静档不消费偏移」，控制台因此在寂静档也禁用了滑杆。原厂 FanSpeedSetting 的
寂静选项并不隐藏偏移：开关与偏移分别发送风扇档位和偏移命令，FnKey 恢复寂静时
也会先下发已保存的偏移。仅按单一现象禁用，与已确认的原厂设置行为不符。

## 决定

- `src/api/fans.ts` 唯一拥有界面档位规则 `offsetModeAvailable`：自动与寂静档可调，
  其余固件模式禁用。滑杆与提交钩子共用该规则，并保留软件接管、忙碌、读取失效、
  除尘与机型能力门控。禁用提示只说明能否调节，不推断固件是否实际消费。
- `fanctl::read_firmware_profile` 合并机型能力：WMI96 bit10 只叠加禁用，不再覆盖
  RPM 布局的不支持结论；能力读取失败保留布局默认值并追加诊断。
- 偏移提交沿用既有 `setFanOffset` → `fanctl::set_offset` 事务：只写偏移命令与
  page4 偏移字段，不切换风扇档。预设、档案、恢复与寂静档保存模型不变。

## 影响与验证

- 界面：`fan-visuals.spec.mjs` 覆盖自动与寂静可调、寂静提交只发一次偏移且回读
  仍为寂静、其余档位与不支持机型保持禁用且不发送偏移写入。
- 原生：`fanctl::dust::tests::native_tests` 覆盖布局与 WMI96 两种能力禁用来源，
  以及寂静档正常设置只更新偏移和所属偏移槽、不发送风扇档命令。
- 未验证：寂静档的物理转速效果与重启恢复仍需真机同负载对照，结论回填
  `docs/oem-dchu-contract.md` §11-9。

## 备选方案

- 保持仅自动可调：与已确认的原厂行为不符，且用户在寂静下无法完成原厂支持的调整。
- 在共享 `fanctl::set_offset` 全局按档位拒绝：会波及预设模式与恢复路径。
- 对齐原厂在 bit10 置位时清零：引入额外硬件写入，收益仅是状态整洁，不做。
