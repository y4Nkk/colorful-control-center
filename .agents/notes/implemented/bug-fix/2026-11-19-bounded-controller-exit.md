# Agent Note: 控制台有期限的退出

Status: implemented

## 问题

原托盘与窗口共用事件线程，退出在事件循环末尾同步等待硬件与监听线程。正在应用的档案释放 HAL 锁后，独显和网卡授权会话仍有提交或补偿工作。

## 决策

- Windows 托盘独立处理菜单。托盘、窗口退出、界面重启和 Windows 会话结束统一请求 `shutdown/`。旧 Tauri 托盘和事件循环末尾的领域清理已移除。
- 第一次请求启动内核计时器并关闭操作准入。同步处理器、实际运行的阻塞 IPC 与启动任务持有操作状态直到提交或补偿结束，后台调度收到停止信号。清理线程等待在途操作与工作线程，再释放软件风扇、显示试用、电池校准及监听状态。
- 独立退出监护通过私有管道接收主进程直接复制的对象句柄，等待主进程结束或计时器到期。期限固定为 15 秒。到期以 124 请求终止该主进程，监护保留设备领域原有的恢复职责与控制权。Windows 需要完成或取消内核 I/O 才能完成进程终止。[Windows 进程终止语义](https://learn.microsoft.com/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess)

## 影响与验证

隔离进程验证了硬件锁释放后的提交等待、拒绝新请求、重复退出维持首个期限、Windows 原生消息接入、主线程与清理线程卡住、监护缺失时结束自身，以及显示、风扇、校准、独显和网卡的独立恢复。另用私有 DLL 夹具等待实际 `DLL_PROCESS_DETACH` 卡住，监护使主进程返回 124。已构建前端并执行 Rust 工作区检查。实际 Windows 通知区域点击和物理设备恢复仍待验证。

## 备选方案

进程内计时器会在 Windows 的常规退出中随其他线程先被终止，无法处理随后卡住的 DLL 卸载。按 PID 重新打开目标会依赖进程标识继续指向原控制台，当前实现使用直接复制的句柄。
