# Agent Note: 设备配置移除模块内恢复初始状态入口

Status: implemented

## 问题

设备配置页各模块底部带有恢复入口：屏幕显示、显卡模式、独显电源、键盘功能、触摸板、麦克风、飞行模式为「恢复初始设置」，自动刷新率为「恢复启用前状态」。这些模块的选择和开关本身直接提交并回读。用户要求移除该页各模块的恢复默认按钮，并明确要求无兼容、无过渡、无技术债的完整实现：不能只藏起按钮而把后端恢复路径留成无人调用的代码，也不能留下删掉按钮后无处可出的状态。

## 决定

2026-11-24 设备配置页八个模块不再渲染恢复入口。早前「初始恢复移至各模块」的描述（2026-11-17-configuration-first-ui）由本条取代。

只服务于初始恢复的路径在所有层一并删除：

- IPC：`restore_display_modes`、`restore_gpu_power`、`restore_graphics_mode`、`restore_keyboard_settings`、`restore_touchpad`、`restore_microphones`、`restore_airplane` 七条命令，连同注册表项和 `src/api` 封装。
- 领域：各域的首次基线，以及 `canRestore`、`initial`、`restoreRevision`、`restoreError`、`restoreBlockedReason` 字段和对应的原生测试。单次写入失败后的补偿、档案应用逐次回滚和显示试用监护都使用每次操作自己的前态，不受影响。
- 触摸板与麦克风：以首次基线为参照的「设备集合已变化」禁令随之删除。它只为保护恢复记录而存在；请求仍绑定当前修订，热键仍绑定设备身份。
- `keyboard`、`touchpad`、`microphone` 的 `Scope` 同时承担档案事务期间的写互斥，予以保留：锁对象由首次基线换成专用的写互斥锁，与独显电源域的做法一致。档案持有 Scope 期间，手动写入和热键照旧等待，执行与回滚的并发语义不变。

保留的部分：独显电源请求上的 `restore` 标志表示「重放原厂恢复命令」，原厂供电模式的节点恢复同样使用，不属于初始恢复；自动刷新率的 `restore_automatic_refresh` 由开关关闭时调用，继续使用。

恢复入口曾是一些异常状态的唯一交互出口。删除后改用不依赖恢复按钮的规则：

1. **自动刷新率**：开关表示「是否仍持有启用记录」，不再只表示「策略正在运行」。已暂停、事务未完成或显示事务未完成时开关保持打开并显示原因，关闭即执行原有恢复命令。启用记录属于另一台主显示器或原厂能力已变化时仍不可恢复，这是既有行为。
2. **显卡模式未确认状态**：记录停在 Prepared 时，原实现拒绝任何新选择，只允许恢复。显卡选择是绝对值而非切换，新选择本身就是恢复，因此改为允许直接重新选择；选中与当前报告相同的模式也会实际发送并改写记录，使状态回到已接受。
3. **显卡模式落盘记录**：`initialMode` 删除，记录版本升为 2。旧版本记录作废，读作无记录，由下一次写入替换；版本更新、含未知字段、损坏或超大的记录仍然拒绝读取且不替换。

界面文案同步：删除「恢复暂不可用」「可先恢复初始设备」「当前固件未提供原模式，无法恢复」；独显详情改为「切换会请求 Windows 授权」；后端提示里「请重试恢复初始状态」「请先恢复选择记录」「可重试或恢复」等指向已删除入口的措辞改写。

## 影响与验证

- 各模块只能用自身控件切回。麦克风首次操作前的混合静音状态、触摸板系统开关与保存偏好不一致的初始组合、独显「已开启且允许自动关断」的混合初态不再能经软件还原；档案应用后同样不能回到首次基线。
- 麦克风或触摸板设备集合变化后不再禁用写入，操作作用于当时的设备集合。
- 升级后已有的显卡模式选择记录作废一次：待重启提示、重启后确认和「上次操作未完成」提示随之消失，固件端的实际选择不变，重新选择即可建立新记录。
- 后端删除的都是恢复与只读展示路径，写入、补偿与监护路径未改；自动刷新率与显卡模式各有一处行为变更（见「决定」）。
- UI 检查中经由恢复按钮的步骤改为用模块自身控件切回，并断言卡片不再出现恢复按钮；只为恢复入口存在的用例、模拟 IPC 中的 `restore_*` 处理和辅助文件 `device-settings.mjs` 删除。
- 验证（2026-11-24，全部为隔离验证，未操作真实硬件）：`cargo check --workspace --locked` 与 `cargo build --workspace --locked` 通过且无警告。`cargo test -p colorful-control-center --lib` 按 `airplane::`、`keyboard::`、`touchpad::`、`microphone::`、`display::`、`gpu_power::`、`graphics_mode::`、`profiles::`、`hotkeys::`、`command_registry::` 过滤，723 项通过、0 失败、2 项忽略。`npm run build`、`npm run check:controls`（33 项）与 `npm run verify-notes` 通过。
- UI 检查在 `HEAD` 叠加本次改动的隔离副本中运行设备配置、自动刷新率、档案与导航回归：172 项通过，2 项失败均为 `HEAD` 既有问题（`icons.spec.mjs` 的导航图标用例、`profile-refresh.spec.mjs` 的 GPU 频率文案断言），不属于本次改动。共享工作区中对本次涉及的用例聚焦运行，123 项全部通过。
- 未做真机验证：显卡模式记录的旧版本作废只用临时文件验证，未在真实应用数据目录上验证；自动刷新率已暂停状态下关闭开关只在模拟 IPC 上验证。测试构建中既有的 60 条警告全部位于本次未改动的文件，未处理。

## 备选方案

- 只删界面、保留后端命令与封装：七条命令没有调用方，属于被要求清除的技术债，未采用。
- 显卡模式记录保留 `initialMode` 字段以免改文件格式：留下无人读取的持久化字段，未采用。
- 显卡模式旧记录按损坏处理并拒绝：现有用户升级后模块永久报错且没有界面出口，未采用。
- 读不懂的记录一律作废：会连同更新版本或损坏的记录一起覆盖，削弱已有的保护，未采用。
- 自动刷新率保留恢复按钮，或删掉后不留出口：前者违背移除要求，后者留下重启也无法解除的状态，均未采用。
- 自动刷新率已暂停状态保持开关关闭但允许重新启用：用户无法在不重新启用的前提下回到干净状态，未采用。
