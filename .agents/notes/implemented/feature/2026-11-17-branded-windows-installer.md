# Agent Note: 品牌化 Windows 安装向导

Status: implemented

## 问题

现有交付只有 Tauri 默认 NSIS 界面。用户要求参考 agent-switchboard，完整实现生成图片装饰、步骤、UI 与安装结构；工作树中的硬件、导航及其他并行改动必须保留。

## 决定

- 1.0.1 发布沿用现有安装向导和标签发布流程。版本清单、锁文件与更新日志的版本条目同步。本地产物经内嵌应用及摘要校验后用于交付。

- 参考 `F:/projects/agent-switchboard/installer/` 的独立 WPF 外壳与内嵌 NSIS 机制，仅保留本项目当前需要的中文、当前用户安装契约，不引入 MSI、更新器协议或多语言框架。
- 向导包含欢迎、安装位置、执行、完成四步；按用户后续要求采用Apple风格浅白留白、55%宽度大图与短文案。用户明确拒绝双风扇题材后，重新生成透明抽象玻璃曲面图，所有旧散热装饰图片、功能介绍、标语与重复步骤状态已移除。XAML拥有原生控件样式，画刷从tokens.css生成；图片及提示词归installer/assets/SOURCES.md。
- 进度进一步收为8px小状态点，移除序号、勾号和可见步骤文字；原生Label保留完整状态名称。左侧Canvas浅灰、右侧Surface白色，以背景区分栏目，不加分隔线或额外说明。
- 右侧白色面板以28px左圆角向灰栏叠入同等距离，内容保持原对齐并按实际窗口裁切。步骤采用240ms淡入和16px方向位移，按钮及状态点柔和过渡；进度刷新不重播，快速往返替换旧动画，系统关闭动画或高对比度时直接呈现。参数由tokens.css生成。
- 主窗口外缘使用透明边距绘制一圈浅阴影。窗口尺寸包含阴影边距，内容区沿用原有可用面积，标题拖动区按内容顶部计算。
- 首次安装选择最终目录。完整且可用的旧安装原位更新，位置只读。旧安装路径不可用时说明原因，要求用户确认可用目录后重新安装。首次确认前恢复的旧安装回到原位更新，选定的目标在重试前重新校验。
- 路径确认检查本地磁盘是否就绪、目标或最近现存上级目录的创建权限、目录内容和长度。通过目录句柄查询权限，文件创建交由 NSIS。紧凑窗口优先为操作区留宽，收紧纵向间距，页脚按钮按可用空间换行。
- 真实失败日志证明已装主程序与NSIS包内文件一致，而原摘要来自另一份release程序；构建时以只读共享锁复制引擎到独立快照，再从同一快照解包并内嵌，生成唯一主程序摘要，禁止把loose release文件当作验证事实。失败日志分别记录预期/实际摘要及路径，界面不再推测权限或安全软件原因。
- NSIS 仍唯一负责文件、快捷方式、卸载注册与 WebView2 准备；外壳只验证目录、释放内嵌引擎、等待退出并核对安装结果。未知安装耗时显示不定进度，不能伪造百分比。
- 完成后用户明确选择启动或结束，安装器不自动运行硬件应用。安装过程阻止重复执行及中途关闭；失败保留可复制诊断并允许重试。
- 新构建入口输出唯一面向用户的向导安装包；原NSIS文件作为构建中间引擎。隔离验证使用真实NSIS文件引擎与独立WPF宿主，仅写临时文件，不写真实安装注册、快捷方式或硬件。
- 完整收口：错误对象与日志路径保持结构化，显示文案不承担解析协议；复制诊断包含原始异常与字段。外壳构建只有一个封装函数，先在独立目录编译/校验，再在排他锁下替换安装包和记录，失败恢复原产物。隔离测试改用真实NSIS引擎，仅写临时文件，移除C#假安装逻辑；控制进程夹具只负责占用文件。
- NSIS覆盖默认进程检查，不再强制结束持有硬件状态的进程；正常退出前拒绝安装/卸载。保留原登录启动清理，静默失败返回非零。重试复用已确认目标，返回位置页也能继续修复该次部分安装，不开放无关非空目录。
- 2026-11-18 实际两次更新均在同一路径的控制台持续运行时退出 2。NSIS 钩子的专用退出码区分运行占用与检查失败，构建将同一声明生成到向导常量。诊断保留原始退出码。
- 更新遇到占用时，向导弹出“关闭并安装”，用户取消则回到安装位置。确认后按安装目标的主程序路径、会话和主窗口标题识别主进程，再用进程 ID 和创建时间单独注册给 Windows Restart Manager，请求常规退出。主窗口标题由 Tauri 配置生成。向导用新的查询会话复查文件占用，释放后重新执行 NSIS 检查和安装。退出失败或等待超时时提供托盘退出指引和诊断。安装版使用的 Tao 0.37.2 已通过隐藏窗口夹具验证，通过 Restart Manager 正常退出时会完成清理回调。[Windows Restart Manager](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmshutdown)

- GitHub Actions 复用本地 Windows 打包和内嵌资源校验。手动运行提供候选产物，推送与 Tauri 正式版版本匹配的标签时发布向导安装包和 SHA-256。构建作业使用读取权限，发布作业仅下载同次验证的产物并申请 Release 写权限。已有发行版与草稿保持由维护者管理。

## 影响与验证

真实 NSIS 隔离验证通过 147 项断言，记录在 `target/installer-check/74d930e3fb3a40b4bc84c368fe9e0fc5/result.json`。覆盖取消保留原安装、主程序正常退出、等待恢复进程自行释放文件、同名异目录进程保护、拒绝关闭和自动继续安装。相邻 `09-close-and-install.png` 保存弹窗在 150% 缩放下的截图。隔离验证同时覆盖安装与卸载、中文和空格路径、部分安装重试、摘要、诊断、启动重试、窗口动画、目录入口和越界写入拦截。相邻 `build-result.json` 记录引擎快照、摘要校验、提交失败回滚和并发拦截。外层等待预算为 600 秒，共享冲突时重试同一原子文件操作。

当时核验的是 0.1.0 开发安装包。正式发行从 1.0.0 起，向导和 NSIS 引擎均使用 Tauri 的版本配置，桌面应用的 npm 与 Rust 版本及其锁文件同步。每次构建的版本、大小和摘要由同目录的 verification.json 记录。统一封装入口已校验AMD64、版本、五份内嵌资源和实际NSIS主程序摘要，再替换最终产物；对现有安装目录的VerifyInstallation只读调用通过。原误报证据是已装程序与包内程序一致、原摘要来自另一份release程序。当前截图和150%输出位于上述隔离宿主目录；32位NSIS工具只在沙箱外使用，正式安装、注册表、快捷方式与硬件均未操作。

## 风险

依赖 Windows .NET Framework 4.8.1 与 WPF 构建工具。真实安装涉及程序文件、卸载注册与运行时依赖，不在本轮测试中执行；安装完成后启动应用可能接入硬件，必须由用户明确点击。

## 备选方案

只替换 NSIS 位图无法完整复现参考项目的结构和交互；复制参考项目全部 MSI、更新和语言分支会引入本项目未使用的契约，因此使用单一 NSIS 引擎的原生向导。
