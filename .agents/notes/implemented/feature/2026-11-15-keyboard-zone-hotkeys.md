# Agent Note: 原厂三区开关热键

Status: implemented

## 问题

真实FnKey.Form1的139/140/141分别读取当前保存状态并切换左/中/右区；KBModule.LeftStatus/MidStatus/RightStatus只对type2执行，其他RGB键盘不能直接套用。现有总开关及亮度授权没有说明分区开关，不能隐式扩大接管范围。

## 决定

新增独立keyboardZones授权，严格绑定type2及既有灯光身份。动作通过LightingController同一Scope/Plan只改变目标分区的enabled，保留总开关、亮度、模式与所有颜色；复用既有首次基线、失败补偿、档案捕获和恢复。UI使用现有热键范围卡，说明三个按键的区域含义，默认不选；不增加第二个写入口或新的保存契约。

## 影响与验证

4项跨域内存检查通过，覆盖三个区域、总开关开/关、实际E0掩码、仅目标保存字节变化、精确首次恢复、其他型号及无效区域零输出、发送及保存失败补偿与设备替换。档案捕获沿用已有zones字段。独立授权检查通过，热键12项、灯光85项和核心事件5项通过；完整档案筛选289项通过（含11项显示领域复用，另2项需显式注入的隔离设备组合保持忽略）。

23项相关页面检查通过，3项分区直接检查全部通过；能力失效时禁止应用和旧确认提交，同时保留用户取消已选范围的既有行为。构建、边界、26项控件、主/模拟宿主编译和源码500/80限制通过。未新增依赖、保存字段或平行恢复实现。

即时灯光没有可靠物理回读，只承诺命令与保存事务结果；只使用内存和模拟IPC，不发送真实键盘灯命令或物理热键。

## 备选方案

- 将分区并入已有总开关授权：会扩大旧授权的含义，使用独立范围。
- 对所有RGB键盘开放：原厂属性只允许type2，按真实型号限制。
- 建立独立分区保存和恢复：现有Target已拥有三个分区开关，复用唯一事务和基线。
