# Agent Note: 全局滚动容器与空闲隐藏滚动条

Status: implemented

## 问题

用户要求全局滚动条组件化，参考相邻 agent-switchboard 项目，滚动条不用时隐藏。改动前 AppShell 的 main 直接 overflow:auto，显示 WebView2 默认滚动条，没有统一滚动原语与活动状态管理。

## 决定

- 沿用参考项目的 ScrollArea 固定外框与原生 viewport 分层，AppShell 唯一挂载工作区滚动容器；页面继续 keep-alive，不改页面业务与硬件行为。
- src/components/ScrollArea.tsx 唯一拥有滚动容器结构、原生溢出与键盘滚动入口；src/styles/scroll-area.css 唯一拥有滚动条与容器样式。
- src/app/useScrollActivityMarker.ts 在 App 根调用一次，以捕获阶段的被动 scroll 监听覆盖工作区及其他原生滚动面；活动标记与每个滚动面的空闲计时由该 hook 唯一拥有，卸载清理监听、计时器与标记。
- 原生滚动条保留透明轨道与固定槽宽，滑块默认透明；滚动时显示，停止 900ms 后隐藏，悬停或拖动滑块仍可见。保留原生滚轮、键盘与滑块拖动行为，不增加依赖。
- 滚动条尺寸、浅深主题颜色与空闲延时由 tokens.css 唯一定义；WebView2 不支持原生滑块伪元素的颜色过渡，按参考项目即时显隐。

## 影响与验证

- 移除工作区直接 overflow:auto 的旧路径，工作区与后续局部容器统一接入 ScrollArea；其他原生滚动面共享全局样式与活动监听。
- npm run build（TypeScript、3 页边界检查、Vite）与 cargo check 均通过；笔记迁入 implemented 后重新执行 npm run verify-notes。
- 浏览器通过实际原生 scroll 事件与标记清除事件取样：工作区滚动时显示浅色滑块，约 905ms 空闲后恢复透明；独立原生 textarea 同样显示，并在约 902ms 后隐藏，确认全局捕获覆盖非组件原生滚动面。
- 验证 900×560 应用容器：工作区外框保持完整圆角裁切，内部 viewport 高 492px；固定槽宽 10px，显隐前后内容宽均为 662px，顶栏、侧栏与文档根节点不随内容滚动。
- 浅深主题滑块颜色读取分别为 rgba(20, 22, 27, 0.26) 与 rgba(232, 233, 236, 0.3)，均来自主题令牌。
- 原生 PageDown 能滚动工作区，所记录滚动事件都保持活动标记；原生鼠标拖动滑块将 scrollTop 从约 221 改为 24。
- 切换至无内容溢出的性能档案页再返回控制台：viewport 节点与控制台页面节点保持不变，保留 main 的中文可访问名称与页面 keep-alive 接线。
- 内置预览截图超时，悬停／拖动状态的视觉核对与桌面 WebView2 视觉检查未完成；不将 CSSOM 的悬停伪元素读取作为视觉通过证据。原生拖动动作已验证，没有硬件写入。
- 临时布局、主题与测试 textarea 均已恢复或移除；验证使用独立 1437 预览端口，未修改项目配置或参考项目。

## 备选方案

- 仅修改工作区的默认滚动条样式：没有共享组件，也不能覆盖后续原生滚动面，放弃。
- 手写替代滑块、拖动与键盘逻辑或引入滚动条依赖：当前原生机制足够，增加不必要的复杂度，放弃。
