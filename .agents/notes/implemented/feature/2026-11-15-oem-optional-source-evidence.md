# Agent Note: TP、Deep S5与XMP原版活动范围

Status: implemented

## 问题

路线仍把TP独立颜色、Deep S5和XMP写入列为待追踪。已读反编译中有TP保存字段、XMP结构和Deep S5状态，但字段存在不证明有设置入口，也不能仅凭文本搜索无结果宣称不存在。

## 决定

tools/research/audit-oem-il.py对本机载荷及Pi会话对应的原厂程序集每次重新静态提取IL，记录程序集及IL摘要，逐方法汇总实际指令引用。TP核对能力字段、初始化/保存调用者及即时颜色选择器；XMP核对WMI18解码数组与公开MemoryData的消费者；Deep S5核对状态生产者和睡眠消费者。输入缺失、截断、方法歧义或新增消费者拒绝旧结论，失败覆盖旧报告为ok:false；不执行原版入口、DLL、驱动或系统查询。仅接受明确ilspycmd和原程序集输入，不保留旧IL文件输入模式。

## 影响与验证

9项隔离脚本检查通过：拒绝残缺输入、相似字段/方法误匹配、反射字符串、未知TP调用/委托、额外颜色选择器、新XMP消费者及Deep S5生产/消费变化。Python AST检查确认文件不超过500行、函数不超过80行。实际原程序集重新提取成功，FnKey 2267、CPUOC 542、LedKeyboardSetting 802个方法；报告在target/ui-check/oem-optional-evidence.json，包含完整输入SHA256及指令行号。

当前版本SupportTpColor无活动指令引用，TP属性赋值只来自FirstRun/ReadAllReg，保存调用仅来自属性和WriteAllReg；SetColor活动调用仍为三区/Logo/灯条的F0/F1/F2/F3/F6选择器。公开XMP数组无引用，私有时序/电压字段限解码方法；Deep S5状态只由GetDeepS5Status生产、WndProc消费。结论不把共享保存成功算作即时控制，也不排除其他组件。原版已确认活动内存频率另由硬件参数笔记拥有，已接入自研监控。

## 风险

结果仅适用于记录摘要的版本，不证明硬件永远不支持；动态加载组件及其他固件不能从这些程序集外推。界面资源仅静态检查，枚举常量、保存记录和未消费数组不当作可用控制。

## 备选方案

- 从字段或相邻命令号猜写协议：没有实际调用依据。
- 因缺真机验收停止其余工作：用户明确不调试硬件，继续静态、编译和隔离验证。
- 保留无边界的“待研究”：以版本证据明确范围，不扩大为所有版本的结论。
