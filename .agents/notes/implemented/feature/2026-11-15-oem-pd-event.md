# Agent Note: 原厂 PD 档位事件46

Status: implemented

## 问题

Pi 会话 FnKey 7.19.5.0 的 `Form1.cs` 2569–2570 在 Arg001 46 调用 `Features.Set_PD_Power_level(1)`；该方法以 cmd4/sub55、第二字节1发出PD等级请求。现有PD页及性能档案已实现相同传输、实际能力与初始恢复，但热键事件没有独立授权和执行链。

## 实现

- 把46接入独立范围，预览明确为原始编号1及当前适配器/候选；编号0起与1起的用户显示语义分别说明，不将原始1统一标为第一档。仅设备当前报告有效、候选包含1且校准互斥允许时提供能力，旧授权绑定编码、适配器与完整候选，不绑定会随事件变化的当前档位。
- 与单项PD和档案共用同一Controller、写锁及首次基线。等待控制锁之后、实际输出前重查许可、原厂控制者、目标与当前状态；写后回读，失败恢复并保留可重试初始值。恢复沿用已有PD页面的完整预览确认，不新增第二套恢复记录或传输。
- 不将事件46与低电量阈值209/210、动作44/45、低电量屏幕策略59/60或充电阈值授权合并，也不因为方法名而推断适配器协商功率。

## 验证范围

在内存固件与模拟IPC中验证两种旧编号、适配器能力、候选无1、来源/旧确认变化、写入失败回滚、重复事件、共享初始基线、校准阻止、许可撤销及页面确认；真实固件与供电不调试。

## 风险

设备提供的值1在零基和一基中对应不同显示位置；适配器变化可令初始等级不再合法，不能强行恢复。Windows或固件调用阻塞时，取消等待的时效不能由隔离检查证明。

## 备选方案

- 直接发送原始WMI包而绕开PD控制器：会形成第二套基线并跳过能力和恢复校验，拒绝。

## 决定

新增独立事件范围和双模块预览，输出使用原PD控制器持锁后的同一Plan；恢复先停止监听，再复用单项恢复。候选或适配器改变时撤销执行资格，不能恢复的初始基线不允许继续覆盖。

## 影响与验证

20项PD领域、15项平台档案、86项热键、11项核心事件和28项相关模拟页面通过；最终PD及电池页面10项重验通过，宽窄深浅布局已检查。覆盖两类旧编号、适配器变化、目标无效、锁后许可撤销、失败补偿及首次基线；构建、模拟宿主、控件和源码限制通过。没有调用真实PD、DCHU、OutLog或系统电源操作，现有阶段安装包不包含本功能。
