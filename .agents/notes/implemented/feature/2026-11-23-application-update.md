# Agent Note: 应用内检查更新

Status: implemented

## 问题

用户需要在任意工作区检查 GitHub 新版本，并从应用内下载和打开已验证的安装向导。

## 决定

- 参考 Agent Switchboard 的 Tauri Updater 与 GitHub Releases `latest.json`，由原生端拥有已检查版本、下载取消和签名验证。清单版本须与签名中的版本一致。
- 侧栏和关于页按需检查 GitHub 更新清单。两个入口首次查到新版本时直接打开详情，关闭后可从原入口重新查看候选。侧栏直接显示已是最新版或检查失败，点击失败结果可查看原因。关于页在检查完成后显示结果。折叠侧栏通过图标和提示表达同一状态。
- 采用 FlClash 的确认布局。标题为「发现新版本」，正文从新版本号开始，分组说明可滚动，底部固定「取消」和「更新」。共用应用的弹窗、按钮、主题和 Markdown 渲染。 [FlClash 更新逻辑](https://github.com/chen08209/FlClash/blob/v0.9.5/lib/providers/actions/common.dart#L110-L180) · [Prism UI 弹窗](https://github.com/chen08209/prism_ui/blob/cae9a43572bddb9b20b9350ef7fde3f434a758c7/lib/dialog.dart#L381-L502)
- 应用层唯一持有更新操作、版本读取和详情弹窗。点「更新」关闭确认弹窗并开始后台下载。侧栏和关于页共用进度，重新打开详情可取消或重试。
- 更新载荷使用已经发布给用户的 Windows 安装向导。下载确认后由向导继续处理同目录覆盖安装、程序占用、正常退出及升级后的启动。
- 标签发布用 Colorful Control Center 专用签名密钥生成清单和签名，正文保留下载表格，清单更新说明来自同一版 CHANGELOG。

## 影响与验证

- 检查新版本、已是最新版、失败重试、取消和安装向导交接。
- 验证两个入口发现新版本时直接打开、关闭后保留候选、长说明滚动时操作持续可见，以及折叠侧栏的键盘焦点。
- 验证确认后跨页查看下载进度，在同一会话中取消、重试、查看签名错误和安装向导状态。
- 在隔离环境验证签名、版本绑定和发布清单。真机覆盖升级另行按验收清单记录。

## 备选方案

- 直接调用 Tauri Updater 的 Windows 安装逻辑会绕过控制台现有的退出与恢复协作。使用已校验的 WPF 安装向导完成交接。
