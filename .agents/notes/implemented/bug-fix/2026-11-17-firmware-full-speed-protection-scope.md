# Agent Note: 固件全速与软件曲线的监护范围

Status: implemented

## 问题

用户截图在99°C选择全速。监护参数顺序修复后，所有非自动模式仍共用95°C拒绝条件；诊断准确不等于全速功能已修复。

## 决定

原厂FnKey/Form1.cs事件143显示osd_fan_speed_max并调用Fn1_ChangeFanMode(1)。FnKey.Device/FAN.cs的Write_SituationalMode_of_FanData把1转为0写入分模式槽，表明全速为临时最大散热选择。复用原厂121/1及已核对固件通道；软件曲线仍使用95°C熔断。

HAL监护生命周期集中到hal/fan_guard.rs。唯一子进程用PREPARE_FULL_SPEED与COMMIT_FULL_SPEED交接：准备最多3秒、重复准备及心跳不能延长；固件命令与保存值回读成功后提交，子进程独立检查page4[5]==1。确认后仅豁免Overheat；传感器失效、失联、心跳超时及准备超时仍恢复自动。保存模式离开1即撤销豁免，不把保存值当作物理转速验证。

转回受保护策略先检查实时温度，明确拒绝不改变原全速策略、不发送目标写入；拒绝有独立错误类型，传输故障转为待恢复。返回自动使用同一监护的限时PREPARE_AUTO窗口，自动写入确认后解除，避免高温下保存值刚变0就被旧策略误判失败。模式、偏移、首次/事务恢复及模式组合共用策略；软件曲线始终Protected，不因保存模式1绕过熔断。没有新增用户配置或前端特例。

恢复期间保留句柄并关闭心跳，确认旧子进程退出后父进程才补偿；解除失败不清除待恢复状态，不让旧监护后续覆盖新全速目标。普通退出的既有固件设置持久语义不变，软件曲线退出释放与故障锁仍由原所有者负责。

## 影响与验证

直接消费者及隔离工厂同步传递策略，旧无策略调用签名移除。13项原生监护检查、13项GUI进程检查和20项软件曲线/固件/档案组合检查通过。覆盖99°C全速持续、准备超时、传感器/模式丢失、父进程强杀、软件曲线切换、热时拒绝降低散热、全速回自动、偏移、首次/事务恢复、旧监护恢复中禁止新写入及恢复后重新控制。进程和DCHU桩只使用私有临时文件，不访问真实设备。

构建与工作区检查、控制权进程检查、包与源码一致性校验作为同次交付门槛。物理转速、真实驱动响应和硬件效果未验收，不作为停止代码实现的条件。

## 风险

原厂命令成功及保存值回读不能证明物理最大转速。传感器/驱动故障仍可能导致恢复失败，保留错误并继续重试，不自动重启故障软件曲线。

## 备选方案

拒绝关闭全局温度保护、静默把全速改成自动或要求用户先手工停止软件曲线；也不启动第二个监护与旧恢复并发。
