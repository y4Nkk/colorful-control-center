# Agent Note: 刷新率独立恢复进程

Status: implemented

## 问题

现有15秒刷新率试用依赖主进程线程，主进程被强杀时恢复无法继续。用户要求继续完成原厂功能复刻及完整恢复，不调试硬件。

## 决定

- 模式数据与纯传输契约归 display/model.rs；主控制器继续拥有预览/初始基线，子进程只拥有本次试用恢复目标。
- 使用同一可执行文件的独立入口、标准输入输出管道及 READY/ARM/保留确认协议；监护就绪后才允许显示写入，子进程保留既有控制权租约，旧恢复结束前不能启动另一控制者。
- 倒计时使用 Instant 单调时钟；超时、管道断开或父进程消失时恢复捕获模式，失败重试并报告。保留请求在期限内验证实际模式后解除监护；原始快照不通过命令行或临时文件传递。
- 监护不持有主进程 HAL 写锁，避免其他阻塞传输影响显示恢复；同时保留独显 UAC 与显示试用的互斥。
- 测试复用实际管道客户端和子进程状态机，仅把恢复出口替换为隔离目录日志，不调用 GDI、PnP、HID 或 OEM DLL。

## 影响

- 内存状态机验证超时、保留、拒绝旧目标、断连与恢复重试；真实隔离进程验证强杀父进程、子进程退出、超时恢复及租约保留。
- 页面确认/试用/保留/恢复契约同步，旧字段不残留；前后端编译及相关聚焦检查通过。

## 风险

系统显示驱动调用仍可能阻塞；独立进程只能隔离主程序死亡或卡顿，不能以隔离测试证明真实驱动可恢复。

## 影响与验证

- 显示域9项内存测试、display_process 7项真实隔离进程测试通过；恢复出口仅写临时文件。覆盖监护启动失败、写入期间过期、父进程强杀、子进程提前退出、错误保留目标、恢复重试及控制权释放。
- 实际页面1项模拟 IPC 检查通过，验证 remainingMs 倒计时、二次确认、保留、超时回退和初始恢复；测试在独立本地 Vite/Edge 中执行，不启动生产应用。原沙箱运行未能连接测试服务，终止后在获准环境重跑通过。
- npm run build 通过；未执行真实 GDI、PnP、UAC 或硬件操作。编译不代表显示驱动的物理恢复验收。

## 备选方案

- 仅继续主进程定时器：无法覆盖主进程强杀。
- 任务计划程序或落盘启动脚本：引入持久系统状态且恢复目标易过期，拒绝。
