# Agent Note: 逐键动态灯效、原厂键位与事件链路

Status: implemented

## 问题

现有逐键请求只有亮度和120色矩阵，原动态模式只能恢复。kbled 6.26的PerkeyKB定义经典/新MCU波浪、呼吸、闪烁、随机、扫描、蛇形、涟漪和Fn效果；已安装FnKey的perkeyhook另外负责按键事件发送。单发模式命令不足以完成按键涟漪和Fn提示。6x20矩阵不是物理键帽布局，大键还包含多个LED位置。

## 决定

- 沿用lighting/perkey作为唯一设置、快照和恢复所有者；替换旧静态专用请求为完整当前契约，不保留平行静态写入入口。模式、亮度、速度及实际适用参数绑定设备/MCU能力/保存值的预览修订。
- 从已安装包提取并静态审查perkeyhook、MCU查询和BAML范围/键位信息；不执行原厂初始化、ClearColor或助手。查询采用有界16字节HID报告，不照搬原DLL的越界读取。
- 动态选项按MCU声明能力开放，颜色/方向/速度只接受原厂有效值；保留不属于本次目标的动态参数、矩阵填充和其他灯光字段。状态回读表示保存值，不声称物理效果已生效。
- 按键涟漪/渐灭/Fn使用原厂已确认的事件编码；事件回调只投递有界数据，硬件发送不在键盘回调中执行，不记录按键文本。设置确认前不启动效果写入；失败、退出与切换关闭旧会话，恢复按原始目标准备新会话。暂停事件代次使旧队列失效，线程回收在释放HAL锁后执行。
- 自研键帽布局表达实际大小及对应LED位置，选择/上色仅改草稿；能力和布局未知时显示明确诊断，不冒充已识别。沿用全局Surface/Button/Select/Slider/Input等原语。

## 影响与验证

替换旧静态专用IPC，Rust/TypeScript/页面/夹具使用同一Values/Pattern契约。恢复只写逐键所属字段，保留睡眠和其他灯光的新值。BAML确认速度0..2；16种物理布局事实由离线纯属性桩生成，窄边框空格映射4灯位，ISO Enter映射3灯位。全局Button新增keycap变体，外观仍由button.css拥有。

19项逐键原生内存检查、此前11项分区/白光检查，以及5项逐键和2项键盘设置页面检查通过；页面覆盖全部16个布局分支。构建、主工作区/control-sim编译和25项控件检查通过。模拟模块补齐Windows消息API编译特性，未新增运行时依赖。测试未安装键盘钩子、打开HID或运行生产应用。

事件源是原厂Windowshook使用的WH_KEYBOARD_LL；HKFltrLib不在此事件链路，不引入过滤驱动。已静态核对gamefeet/perkeyhook的扫描码、50ms Win延迟、Copilot组合、重复键过滤及Fn灯位列表。新/旧MCU选项按能力限制；动态黑色不暗改红色，扫描允许单端黑色。

## 风险

MCU命令无即时效果回读，原厂后台可能同时控制设备；键盘事件来源与布局必须以安装包为依据，不用截图猜LED编号。物理灯效和按键响应本轮不验收。

## 备选方案

- 给现有120色网格加灯效下拉但不接事件：不能完成按键效果，拒绝。
- 用原厂GetMcuVersion初始化读取能力：旧实现会清空灯色，拒绝。
- 固定另一型号键盘或推测速度上下界：缺少本机原厂证据，拒绝。
