# Agent Note: 原厂热键接管与自研OSD

Status: implemented

## 问题

软件全局唤起快捷键不是原厂FnKey事件；现有控制域没有统一消费Arg001、串行执行和全屏显提示。直接把每个OutLog文本都当请求会重复执行，也会把电池通知或关机事件误当快捷操作。

## 决策

- 本次补齐FnKey已确认的只读状态事件：166/167扩展坞连接/断开、184/185 GPS关闭/开启、199/200数字锁关闭/开启、201/202大写锁关闭/开启、203/204滚动锁关闭/开启、222/223 寂静模式开启/关闭（原厂 SILENT ON/OFF 图标为风扇）、234/235移动网络关闭/开启。OsdForm的SCR LOCK文案确认203/204不是屏幕开关。新增独立stateNotifications授权，默认不继承现有范围；通知只发布原厂报告，不执行领域写入或发hardware-controls-changed。
- 64号除尘运行与58号Turbo风扇同属纯状态提示，共16个已确认通知事件。301–304虽有switch分支，但OutLog入口先取低字节，不能作为直接Arg001事件映射；相机事件另含page1[6]保存副作用，不混入只读范围。原生属性枚举使用NONSYSTEM_ONLY以对应ManagementObject.Properties，排除可能含USB文字的系统路径/主机名；保留成功HRESULT区分枚举结束，VARIANT由当前windows依赖的Drop释放。
- 数字锁沿用Features.IsUSBKeyboardExist条件：通过本地root/cimv2的Win32_Keyboard只读属性枚举识别大写USB字符串，有USB键盘时不显示数字锁通知。其他通知不枚举设备，查询失败保留具体诊断而不假装无USB。原厂控制者存在仍统一拒绝监听；通知与其他动作共用现有策略文件、预览确认、临时停止和首次软件策略恢复，不新建通知后台或策略副本。原生枚举只编译，测试必须显式注入，不能回退系统查询。

- 原厂来源为本机FnKeyPack 7.19.5.0的Form1.Arg001_GetEvent及Features/KB/FAN对应处理函数。共享hal/event_log只负责记录顺序和只读订阅；ccc-core拥有Arg001的有符号32位解码、动作分类及原厂模式事件3秒抑制。校准与宏程序事件保持各自精确筛选，不把clevofnkey状态通知再次执行。
- 控制台先展示明确动作范围，启用接管需预览确认；默认不启动写入型热键，原厂控制者存在时不接管。物理按键是已授权动作的执行触发，不在后台另造直接命令。模式、风扇、Fn锁、映射和灯光均复用领域事务及恢复基线，互斥和能力变化导致拒绝并报告。
- 授权持久化绑定所选范围及稳定能力/设备身份；模式和风扇明确授权“使用执行当时已保存的设置”，页面草稿不参与。实际执行重新读取并绑定领域预览，原厂参数变更仍由既有能力校验及事务处理。映射只切换本应用已接管设备，授权还绑定动作内容摘要，启用状态翻转不改变摘要。
- hotkeys拥有严格版本化策略文件、首次软件策略基线、监听状态及事务；保存失败或新监听准备失败时保留/恢复旧策略与诊断。临时停止只停止本次监听，不改硬件；策略恢复与各硬件域初始恢复分别呈现。默认配置不启用，重新启动只恢复已授权且能力匹配的策略。
- 稳定软件策略、订阅生命周期与本次运行状态分开；变更策略及退出停止旧订阅，重启监听从日志尾开始，不补放历史动作。队列串行消费，不能持有HAL控制锁等待UI线程；错误保留原因，不能把写失败显示成状态已改变。
- 自研OSD是应用级单一Host，独立透明、置顶、无焦点、鼠标穿透窗口；只显示动作结果和可确认的状态，主窗口隐藏时仍可提示。采用现有Surface、令牌与图标，不复制原厂图片、不用toast冒充桌面OSD。创建与销毁由app层拥有，业务只发布类型化提示。
- OSD序列号防止旧的显示/隐藏任务覆盖新消息，显示成功后开始单一计时线程；IPC入口只允许osd窗口读取屏显状态，不允许其调用硬件命令。独立前端入口不挂App、监控或控制器；只读快照携带外观子集，复用现有外观应用函数。
- AC/DC、盖合、睡眠、校准及关机类事件不是普通热键，保留独立类型和路由；不因接管热键而自动授权关机或切换MUX。
- 热键动作通知由控制台统一刷新相关域；读取更新未编辑的草稿，保留未提交修改，读取失败撤销可执行快照。开发模式重挂载及刷新时等待旧读取结束后再取最新事实，避免取消首读后永久停在加载中。页面隔离服务器显式加载React配置并关闭文件监听，不合并生产开发服务器的watch对象而误监听编译产物。
- 已接通OutLog精确来源、十一类已核对动作的领域事务、策略保存/监听激活/失败补偿及控制台。首次软件基线在可能修改监听或文件之前保留，补偿失败仍可显式重试；不把停止监听称为硬件恢复。共享原厂控制者检查移至hal/oem_owner，移除宏私有扫描路径。
- OSD等待WebView加载后才显示并开始2800ms计时，pending/序号/状态修订同时隔离重复显示、旧计时和迟到读取；外观、渲染加速分别复用已确认偏好及本次运行配置。OSD前端只读取状态，中央IPC窗口限制与最小事件权限共同生效。

麦克风静音与端点事务见同目录2026-11-15-microphone-control.md，38号事件单独授权，读取不初始化原厂偏好。

键盘灯总开关与type38补充见同目录2026-11-14-keyboard-switch-hotkeys.md；开关单独授权，不扩大原亮度授权范围。

## 风险

没有读取真实OutLog、触发物理热键、安装钩子、操作硬件或创建原生OSD窗口；DPI/多屏、隐藏主窗口的提示与实际退出清理仍需独立桌面验收。当前范围为十三类控制动作、独立状态通知和摄像头反馈，其余原厂事件分支仍按真实执行链核对；读取保存字段不等于物理状态。

## 备选方案

- 仅注册通用全局快捷键：不能代替原厂固件事件，拒绝。
- 所有OutLog消息自动映射动作或启动时重放旧消息：会重复执行通知或历史请求，拒绝。
- 复制原厂OSD图片或仅用主窗口toast替代桌面提示：不满足自研及隐藏窗口时的屏显语义，拒绝。

触摸板252/253的I2C切换分支已复用同一领域事务及完整档案，原始状态与偏好独立；详见2026-11-15-touchpad-control决策笔记和docs/touchpad-contract.md。

139/140/141三区开关以独立keyboardZones授权接入；只允许KBModule原始属性实际支持的type2，复用灯光Scope/Plan及已有档案字段。见2026-11-15-keyboard-zone-hotkeys决策笔记。

57号颜色循环以keyboardColor独立授权接入，序列位置与颜色由既有lighting基线统一恢复，完整档案继续复用All字段。见2026-11-15-keyboard-color-cycle决策笔记及keyboard-contract.md §16。
