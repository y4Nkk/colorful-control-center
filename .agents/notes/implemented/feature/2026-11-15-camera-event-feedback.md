# Agent Note: 原厂摄像头事件反馈与保存同步

Status: implemented

## 问题

本机FnKey.Form1.Arg001_GetEvent的246/247/248/249尚未接入。246/247调用Features.WriteCCDValue(0/1)，249调用WriteCCDValue(1)，仅写page1[6]；248只显示复合关闭提示。Features.SetCCD另有SetWMI(34)设备控制，事件分支没有调用它，不能把报告当作摄像头或麦克风开关命令。

## 决定

- 新增独立cameraReports范围，已有状态通知和麦克风权限不自动扩大；保持默认关闭、预览确认、临时停止和初始软件策略恢复。
- ccc-core拥有四事件的语义及精确缓存副作用，hotkeys/camera_report唯一拥有page1[6]事件镜像。读配置只核对可读取性；执行时在共享HAL事务锁内读前态、按需同步、回读，失败只补偿这个字节并保留原始诊断。未知前值原样保留，其他page1字段不得改动。
- 不调用SetCCD、SetWMI(34)、Core Audio或设备管理；不为固件先前执行的动作创建硬件恢复基线。软件策略恢复还原初始规则，由原规则决定后续接管，不把已同步的真实报告改回旧缓存。
- 原版246/247在CC40存在时不显示，既有全局原厂控制权检查会在CC40存在时阻止接管，沿用该边界。统一运行时发布最后结果和可选OSD，此类反馈不发布硬件控制刷新。

## 影响与验证

28项热键/反馈检查与7项核心事件检查通过，包含6项摄像头领域及3项独立权限/软件恢复检查。覆盖逐事件矩阵、零设备命令、共享字段、未知前值、幂等、读取/写入/回读/补偿失败、失效授权，以及初始规则已启用时恢复后继续接管。新增6项模拟页面最终通过，另22项相关页面通过；覆盖确认、失败重试、能力变化、默认关闭、范围恢复和深浅360/760/1440px布局。前端构建、主程序及control-sim编译、441个Rust/279个前端脚本限制和笔记检查通过。日志在target/ui-check/camera-feedback-{hotkeys-final,core-tests,ui-final,cargo-check,sim-check,build-final}.log。

## 风险

原厂事件是报告，不能证明当前Windows摄像头或录音端点状态；同步回读仅证明保存值。测试仅显式内存FFI与模拟IPC，不消费真实事件、不访问实际设备。

## 备选方案

- 把246/247/249归入既有只读通知：会隐式扩大旧授权的保存副作用，拒绝。
- 收到事件后执行摄像头或麦克风开关：重复执行固件动作且偏离原版调用链，拒绝。
- 为报告镜像建立硬件基线：会在恢复时把真实报告覆盖为旧值，拒绝。
