# Agent Note: 档案与启动选择的完整文件替换

Status: implemented

## 问题

profiles::save 与 startup::set_profile 直接使用 fs::write 覆盖目标 JSON；打开目标会先截断，写入错误或进程中断可能破坏已有档案或启动选择。Windows 文件名校验还漏掉了 COM¹/²/³ 和 LPT¹/²/³ 设备别名，不能将它们作为普通档案文件路径。

## 决定

- storage.rs 唯一拥有完整文件替换：在目标同目录用 tempfile 建立唯一临时文件，写入完整字节并 sync_all，然后 persist 原子替换。不先删除、截断或修改原文件，不新增备份格式、兼容读取或第二份业务数据。
- 档案保存/导入和启动选择均复用该入口；先完成原有校验与序列化。错误包含原始文件系统原因，可在 UI 看到。文件布局、JSON schema、时间戳及档案语义保持原契约。
- tempfile 3.27.0 已在桌面锁文件中，增加直接依赖以复用随机命名、排他创建、Windows 替换及正常失败清理，避免自行维护临时文件机制。
- 实际并发读取检查复现 Windows 提交阶段错误 5。仅对替换阶段的错误 5/32 保留同一完整临时文件，最多额外重试 8 次、间隔 5ms；耗尽返回原始错误，不转为原地覆盖。被持续占用时仍应失败并保持原文件。
- 将现有目录读写函数拆出可传入隔离路径的薄入口，不启动 Tauri 或读取真实用户目录。补齐 Windows 保留设备名称校验，保存、导入和读取共用同一校验。

## 影响与验证

- COM¹ 漏检先在原实现上复现；修正后覆盖六个上标别名及扩展名/大小写，合法中文上标和 COM10 仍可用。
- 原生 storage:: 5 项、profiles:: 25 项、startup:: 4 项通过。覆盖实际文件占用后保留旧内容、解除后重试、正常失败清理、32 次更新的并发完整 JSON、档案保存/加载/覆盖、临时文件忽略及损坏数据拒绝。并发测试先确认旧版本读取，再等待最终新版，不能只在写完之后检查一次。
- storage_process 2 项真实进程强杀通过：提交前旧档案不变、首次保存不发布半文件，均可随后提交新完整内容；只写本次唯一目录，确认子进程退出后清理，失败保留日志。
- 保存/列表/读取/删除命令保留完整错误链，移除档案与启动选择的原地覆盖路径。npm run build、cargo check --workspace、18 篇笔记校验与 diff --check 通过；源文件 ≤500 行、函数 ≤80 行。
- NSIS 构建及 7z t 完整性通过：1897721B，SHA256 fbbd85d411cecaa7c42ba9b9aa0f245401eb6cfba140ee07cba6a0e77815fd2d。未安装、启动应用，未修改真实用户档案、注册表或硬件。

## 风险

进程被强杀可能遗留未提交临时文件，它们不进入档案列表；不能仅凭该机制宣称断电或存储设备故障恢复已验证。不清理未知文件，不修改真实档案或注册表进行验收。

## 备选方案

- 继续原地覆盖并在失败后重写旧内容：中断时仍会破坏原文件，不采用。
- 每次维护 .bak 和多版本读取：增加第二份事实来源和恢复分支，不采用。
- 自行拼接 PID 临时文件名：需要维护重名、崩溃残留和系统替换细节，采用现有 tempfile 实现。
