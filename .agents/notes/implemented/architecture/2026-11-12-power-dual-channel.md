# Agent Note: Phase 3 双通道性能调校与档案事务

Status: implemented

## 问题

Phase 3 要求 PL1/PL2、undervolt、GPU 偏移及一键档案。page6 保存与 MSR 即时值含义不同，不能混用；原档案只有保存语义，未实现即时 CPU 切换，逐参数调用也会留下部分成功状态。

## 决定

（2026-11-12）

1. **双通道**：控制台同组滑杆选择即时或保存；各自的一次确认提交整组变更，分别使用 MSR 计划或 page6 字段事务，首错停止并恢复。桌面 MSR 由 HAL 统一创建，测试只能注入内存传输。
2. **范围**：PL 35–157 W，保存为整数、MSR 按 RAPL 单位编解码；核心 −150…+50 mV、GT −150…0 mV，以最近 Mailbox 编码执行并精确回读/恢复。
3. **档案**：顶层原字段仍是保存值，runtimeCpu 保存即时 PL 与电压编码。全量预检后依次执行 OEM 模式、风扇、保存值、即时 CPU、GPU，首错停止；恢复 GPU/保存值/OEM 模式之后再恢复 CPU 和风扇。手动应用绑定完整已预览内容，自启复用同一执行事务。详见 implemented/feature/2026-11-12-profile-runtime-cpu.md。
4. **GPU**：NVAPI 已实现，原始 kHz 快照、范围校验及恢复由 gpuctl/hal::nvapi 拥有；不能把 page6 的 GT 电压当作独显时钟偏移。

## 影响

- 即时可行性仍需实际设备回读；probe 默认不安装驱动、不重启服务、不执行电压测试。page6 成功只证明保存，不保证消费时机或重启效果。
- 档案已覆盖即时 CPU，保留原保存字段的含义；不能把离线模拟当作本机 PL/降压结论。
- 移除拆分的 PL/电压 IPC，控制台/性能档案使用现有三页入口和同一底座；新事务决策及验证见上述笔记。

## 备选方案

- **仅持久化通道**：零驱动依赖；但用户无法即时验证效果（生效时机黑盒），undervolt 调参体验差。补运行时通道。
- **仅运行时通道**：即时生效；但 page6 不写则重启丢失，且强依赖 PawnIO。双通道互补。
- **用 NVML 调独显偏移**：本项目采用已核对的 NVAPI 接口，NVML 保持监控用途。
