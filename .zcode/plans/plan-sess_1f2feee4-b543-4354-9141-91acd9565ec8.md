# colorful-control-center 底座与规范搭建方案

## Context

继承会话决定：动工功能代码前，先搭好「全局底座 + 规范」。参考两个项目的成熟实践：agent-switchboard（Tauri 同栈、极简自研底座、契约式文档）与 spiralcoder（可执行规范、决策笔记体系）。已确认三项决策：**极简自研底座 / 中文单语 / 决策笔记完整版**。

两参考项目的「全局化 → 模块接入」核心模式一致：全局能力 = 模块级单例 store + 命令式 API，app 层唯一挂载 Host；模块位置只 import 调用。本方案将其落地为固定的接入点与接入步骤。

> 之前断点的 Phase 0 探测工具（WMI 枚举 / probe-cli）顺延到底座完成后再做。

## 二、前端全局底座（零新依赖，agent-switchboard 同款）

```
src/
├── styles/tokens.css      # 唯一令牌所有者（头注释声明）：--ccc-* 前缀，
│                          # 浅/深双主题语义变量（data-theme 切换）、
│                          # 圆角/间距/字阶/动效（400ms+reduced-motion）、40px 控件高
├── styles/base.css        # reset + 全局硬约束（焦点环、滚动行为）
├── api/client.ts          # 唯一 invoke 边界（头注释契约）+ re-export 聚合
├── api/shared.ts          # CommandError 类型
├── api/app.ts             # backendInfo() typed wrapper
├── components/use-toast.ts # 全局通知单例 store（memoryState+listeners+dispatch，
│                          # 命令式 toast() + useToast()；简化自 agent-switchboard，去 i18n）
├── components/Toaster.tsx  # 全局唯一渲染 Host（app 层挂载）
├── app/navigation.ts       # PageId + PAGES 注册表 + 中文标题映射
├── app/AppShell.tsx        # 外框 grid：侧栏导航(40px 项/20px 圆角/选中态令牌) + 顶栏 + 工作区
├── app/AppWorkspace.tsx    # keep-alive：visited Set + hidden 切换（复刻 AppWorkspace.tsx:14-55 模式）
├── app/{Dashboard,Fans,Performance,Profiles,Settings}Workspace.tsx
│                           # 5 个占位 Workspace = 模块接入点（Phase 1/2/3/3/4）
├── App.tsx                 # composition root：AppShell > AppWorkspace + <Toaster/>
└── main.tsx                # 引 styles + 挂 App
```

**冒烟验证点**（同时也是「模块接入全局服务」的模式示范）：DashboardWorkspace 调 `backendInfo()` 显示后端版本（验证 IPC 全链路）；SettingsWorkspace 一个「测试通知」按钮调 `toast()`（验证模块→全局服务接入）。

**删除模板残留**：`src/App.css`、`src/assets/react.svg`、`App.tsx` 模板代码。

## 三、Rust 底座（src-tauri/）

- `lib.rs`：清除模板 greet；`mod commands / command_registry`；`run()` 组装
- `command_registry.rs`：macro_rules! 集中注册所有 IPC 命令（复刻 agent-switchboard 同名文件宏模式，实现时读其实现）
- `commands/mod.rs`：命令层契约头注释（薄委托：参数校验 → 领域模块）
- `commands/app.rs`：`get_backend_info` 命令（返回 version/name），作为唯一初始命令验证通路

## 四、可执行规范

`scripts/check-boundaries.mjs`（挂 `npm run check:boundaries`，进 build 链 `tsc → check → vite build`）：
1. `invoke(` 与 `@tauri-apps/api` import 仅允许出现在 `src/api/`
2. `--ccc-*` 自定义属性定义仅允许在 `src/styles/tokens.css`
3. PAGES 每个页面 id 必须在 AppWorkspace 有对应 Workspace 分支

（脚本思路参考 spiralcoder `web/scripts/check-css-ownership.mjs`，实现时读）

## 五、验证

1. `npm run build`（tsc + 边界检查 + vite build）通过
2. `cargo check` 通过（已验证脚手架本身可编译）
3. `node scripts/verify-notes.mjs` + `check-boundaries.mjs` 通过
4. `npm run tauri dev` 目检：侧栏 5 页切换 + keep-alive；仪表盘显示后端版本（IPC 通）；设置页测试通知（toast 通）
