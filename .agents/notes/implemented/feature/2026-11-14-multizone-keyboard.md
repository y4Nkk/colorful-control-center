# Agent Note: 原厂type23多区键盘

Status: implemented

## 问题

普通三区cmd103、逐键HID和type23多区cmd4/sub44不是同一协议。真实Pi反编译CC40.Style4.MainWindow.Load_page_LED_Device把type23明确路由至PageLEDdevice_zoneKB，后者调用CC40.LEDdevice.ZoneKB。原有family未知会阻止灯光与完整档案；不能套用普通灯条或逐键编码。

## 决定

- lighting/multizone独立拥有type23的模式、速度、开关、亮度和四区颜色，以及原厂允许的Zone5灯条和Zone6顶盖颜色。闲置与开机覆盖仍由lighting/options唯一拥有。通过领域Scope→HAL复用首次基线和单次前态，不另建档案执行器。
- 原厂设置页索引按InsydeDriver.ReadAppSettings的/256和%256换算为page2：mode32、speed34、brightness35、status80、四区RGB85/89/93/10、灯条RGB27、顶盖RGB13。只改所属字段，保留填充、逐键及其他灯区；读取不仿照Init写默认值。
- 原厂37字节sub44报文保留0..36布局，模式映射和键盘/灯条亮度档转换直接取ZoneKB源码；开关关闭时三个亮度为0，保存亮度独立保留。灯条是否输出遵守sub60状态，顶盖遵守sub8/page7 byte23 bit5；未知版本和状态拒绝。
- 即时命令接受与保存回读不表示物理效果，预览绑定完整能力及所属字段。部分失败恢复即时包及保存字段，后续档案失败恢复本次前态，显式恢复保持首次基线。字段需同次接通捕获、严格文件、预览确认、手动/启动和恢复后才公开。
- TP另有保存字段和E0掩码，但当前已读RGBKB没有独立颜色发送分支，继续追踪实际消费者，不凭持久字段猜命令。

## 影响与验证

只用明确注入的内存DCHU、临时档案与模拟IPC。覆盖全部模式和亮度、能力/状态变化、字段保留、旧预览、每阶段失败/补偿/重试、单项与档案共享恢复、启动预览、页面宽窄深浅布局；build、cargo check、边界/控件/笔记与500/80限制通过。不启动原厂/生产应用，不访问真实HID/WMI或发送硬件命令。

- 原BAML connection83静态属性确认为Minimum1/Maximum3，SHA256 C0491EC89D215C78572B2B041EC439418D3322F13BF7B4F68C7F2999D77F0B03。以ILSpy的BAML记录格式解析本地二进制，不加载WPF或原厂程序集；研究摘录在target/ui-check/multizone-baml-speed.json。
- 领域11项及档案11项通过，档案过滤254项含11项显示领域复用；74项灯光回归为首批10项多区与原有64项，后追加的能力变化诊断单独验证。8项热键策略回归通过。覆盖手动/启动、完整往返、文件与设备变化、显示先保留、部分与后续失败、初始基线共享及非所属字段保留。
- 136项相关页面回归通过；新增11项多区/档案页面包含双确认、旧预览、读取/写入失败、关灯保留亮度、捕获导出、启动选择、多屏试用与宽窄深浅布局。实看截图后移除重复草稿色块与无变化摘要，当前/草稿模块按内容排列，只显示真实差异。
- 构建、主/模拟宿主检查及500/80限制通过。单项、亮度热键和档案只有一个multizone事务和首次基线；没有原厂默认初始化、普通cmd103模拟、HID回退或档案专用执行器。测试仅限内存DCHU/临时文件/模拟IPC，没有访问真实硬件。

## 风险

保存值与命令接受不能证明物理灯效。原有效初始快照在能力或平台灯条状态变化后保留并明确阻止旧写入，未知当前设置不创建新基线；其他独立顶盖bit6及TP的实际发送分支仍在总路线内，不能把本节多区bit5当作这些功能完成。

## 备选方案

- 用普通cmd103或逐键HID代替sub44：实际原厂调用及报文不同，拒绝。
- 读取时自动初始化默认颜色或猜速度范围：产生未确认写入和虚构基线，拒绝；范围由原BAML确认。
- 增加档案专用写入器或把保存回读称为物理生效：会产生第二套恢复所有者或越过证据，拒绝。
