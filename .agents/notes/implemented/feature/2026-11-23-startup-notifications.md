# Agent Note: 启动显示、原厂进程与全局通知

Status: implemented

## 问题

启动显示由一个独立开关控制，原厂 FnKey 运行时会阻止多个领域接管。已有应用通知悬浮在工作区右下角。

## 决定

- 设置页明确提供显示主界面和最小化到托盘两个选项，沿用已保存的启动显示偏好，对登录自启和手动启动生效。
- 主程序取得控制权后，在装配 HAL 前和运行期间检查原厂控制软件，托盘运行也继续检查。原有偏好控制两处检查，默认开启，切换后无需重启。进程退出前核对 Windows 会话、应用包和包内映像路径。
- 本机原厂安装包提供了明确的映像：FnKey 包的 `FnKey/FnKey.exe` 与 `FnKey/CC40/CC40.exe`，Control Center 3.0 包的 `ControlCenter30/ControlCenter30.exe`，Flexikey 包的 `LaunchFlexikey/LaunchFlexikey.exe` 与 `LaunchFlexikey/CC.exe`。主应用再核对应用 ID。各进程在已核验的句柄上结束并确认退出，未通过核验的候选继续通过占用门禁和诊断报告。
- 当前 FnKey 冲突共享「关闭 FnKey」入口，确认前重新核验实际进程。原厂预设保留绑定模式目标的「关闭并切换」。其他进程的退出指引直接出现在冲突提示中，档案和其他领域的历史执行记录只提供诊断。确认退出后的重新读取先清除已处理的操作错误，并以最新回读更新占用，避免并发刷新留下旧按钮。
- 参考 AgentSwitch 将普通通知从右下角迁至标题栏摘要和展开列表，电池低温警告使用直接确认。启动原厂进程处理结果在主窗口可读，并保留到用户清除。

## 影响与验证

- 保留既有启动显示和原厂退出偏好的保存值。启动处理在标题栏反馈，运行期间的处置和失败写入运行日志。确认退出后通过现有事件重新读取控制状态。
- 前端构建、Rust 工作区检查、16 项 Rust 偏好测试、32 项控件检查与 40 项模拟 IPC 浏览器检查通过。浏览器覆盖启动选项、原厂退出结果、通知计时与展开、低温提醒、原厂冲突和档案反馈。
- 启动与运行检查扩展通过前端构建、Rust 工作区检查以及三项偏好与进程身份测试。手动入口收敛后通过 26 项模拟 IPC 浏览器用例，覆盖自动与手动退出后的回读、历史失败、其他进程提示及预设确认。
- 自动档案通过策略状态直接报告最近失败原因。原来为历史关闭入口单独读取的报告 IPC、前端订阅和内存副本随入口删除。
- 关闭 FnKey 会结束由它提供的原厂热键与屏显。可关闭开关后重新打开原厂软件。真机进程终止、Windows 登录启动及硬件联动待验收。

## 备选方案

- 仅按映像名匹配的退出操作无法可靠区分同名程序。沿用已有包身份核验。
- 独立登录显示偏好会改变手动启动及旧偏好的语义。沿用统一启动显示偏好。
