# Agent Note: 监控与控制合并为图形控制台

Status: implemented

## 问题

用户明确要求概览与控制集成到一个页面，全部改为图表化操作，逻辑简单，去除复杂说明和装饰文案。现有仪表盘、风扇曲线、性能调校分为三页，实时读数与调节脱节，控制仍依赖数字输入和大量实现细节说明。

## 决定

2026-11-16按用户补充，软件内UI与模块采用少文字、优质SVG/已有生成场景图的视觉表达。主视图保留模块名称、真实状态、关键数值和动作；协议、驱动、完整参数及长规则放进Collapsible详情，必要风险与失败诊断不隐藏。GPU当前/目标和独显控制优先复用已有精细显卡SVG，与短状态及读数组合；阶段图只根据真实预览中的已确认动作绘制，未知不补零，离散开关不画假百分比。保持左右布局、Surface模块边框和间距；大插图不遮挡控件，不冒充本机具体显卡外观。后续各模块按同一契约接入，不增加平行执行或确认路径。

热键主视图只展示范围名称、短状态和必要风险，长规则折叠；能力详情仅在草稿已选、当前接管或有首次恢复记录时显示，不能因为取消草稿就隐藏仍需恢复的硬件。运行状态归HotkeyCurrent，名称/规则归hotkey-actions，避免拆分后重复术语和规则。频率不是百分比：用真实数值与插电/电池表格，配合已有生成场景缩略图；不增加无分母的仪表。

2026-11-13 控制台模块按同一网格行拉伸：风扇与右侧调节组、刷新率与独显等并排模块共享顶部和底部，不再使用 align-items:start 形成阶梯。右侧调节组首尾分布，设备模块主要操作行靠底对齐；长文案、错误、展开说明由同排最高内容自然决定行高，不固定高度、不裁切内容，单列布局保持自然高度。

2026-11-13 按用户要求明确页面边界：设置页只保留软件外观、开机启动、窗口行为与关于；键盘灯光（含逐键）、屏幕刷新率、独显开关和启动性能档案统一由控制台组合。硬件组件及灯光状态移入 components/control/，删除 settings/ 下旧位置；设备分组样式归 control.css，保留现有草稿、确认、回读及恢复。新增设备区放在性能调节之后，按实际容器宽度折为单列；active 由控制台透传，不在隐藏页继续显示轮询。独显操作完成后由 app 层刷新同页 GPU 调节事实；启动档案回读只跟随未编辑的选择，不覆盖跨页保留的草稿。

2026-11-13 按用户温度模块截图，将叠加细折线改为 CPU/GPU 上下分区的采样柱状图：左侧分别显示当前温度，右侧使用相同的 0–110°C 比例与时间轴，每个柱条对应一条真实采样，不做聚合或插值。柱宽按 1Hz 采样间隔限制，时间跳跃及空值保留空位；最新有效采样仅在当前点有值时加深，95°C 参考线和超温红色保留。移除旧温度折线路径、叠加图例和未再使用的时间折线工具，不改变采样、硬件协议和控制流程。图表与空态在隔离预览中验证，生产界面不添加演示数据。

2026-11-13 按用户新截图调整监控卡片：CPU/GPU 各有模块边框和间距，卡内左侧集中标题与 RPM，右侧呈现环形占空比/利用率/显存比例。环形仅用于有分母的读数；未知分母或缺失值保留空环和实际空态，不为 RPM 伪造上限。仅增加模块边界，不恢复密集网格和装饰折线。比例的可访问语义、数值与容量总额由 MetricReadout 统一拥有，原生横条从监控路径移除；档案仍沿用自身参数条。

2026-11-12 用户按截图要求继续重构“按语义图表化、减少线条”：监控按 CPU/GPU 分组，转速使用直接读数，占空比/负载/显存使用真实比例；移除六张重复微型折线与边框。温度保留时间趋势和缺口，只呈现必要温度参照；编辑曲线保留控制关系与拖动/数字草稿，移除密集网格、常驻悬浮标签和投影虚线。右侧调节按模式、功耗、GPU 用留白分组，移除装饰刻度。沿用令牌、三页接入与确认恢复流程，不更改硬件协议。

1. 一级导航收敛为控制台（dashboard）、性能档案、设置；旧监控/风扇/性能三个工作区被单一 `ControlWorkspace` 取代并删除，不留下平行入口。页面→工作区组件映射通过 `PageDefinition.workspace` 字段显式登记（`check:boundaries` 读取该字段）。
2. 控制台主体自上而下：CPU/GPU 温度趋势（5 分钟、真实时间与缺口，仅保留 95°C 安全参照）→ CPU/GPU 分组读数（RPM 数值，占空比/利用率/显存比例）→ 左侧风扇曲线编辑与右侧模式/功耗/GPU 调节。边界使用表面与留白，移除逐卡描边；曲线点标注仅在交互时出现，图外明确标识预估值。
3. `src/components/control/` 拥有 plot.ts、curve.ts、TrendChart、HardwareReadings、MetricReadout、FanCurveEditor、ScaleSlider、DiffPreview；MiniMeter 及旧六折线布局已删除。监控样式由 monitoring.css 拥有，编辑操作由 control.css 拥有，页面只组合。恢复使用全局 ConfirmButton 的 secondary 层级，确认仍统一红色。
4. 风扇曲线编辑自动选择自定义模式，模式/曲线/偏移确认后顺序执行、首错停止。功耗滑杆区分「立即应用／保存设置」，实时 MSR 值与 page6 保存值分别展示，PL1/PL2 联动保序；草稿跨页保留，失败回读，恢复走后端记录。
5. 主流程只保留短状态和操作，技术诊断折叠；档案使用图表预览，托盘选择只触发预览。
6. 编辑曲线使用 viewBox 0 0 100 100 + preserveAspectRatio="none" + vector-effect="non-scaling-stroke"，轴标/图例用 HTML 保证 360px 可读；温度柱条使用 HTML 按时间定位，缺失读数留空不补 0，窄屏时间标签使用整行宽度；快照停滞 >3s 显示"读数停滞"短状态。
7. 风扇曲线同时提供拖动与 T2/T3 温度/占空比数值输入，共用同一份草稿与 curve.ts 约束；拖动同步输入框，合法输入立即更新曲线，空输入不污染草稿，越界在提交/失焦时归入有效区间。两条路径都只在最终确认后写硬件。
