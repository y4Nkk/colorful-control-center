# Agent Note: 翻转主屏的说明移入开关旁的信息弹窗

Status: implemented

## 问题

设备配置页「屏幕显示」卡片的「翻转主屏」开关下方有一行说明，显示切换后的方向，分辨率变化时一并显示。用户要求移除这行文字，在「翻转主屏」标题旁放一个单独的信息按钮，用弹窗详细说明。

## 决定

2026-11-27 卡片内不再显示目标说明行，开关也不再用它作为无障碍描述。「翻转主屏」标题旁新增信息图标，打开共享详情弹窗「翻转主屏说明」：

- 首段按当前状态给出事实：主屏当前方向和分辨率，打开或关闭开关后切换成的方向；分辨率变化时一并给出。开关已打开时改述为关闭后的结果。不能翻转时说明原因：没有唯一活动主屏，或当前选中的不是主屏。
- 其余段落说明作用（画面旋转 180°，刷新率和屏幕位置不变）、15 秒试用与保留或取消、只对主屏生效、不写入 Windows 显示设置和配置档案，以及开启「原厂屏幕旋转」后快捷键只定位、不自行翻转。事实来源是 `docs/oem-device-contract.md` 的「刷新率与主屏方向」，未新增行为。

「翻转主屏说明」是模块标题栏信息图标之外登记的第二个信息入口，`DESIGN.md` 的页面结构与组件所有权两处已写明。全页面巡检的「重复信息按钮」检查对「屏幕显示」允许两个，其他模块仍只允许一个。

说明行移除后底部行只剩一行，比相邻「自动刷新率」卡片的两行矮 1.28px，两个开关的纵向位置相差 0.64px，超出同线检查的 0.5px 容差。原先的齐平依赖两边恰好都是两行。改为两张卡片底部行的末项开关都贴行底对齐，行高不同时仍保持同线；自动刷新率卡的开关因此下移 0.64px。选择器只落在各行的末项（`:last-child`），不点名 `.ccc-switch`：边界检查规定控件外观归全局原语所有，业务样式一旦选择到控件类就判违规。

开关的 `aria-describedby` 随说明行删除，读屏用户改为通过相邻的「翻转主屏说明」按钮获取目标。热键事件定位后的「展示目标」也改由该弹窗承担，两份契约文档已同步。

## 影响与验证

- 用户要点开弹窗才能看到切换后的方向和分辨率，卡片内不再直接可见。这是用户明确要求的信息位置调整。
- 仅前端展示变化，显示写入、试用、监护和恢复路径未改，不涉及硬件写入。
- 验证（2026-11-27，隔离副本，模拟 IPC）：`npm run build` 通过。`display-rotation` 4 项通过，含三种宽度、深浅主题下信息图标位于标题右侧并垂直居中的新检查，以及原有同线检查。`display`、`configuration-review`、`auto-refresh`、`profile-display`、`oem-conflict` 共 50 项通过，`control-alignment` 5 项通过。
- `all-pages-configuration` 10 项通过，但这是在副本里暂时去掉「信息按钮须有原生 title」条件后的结果。该条件自 2026-11-26 全局提示气泡改动起在概览页就不成立，属既有问题，未在工作区修改。另有 `control-alignment` 的「保存当前配置」主按钮颜色、`icons` 的导航图标两项失败，分别在配置档案页和侧栏，与本次改动无关，未处理。
- 截图目检：宽窗浅色、窄窗深色下的卡片与弹窗，以及竖屏状态下的目标分辨率。

## 备选方案

- 只保留标题栏的「显示器详情」，把翻转说明并进去：不符合用户“放在翻转主屏旁边”的要求，未采用。
- 放宽同线检查的容差来掩盖 0.64px 偏差：齐平依赖两边行高巧合，以后改文案还会再断，未采用。
- 用视觉隐藏文本保留开关的无障碍描述：用户要求移除该文案，弹窗已提供同样的信息，未采用。
