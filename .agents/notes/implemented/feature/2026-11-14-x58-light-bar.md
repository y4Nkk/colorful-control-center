# Agent Note: X58独立灯条

Status: implemented

## 问题

CC40与FnKey的X58灯条使用独立CD集合，不能复用X170的设备或效果编码；当前控制台只接通X170。另有TP颜色保存字段，但在已核对版本中尚无有效颜色发送分支，不能猜测F4作为补齐方式。

## 决策

- 来源为Pi的CC40.LEDdevice.LightBar_X58、CC40.Style4.PageLEDdevice_perkeyKB、FnKey.LightBar_X58，以及本机FnKeyPack_7.19.5.0_x64.appx内FnKey/Device_HID/lightbar/HID_Device.dll。与包内perkey副本内容相同，SHA256 7EDA28D94EA716D1CA5A8A0910B1D56EA6D1608C02E624A1D783C9355575AFD8。
- 已静态核对导出WriteData RVA787f0跳至87870，再经757c1跳至85270：报告ID、命令、payload依次位于0、1、2起始，payload最多62B。Init_HIDdevice RVA78868跳至85860，在8590c将全局报告长度设为64；全库对该全局字节只有这一次写入。SetFeature返回失败时2，未初始化99。完整传输摘录在本线程artifact的source-audit/x58-hid-write-disassembly.txt。
- 原厂绑定VID048D/PID8911、usagePageFF89/usageCD。CC40.InsydeDriver及FnKey.Features均由page7 v1 byte23 bit7声明LightBar_new2025，再读取cmd4/sub60；LightBar_status等于1时才初始化X58。未声明时不查询sub60，不使用X170 WMI96 bit11或普通灯条位代替。
- 所有设置调用CMD E2：模式0..5分别发送05..0A，速度发送01/speed，亮度0..4发送02/1..5，颜色发送03/ID。模式0保存独立静态颜色，模式4保存独立移动颜色，颜色ID1..7为红、黄、黄绿、绿、青、蓝、紫。静态BAML解码确认速度Minimum1/Maximum3、亮度Maximum4（默认Minimum0）；摘录为source-audit/x58-perkey-page.xaml的3665/3688行。
- 原保存地址620、19B对应模式、速度、亮度、两个独立颜色及保留字段；InsydeDriver.ReadAppSettings/WriteAppSettings以index/256及index%256转换，实际为page2 offset108。读取不得照抄原厂自动初始化默认值；未知保存值应明确未知，保留恢复资格。亮度0仍发送编码1，不能将它当原厂关灯语义。
- 实现独立领域模型及设备身份绑定的事务、预览确认、失败即时/保存补偿和初始恢复；允许复用现有HID枚举所有者的确切共性，但不引入泛化驱动框架。UI提供六模式、七色、速度/亮度及左右语义卡片。
- X170/X58共用已有灯条生命周期、19B保存事务及HID枚举，型号和取值以严格kind/settings联合契约区分；同步更新IPC消费者和夹具，不保留无型号的旧写入结构。能力页声明候选，以唯一实际HID集合确定型号；两个真实匹配设备共享19B时拒绝含糊绑定，不因同时声明候选就拒绝唯一实际设备。快照修订及初始身份同时绑定型号；型号变化保留旧草稿并要求显式载入当前配置。

## 影响与验证

原库初始化、64B报告、地址620转换及BAML速度/亮度范围已经静态核对。19项灯条检查（原X1708项和X5811项）、19项逐键回归通过；覆盖六模式/七色、亮度零档、颜色及保留字节、每次部分失败、恢复重试、未知当前值、未知非活动颜色、类型身份及过期请求。旧无kind契约拒绝，两个真实设备含糊绑定不写入。13项独立灯条页面及含逐键/外围的25项页面组合通过，布局覆盖360/760/1440px且截图已目检；工作区及control-sim编译、前端构建通过。未枚举真实HID、加载原库或发送实际报告。

## 风险

共享19B布局与其他灯条有不同含义，必须以原设备和能力绑定，不能通过保存颜色猜型号。读取保存值和HID接受结果不证明物理灯光效果。

## 备选方案

- 将X58当成X170或普通RGB灯条：设备与报文不同，拒绝。
- 只实现保存字段并报告灯效已生效：缺少即时控制链，拒绝。
