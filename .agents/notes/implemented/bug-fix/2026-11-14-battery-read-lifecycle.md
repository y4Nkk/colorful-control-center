# Agent Note: 电池读取生命周期

Status: implemented

## 问题

电池/节能/校准的effect清理只失效读取代次，但保留正在读取标记。React StrictMode立即重建effect或快速离开再进入页面时，新effect被旧请求阻止；旧结果随后又因代次过时丢弃。充电需等待5秒，节能/校准因尚无profile不启动轮询而长期空白。模拟页面回归复现充电环无初始读数和两个子域停留加载中。

## 决策

- 三个effect清理同时释放当前读取引用，重建effect可立即发起新读取。旧请求仍受代次保护，finally只有仍拥有该引用时才清理，不能抹掉新请求。
- 充电原布尔reading改成实际Promise引用，轮询、重读与写后回读共用同一入口；写入等待已有读取结束，写入期间普通轮询不并发。保留草稿、写入错误及读后状态语义，不增加重试定时器或共享抽象。

## 影响与验证

实际StrictMode页面的2项新检查及7项校准页面回归通过；先挂起三个域的旧读取，快速切页后接收新状态，再释放全部旧响应，证明旧电量/计划/开始资格不会覆盖新值。18项电池/节能/档案页面通过，覆盖草稿、确认及写后回读；构建与26项控件边界通过。只连接隔离模拟IPC，不调用真实电池或校准入口。

## 备选方案

- 延长页面断言等待或移除StrictMode：掩盖生产快速切页的同类状态，不采用。
