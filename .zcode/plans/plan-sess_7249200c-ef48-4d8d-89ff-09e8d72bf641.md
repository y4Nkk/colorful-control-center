## Context

目标是让 CCC logo 达到与 spiralcoder 同等级的液态玻璃质感，并完成从网页到 Windows 图标的统一交付。沿用你已确认的方向：**圆形玻璃盘＋五叶风扇蚀刻，CCC 蓝→紫→粉→琥珀光谱**。

当前版本存在三个缺口：材质未经可信的最终视觉验收；应用内“减少动效”没有传入外部 SVG；favicon 与原生图标依靠手动同步。上一轮关于“resvg 普遍丢弃 opacity”的说法缺乏可靠证据，需要纠正。此次直接替换现实现，不保留旧版、兼容分支或临时回退。

## 设计与验收标准

以 spiralcoder 的 `web/public/logo.svg` 为材质参考，借鉴其裁切流彩、镜面高光、渐变边缘和柔和投影，保留 CCC 自己的形状与色彩身份。

- **轮廓**：圆盘留白均衡，风扇五叶保持同向旋势，轮毂与扇叶比例统一；缩小后仍能识别为风扇。
- **玻璃**：统一左上光源，薄而清晰的亮边、受控的暗边与局部反光表达厚度；蚀刻融入玻璃表面，避免厚重塑料感、白色贴纸感和花瓣感。
- **色彩**：左下蓝色至右上琥珀，紫粉用于过渡；高光不洗掉光谱，深色背景下不出现脏灰边。
- **动效**：仅内部流彩缓慢变化，外轮廓与风扇不转动、不跳动；停止动画后仍是完整的优质图标。
- **尺度**：重点验收实际顶栏的 24px，以及 16/32/40/64/128/256px；浅深背景均无裁切、细线消失或明显糊边。

“完美”以可展示的最终图和这些具体标准验收，不用构建通过代替视觉质量。

## 实施

### 1. 修正设计契约与笔记

先更新同主题笔记 `.agents/notes/implemented/feature/2026-11-17-liquid-glass-logo.md`，撤回未经证实的渲染器限制及目检结论，记录本轮方案，验证结果完成后再填写。

在 `DESIGN.md` 登记应用 logo 的唯一源、渲染组件和生成入口，明确局部品牌玻璃材质的使用范围；应用外框仍沿用现有设计。

### 2. 重做唯一 SVG 源

修改 `src-tauri/icons/icon.svg`：

- 精修圆盘、扇叶、轮毂比例与材质分层，删除上一轮因错误推断叠加的补偿层和注释。
- 渐变、几何及光影只在此定义，组件不复制绘图。
- 对透明度与镜面光照做最小实际渲染验证，以像素和报错判定；选择浏览器和图标生成器均可稳定呈现的最终实现，不维护两套材料版本。
- 明确定义静态基准帧，修正流彩层初始状态，完整支持系统减少动效和高对比显示。

### 3. 统一应用内渲染与动效

新增 `src/components/BrandLogo.tsx`，直接读取唯一 SVG 源并以内联 SVG 渲染；只负责实例 ID 隔离、装饰语义和既有布局属性，不拥有另一份材质。

将 `AppShell.tsx`、`AboutSettings.tsx`、`SettingsPreviews.tsx` 的应用标识统一接入该组件。设置预览中的 SVG 图片引用也替换为同源标识，删除旧绘制入口。

让 SVG 动效同时响应现有 `appearance.ts` 写入的 `data-motion` 和系统偏好；复用现有状态，不新增偏好、监听器或 store。浏览器 favicon 保留外部 SVG，遵守系统偏好。必要尺寸与样式遵守 `tokens.css` 所有权。

### 4. 收口图标生成

新增 `scripts/generate-icons.mjs`，提供生成与检查两种模式：

- 唯一输入为 `src-tauri/icons/icon.svg`，调用项目已安装的 Tauri CLI，在临时目录生成。
- 成功后同步 `public/favicon.svg` 与项目现有桌面图标集；不向仓库写入 Android/iOS 等无消费者产物。
- 任一生成失败即报错退出，避免把部分产物当作成功结果。
- 检查模式重新生成并比对受管文件，验证 favicon 字节一致、产物未过期。

在 `package.json` 提供 `generate:icons` / `check:icons`，构建接入检查。移除手动复制作为正式流程的旧说明，不引入新依赖。

## 验证

1. 执行生成与检查：确认全部受管图标来自当前源；用临时副本制造过期产物，验证检查会失败。
2. 浏览器查看参考与最终 logo：浅/深背景、多尺寸、静态与动画关键帧；检查实际顶栏、关于页和设置预览。
3. 验证系统减少动效、应用内减少动效、forced-colors，以及同页多实例 ID 隔离；确认动画关闭后仍清晰完整。
4. 实际打开生成的 PNG 与 ICO 关键尺寸，检查与 SVG 静态基准的材质、透明背景和边缘一致性；保存与最终源摘要对应的截图证据。
5. 运行 `npm run verify-notes`、`npm run build` 及仓库要求的 `cargo check`。只跑与本次有关的检查，不运行完整测试套件。
6. 发现视觉问题继续修到上述标准通过，再交付最终预览、验证结果及尚未完成的原生显示检查；不以中间截图或源码推断宣称视觉通过。
