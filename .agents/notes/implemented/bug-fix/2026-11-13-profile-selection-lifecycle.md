# Agent Note: 档案读取、导入与托盘请求的时序

Status: implemented

## 问题

Phase 3/4 档案链路仍有异步缺口：托盘预览请求可在应用档案期间替换预览；较早的文件读取/解析可能晚到并覆盖新选择。写入结果可能与当前预览错配，快速连续导入不保证最后一次选择胜出。

删除档案也没有解除开机档案引用，之后导入同名文件可能沿用已删除档案的启动授权。

## 决定

- 预览读取和导入共用同一请求代次，在异步开始时登记；写操作开始就使旧读取失效，过期响应不发布。
- 写入期间暂存根组件提供的最后一个托盘请求，操作结束后消费一次；不重复消费旧请求，不影响后续手动选择。
- 列表刷新有独立读取代次，旧列表响应及旧错误不覆盖新状态。成功通知带实际应用的档案名。
- 继续沿用后端完整 expected 档案绑定，不新增第二套存储、队列或兼容路径。
- 删除档案时，在同一配置互斥下先解除匹配的开机选择，再删除文件；删除失败恢复选择，恢复也失败时保留错误。启动选择保存与删除共用此锁，避免校验后删除造成悬空引用。界面确认说明会取消该档案的开机应用。
- 档案文件名遵守 Windows 大小写身份：只改大小写的保存/导入在替换文件前拒绝，避免文件名与 JSON 名称失配或悄悄覆盖；删除解除引用使用 Windows ordinal 大小写比较，不增加别名读取路径。
- 2026-11-16：显式模式选择新增 page1[16] 插电偏好及公共EnergyStar输出，不能让旧的仅名称或仅插电偏好启动记录自动取得新增输出。启动选择使用唯一的版本3格式，必填version/profile；缺失或其他版本拒绝且保留原文件，不迁移或自动重新授权。显式重新预览、保存或取消选择才写入当前格式，仍只保存档案名并使用该名称的最新配置，不复制档案或联动事实。
- 启动设置读取失败不能连带隐藏可选档案或把未知保存状态当作“未选择”。列表与当前选择独立接收结果；未知状态清除可执行旧预览，允许用户明确确认重新选择或取消。初次读取未结束时不开放保存，修复失败继续展示错误。启动读取在取得HAL及创建档案执行前完成，格式拒绝不会产生硬件输出。

## 影响与验证

- 生命周期浏览器18项通过：连续选择/导入、解析中开始写入、写入中最后托盘请求、旧请求不再消费和旧列表响应不覆盖新列表。
- 档案34项、启动选择10项原生聚焦检查通过，读写只在隔离目录：删除成功解除引用，删除失败恢复选择，解除失败不删除，Windows 大小写身份不覆盖既有文件。
- npm run build 与边界检查通过，原有导入、预览与确认流程通过页面回归。
- 2026-11-16：启动16项聚焦检查通过，包含原有回归、严格当前格式、旧记录保留及显式重选、写入前拒绝过期格式。启动修复与组合模式预览5项模拟页面检查通过，覆盖读取等待、旧选择读取失败仍可选择、明确取消及保存失败重试；前端构建通过。没有读取真实启动选择、运行原生应用或写入硬件。

## 风险

验证只使用浏览器内隔离档案与模拟 IPC，不修改真实用户档案或硬件。

## 备选方案

- 只禁用页面按钮：不能阻止原生托盘事件和已发出的读取响应。
- 新建持久化操作队列：当前需求只需请求代次和一次消费，拒绝扩大结构。
