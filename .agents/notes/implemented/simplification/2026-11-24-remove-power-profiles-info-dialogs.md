# Agent Note: 电源与档案页面移除信息图标弹窗

Status: implemented

## 问题

「电源与档案」页面的两个分区里，卡片标题行、确认弹窗和档案预览共有 20 处信息图标按钮（`DetailsDialog` 默认 `icon="info"`）。每张卡片各带一个 ℹ，档案预览的每个设备分区再各带一个，信息入口的数量与主操作相当。这些弹窗并不都是说明文字：授权自动应用前的完整档案预览、两条恢复操作、原厂自动切换的六条件规则表和多数失败原因只在其内可达。用户要求移除该页面全部信息图标按钮及其弹窗。

## 决定

2026-11-24 「电源与档案」页面（「电源设置」与「配置档案」两个分区）移除 18 处信息图标按钮及其弹窗：

- 卡片标题行的详情入口：电池与充电、电池校准、节能计划、原厂供电模式、平台电源、USB 选择性暂停、网络驱动策略，以及原厂供电模式内的「联动目标」和「供电档案状态与记录」。
- 档案预览各分区（`ProfilePreview`）的说明入口：充电策略、节能策略、按键映射、网络驱动、显示器绑定、性能选项、独显电源、PD 与 USB 应用检查。`ProfilePreview` 同时服务两个分区、保存弹窗与授权预览，故一并移除。
- 原厂供电模式的详情连同只为其服务的 `SupplyModeCurrent`、`SupplyModeScenarios` 一起删除。

同日经用户确认的两处例外，功能保留、入口不再是信息图标：

- 启动档案授权与自动档案规则保存确认中的完整档案预览，是授权前的预览步骤而非说明。入口改为「查看档案参数」文字按钮（`icon={null}`），弹窗与 `ProfileModeExecutionNotes` 保留。
- 自动档案的「重新读取并暂停」是规则保存被拒后刷新预览的入口，改为仅在卡片出现失败原因时显示的卡内按钮。节能计划的「重新发送保存计划」没有保留，随弹窗删除。

卡内原本以「… · 查看详情」概括的错误改为直接显示具体原因（自动档案、原厂供电模式、平台电源），规则不可用的原因显示在对应规则下方；恢复操作被阻止的原因（PD 档位、USB 选择性暂停）保留在恢复入口旁。其余只存在于弹窗内的内容随弹窗删除，不另找位置：诊断读数（循环次数、容量、状态码、各标准计划实读值、网卡身份）、校准阶段与采样电量、自动档案的供电来源与最近自动应用记录、供电模式六条件规则表与最近切换结果。

不属于信息图标的入口保持不变：`icon="edit"` 的「编辑节能时段」、`icon="logs"` 的「执行明细」、带文字标签的详情按钮，以及其他页面的信息图标。Rust 端命令与数据字段不动，后端仍返回已不在页面展示的诊断字段。

## 影响

- 页面信息入口统一为卡内实况、控件与短原因；全局「逐层披露」约定（`DESIGN.md` 布局原则、`DetailsDialog` 所有权行）对其余页面继续生效，本页面记为例外。
- 失去仅经弹窗可达的内容（见决定末段）。节能计划如需重新下发只能在编辑器里再保存一遍；电池健康度（循环次数、容量比）暂无任何页面展示。
- UI 检查中经由这些弹窗断言的用例改为断言卡内内容或删除：删除电池诊断布局、供电六条件规则表与布局、最近自动结果展示，其余改写；为卡内直显的原因和恢复受阻原因补了用例。

## 备选方案

- 仅移除电池卡片与配置档案分区的信息图标：与页面其余卡片的命名不一致（项目文档把「电源设置」分区称作电池页面），同一分区内会出现有无 ℹ 并存，未采用。
- 授权预览一并移除或原样保留：移除后授权时只看到档案名和 GPU 联动，与「硬件写入必须有预览/确认语义」相悖；原样保留则页面仍留有两个信息图标。改用文字按钮与概览页「文字按钮打开详情」的做法一致。
- 把弹窗内全部错误、操作与规则表改为卡内直显：等于重新设计各卡片布局，超出「移除弹窗」的范围；只保留卡内已有概括的原因与阻止恢复的原因。
- 两条恢复操作都改成卡内按钮：「重新发送保存计划」会在节能卡片有已保存计划时一直可见，用户选择只保留出错时才出现的「重新读取并暂停」。
- 同时删除失去调用方的 Rust 命令：最终没有命令失去调用方（`reload_power_profile_policy` 由卡内按钮继续使用），无需改动后端。
