# Agent Note: 独立顶盖灯光

Status: implemented

## 问题

多区Zone6（page7 byte23 bit5）不等于独立Logo_ACover（bit6）。真实Pi反编译的FnKey.KBModule.Init在键盘初始化后调用logo_topCover.init，实际FnKey.Logo_TopCover先发送亮度，再发送F0/F1/F2颜色。CC40同名类只在保留代码中出现，其额外F6调用不能当作真实FnKey执行依据；Support_BIT.SupportLogoColor是默认常量，不冒充WMI122 bit18。

## 决定

- lighting/options继续唯一拥有外围保存布局，新增独立topCover值（brightness0–4、RGB）及能力；page2[100..104]按bit6解释为亮度/RGB，普通Logo在同一布局下不能同时拥有该字段。闲置、开机覆盖及普通灯条保持原所有权。
- 仅原厂扩展页v1.0 byte23 bit6声明时开放；三色采用FnKey精确B/R/G编码，对0/254/129及0/255/127执行原有蓝值70转换。亮度对应0/47/95/143/191；不套用普通键盘蓝色缩放，不发送没有真实调用依据的F6，不在读取时初始化默认。
- 预览修订绑定能力与保存值；单项、严格文件及完整档案共用现有Target/Plan/Scope、首次基线与本次补偿。三颜色/亮度及保存失败独立恢复；初始恢复只改所属字段。普通键盘及其他灯效恢复后再恢复外围顶盖，遵守原厂初始化次序。
- 前端按当前/草稿显示亮度和颜色，关闭以亮度0表达；确认、恢复及档案/启动预览同次接入。所有验证仅用明确内存DCHU、私有文件与模拟IPC，不调用真实WMI/HID或运行原厂/生产应用。

## 影响与验证

外围策略18项（7项新增顶盖）、新增6项顶盖档案及1项多区/顶盖组合检查通过；档案过滤261项通过（含11项显示领域复用、2项真实设备检查忽略），灯光82项通过。覆盖能力位/版本、共享布局解释、全部亮度和特殊颜色、逐阶段发送/保存失败、补偿重试、外部变化、单项/档案首次基线及手动/启动。

新增11项模拟页面通过；相关147项页面组合回归通过，随后核对模拟恢复保留基线与生产一致，25项直接相关页面再验通过。深浅360/760/1440px截图已目检。npm build、workspace cargo check及12项隔离软件风扇进程检查通过；81个Rust和36个前端/检查源文件500行、函数80行扫描通过。所有检查未运行真实原厂程序、读取实际事件、打开HID或发送硬件命令；物理灯效未验收。

## 备选方案

- 复用普通Logo开关或type23多区顶盖：两者能力位、字段解释与发送路径不同，拒绝合并为同一控制。
- 直接复制CC40保留类的F6调用：没有进入已确认的FnKey初始化链，采用实际亮度及F0/F1/F2流程。
- 独立维护顶盖档案或恢复事务：已有外围字段所有者和完整档案Scope，继续复用，避免重复状态与整页覆盖。
